# Qualify automatic memory against existing checkout state

For Agent Memory identity and harness integration work, a fresh bound fixture is insufficient: the 2026-10-27 incident affected previously adopted checkouts whose filesystem device number changed while location and inode remained unchanged. Treat device/inode keys as observed provenance, not durable identity or authentication. Historical continuity requires matching registered location and inode, project/bank UUID, and authority; conflicting aliases remain unresolved until an explicit reviewed link.

A hook process running or acknowledging no learning is insufficient evidence of durable memory. Keep invocation, semantic assessment, local admission, witnessed publication, and freshly imported recall separate in reports. Fixed failure stage/reason metadata must remain private and isolated by checkout and adapter so another session cannot clear or hide the failure.

These lessons concern this repository’s memory runtime and qualification design; they do not establish OS reboot causation, universal semantic capture, production hook trust, or freshness when authority refresh is pending.
