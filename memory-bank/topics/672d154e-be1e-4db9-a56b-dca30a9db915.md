# Extra executable caches do not inherit signed-payload trust

For Agent Memory installed-runtime diagnostics, intact signed source and manifest bytes do not authorize extra executable files. In the Linux v0.0.8 incident, all expected payload hashes and modes remained intact but 34 additional CPython cache files correctly caused an exact-inventory refusal. Bytecode disabled for writes can still be read; excluding caches from verification or rewriting the receipt would weaken the signed installation boundary.

Diagnostic imports must avoid modifying the authenticated tree: Python isolated mode ignores environment-based bytecode suppression, so direct probes need explicit -I -B; packaged helpers use the supported version-selecting python3.sh launcher. For an existing mismatch, retain the exact inventory and unknown changes, independently verify payloads against signed release evidence, and keep any narrowly qualified cache quarantine reversible. A failed update or healthy setup check alone does not identify the cause or authorize cleanup.

This is a repository-specific integrity and diagnostic lesson, not a general exemption for cache files, automatic repair authority, or current release status.
