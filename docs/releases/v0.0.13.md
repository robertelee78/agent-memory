# v0.0.13 — Actionable signed-download failures

Signed-release downloads retry selected transient network and server failures up
to three times within the existing 30-second download budget. Successful recovery
is quiet. A terminal failure identifies the download stage and hostname, curl
exit code, HTTP status when available, and attempt count. It gives category-specific
next steps and retains a bounded, private, sanitized JSON diagnostic when local
storage permits. Payload bytes, URLs and authentication headers are not logged.

Certificate, signature, digest, size and local resource failures do not gain
retries or bypasses. Every attempt uses fresh staging; failed downloaded bytes
are never accepted for activation. This does not add retries to the initial
outer `curl` that fetches `install.sh` itself.

The initial report was curl exit 56 on one Mac; its exact network cause could not
be recovered because the old implementation discarded stderr. Later read-only
previews succeeded. This release improves diagnosis and recovery without claiming
to have established that original cause.

`--check` and `--dry-run` remain previews. They do not install `am`. To install,
rerun the same command without the preview flag, preserving other options:

```sh
curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | bash
```

An installed old updater runs its existing acquisition logic until it has an
authenticated new release. Running the trusted one-line installer loads the new
bootstrap download handling immediately. Repository memory is not installer-owned.

Bank-size recovery and hook-health diagnostics are separate follow-up work;
this release does not repair a malformed memory bank or reconcile hook settings.

Actual public qualification passed on macOS and Linux: 32 commands, zero failures;
maximum command duration 8.402 seconds. See the
[delivery evidence](../research/2026-10-31-v013-public-delivery.md).
