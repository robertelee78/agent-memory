# v0.0.11 — Recoverable updates and simpler memory refresh

This release makes cache-only drift recoverable during signed updates. When the
signed payload still matches exactly and only narrowly recognized, owned cache
files have appeared, AM preserves the entire previous runtime in its journaled
backup and installs a fresh authenticated release. Cache contents remain opaque:
they are neither executed nor parsed or blessed. A same-version update can repair
this drift; an unchanged clean installation remains a no-op. Changed source,
unknown files and unsafe ownership or links receive a specific refusal.

The CLI and hook launchers isolate Python cache reads before loading AM modules.
The old v0.0.10 launcher cannot acquire that protection retroactively. For the
first transition from an affected older installation, use the signed installer:

```sh
curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | bash
```

After that transition, ordinary `am update` uses the new recovery path. Existing
project memory, feature branches, staged work and client text remain separate
from runtime replacement. Recovery preserves its backup; it never deletes memory
or changes the repository's permissions or publication rules.

The refresh guide now hands the complete saved private prepare result directly
to apply. AM checks that report metadata agrees with the retained proposal before
writing output or applying the refresh; it retains exact inner-proposal support
and historical retries. No generated JavaScript extraction step is needed.

The source-bound bytecode-writer RCA and preventive guidance accompany these
changes. Native OpenCode completion work, broader stress qualification and the
remaining roadmap remain deferred to v0.0.12 with their existing approval gates.

## Correction published in v0.0.12

Actual Beast adoption exposed an overly strict refusal of a mode-0775 cache
directory beneath the private runtime root. v0.0.11 did not heal that case.
[v0.0.12](https://github.com/robertelee78/agent-memory/releases/tag/v0.0.12)
corrects it using the existing private-ancestor policy. An already blocked old
updater can use the signed one-line installer to load the correction. Original
v0.0.11 tags/assets remain unchanged; the unsuccessful adoption is retained
in the [RCA](https://github.com/robertelee78/agent-memory/blob/main/docs/research/2026-10-30-v012-cache-directory-rca.md).
