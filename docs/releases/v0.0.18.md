# v0.0.18 — the right GitHub account for `am share`

A small fix release of the lean `am`.

## Fix

When `gh` is signed in to more than one GitHub account, git logs in as the
active one. In a repository that account may not push to, `am share` failed,
mistook the refusal for a protected branch and ended with a raw git error.

Now, when github.com refuses the login for a push or a fetch, `am share` and
`am refresh` retry with the other accounts signed in to `gh`, the repository
owner's first, and say which one they used:

```text
Used GitHub account OWNER for OWNER/REPO (OTHER may not push to it).
```

- Your active `gh` account and your git settings are not changed. The account
  is used only for `am`'s own git calls in that command.
- The login is only ever offered to github.com, also when the repository
  pushes to another host.
- A refused login is no longer treated as a protected branch.
- When no signed-in account may reach the repository, `am` says which logins
  were refused, for which repository, and what to do. Nothing is written to
  GitHub.

Remotes over SSH and on other hosts work as before.

## Getting it

Run `am update`, or the one-line installer:

```sh
curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | sh
```
