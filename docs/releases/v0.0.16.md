# v0.0.16 — omp by default, clean reinstall, `git pull` after refresh

A small fix release of the lean `am`.

## Fixes

- **omp is set up by default** ([#268](https://github.com/robertelee78/agent-memory/issues/268)).
  The one-line install sets up omp like Claude and Codex when omp is on the
  machine, that is when its agent directory exists (`$PI_CODING_AGENT_DIR`,
  else `~/.omp/agent`, the way omp itself finds it): the skill, the activation
  block in its `AGENTS.md` and the session-start extension
  `extensions/agent-memory.ts`. Without omp nothing omp-related is created.
  Your other omp files are left alone, and `am uninstall` removes only
  agent-memory's. `--omp-agent-dir PATH` still picks another directory, and
  `--presets` without `omp` still leaves it out. `am status` and `am doctor`
  list omp with the other clients, and say when omp was installed later and
  `am update` should set it up.
- **Install on a fresh machine and after `am uninstall`** ([#269](https://github.com/robertelee78/agent-memory/issues/269)).
  The v0.0.14 `am uninstall` left its install record behind, marked
  uninstalled, and the v0.0.15 installer then refused with "changed since
  agent-memory installed it". That record now counts as no installation. A
  file that agent-memory did not put at an install location is still refused,
  never overwritten.
- **`git pull` works after `am refresh` and `am share`** ([#270](https://github.com/robertelee78/agent-memory/issues/270)),
  whether git merges or rebases on pull (`pull.rebase`). Before, the shared
  memory was left staged, and a rebasing `git pull` failed with "cannot pull
  with rebase: Your index contains uncommitted changes". Now:
  - when your branch tracks the shared branch and only memory commits lie
    between them, `am` moves the branch to the shared memory: nothing is
    staged and nothing differs;
  - when git rebases on pull, or your branch has its own commits, `am` adds one
    commit that changes only `memory-bank/`; a rebasing pull drops it once the
    shared branch holds that memory, and a merging pull finds the same files on
    both sides;
  - otherwise (a merging pull that fast-forwards) the memory stays staged, as
    before.

  `am` says which it did. Where a plain pull cannot work it says what to do
  first: `am refresh` again if more memory was shared before you pulled; with
  a rebasing pull, commit or stash uncommitted changes (`am share` shares
  memory edits); with `pull.ff=only`, `git pull --rebase` or `git pull --no-ff`
  for its memory commit. On a branch without an upstream it says there is
  nothing to pull. Memory you have not shared is never lost.

## Getting it

- From v0.0.15: run `am update`. v0.0.15 does the update itself, so it does not
  know about omp yet: if omp is on your machine, `am status` then says so; run
  `am update` once more and v0.0.16 sets omp up.
- Otherwise, or to do it in one step, run the one-line installer:

  ```sh
  curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | sh
  ```

Restart running Claude, Codex and omp sessions afterwards.
