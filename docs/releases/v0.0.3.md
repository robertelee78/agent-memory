# v0.0.3: shared recall, recovery and signed delivery

Agent Memory maintains one Git-tracked Markdown bank per repository across
Claude, Codex, OpenCode and custom harnesses, with each coding session in its own
worktree or branch. This release improves semantic navigation and qualification
as that bank grows, makes sharing/recovery failures more actionable, and adds a
pinned-key signed default distribution channel. A published release and verified
milestone delivery establish shipment; a branch or this guide alone does not.

## Install, update and uninstall

Install once per computer on macOS or Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | bash
```

The same one-line installer updates an owned managed installation. The ordinary
commands stay concise and follow the established AWA lifecycle:

```sh
am --version
am update --check
am update
am status --repo /path/to/project
am doctor --repo /path/to/project
am uninstall --check
am uninstall
```

`--json` retains complete machine results; `--verbose` adds detail. Restart
running agents after activation so they load the new skill. A repository needs
its own explicit project binding and evidence-led bank initialization, rather
than another runtime installation. Missing identity, unavailable memory and
installed-runtime health are reported separately; a diagnostic never silently
creates an identity or replaces a bank.

The default bootstrap authenticates the signed manifest and portable archive
before running candidate code. The signed updater preserves ownership,
compatibility, downgrade and same-version identity guards. An already executing
v0.0.2 Git updater cannot authenticate its own first transition; repeat the trusted
one-line installer to verify a candidate before activation. Explicit development
and custom Git sources retain their actual operator-selected/unsigned boundary.
The fetched bootstrap remains an initial HTTPS trust anchor. See the
[lifecycle security contract](../contracts/lifecycle-security.md) for precise limits.

The consumer archive contains only the portable runtime. It excludes this
repository's development memory, Git history, documentation and tests. A full
Git clone can contain this project's bank; installation never imports or binds
that bank as another repository's memory. Ordinary uninstall preserves project
memory and user edits.

## Recall through the agent

The invoking agent interprets plain-language meaning and navigates bounded maps
through the skill and public CLI, then reads sources with current project,
validity, trust, applicability and invalidation checks. This is portable harness
semantic recall without a required embedding provider or vector database.
`am search` used directly in a terminal remains literal.
[Standalone terminal semantic search](https://github.com/robertelee78/agent-memory/issues/200)
is a later-release requirement, not a v0.0.3 promise. Automatic hook enforcement
is planned for v0.0.4; the current skill performs the explicit boundary workflow.

The [source-bound recall evaluation](../research/2026-10-25-recall-final-evaluation.md)
retains the fixed 1k/10k/50k matrix, actual v0.0.1 baseline, model-mediated
observations and native timings. Two local warm complete navigation/read samples
at 50,000 lessons are 4.836 and 4.869 seconds, excluding AI thinking time. A cold
catalog rebuild takes 18.859 seconds on that path. These measured observations
are not an every-query or every-machine latency guarantee. The known literal
paraphrase miss, semantic extras and earlier failed model selection remain
visible rather than being renamed successful recall.

## Sharing and recovery

Eligible memory can land independently of unfinished code and refresh through
Git into the other worktrees and clones. Publication still respects existing
repository rules. Conflicting claims keep their provenance and go to the
detecting developer; cross-developer attribution supports clarification without
automatically messaging another person. Independent learning can continue while
disputed or unsafe changes remain held.

Private Git observation refs no longer update configured remote-tracking refs
while other worktrees fetch. Transport failures identify advertisement versus
fetch and retain safe repair instructions. Renewed clarifications preserve the
prior dispute evidence needed to validate their proofs after correction and
consolidation. Local pending evidence, registry recovery, tombstones and later
ordinary feature integration remain separate from successful publication.

The daily-use requirement includes complete 12-session/1,000-lesson and
24-session/10,000-lesson schedules plus independent size/session variations.
Smaller focused or core-only runs do not establish that gate. Actual outcomes,
source identities, platform checks and remaining limits belong in the published
release evidence and [reliability task](https://github.com/robertelee78/agent-memory/issues/99).
Heavy qualification runs locally on the available Mac and Linux machines; the
hosted matrix is available by manual dispatch rather than running on every push.

Canonical memory remains `agent-memory/v1`. No implicit bank migration, personal
memory, cross-repository federation or MCP integration is introduced. The
explicit migration/recovery surface refuses unsupported conversions; install
and update do not migrate a bank as a side effect.
