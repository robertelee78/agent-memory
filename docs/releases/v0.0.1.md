# v0.0.1 release guide

v0.0.1 provides shared project memory for agents working in separate sessions,
worktrees, branches and clones of the same repository. Ordinary Markdown and
Git hold the durable bank. The portable skill supplies semantic judgment; the
standard-library CLI supplies validation, guarded changes and verified readback.

## Daily workflow

Load the installed skill in each session. It reads the bank's router and
applicable context, uses current project evidence for initialization, and
compares durable learning with existing memory before admitting changes. It can
combine equivalent lessons, retain distinct conditions and provenance, correct
outdated claims and prune obsolete guidance. Qualified recall and bounded context
assembly keep relevance, validity and applicability attached to remembered facts.

Each coding session keeps its own worktree or branch. Eligible memory-only
changes can be committed, pushed and landed through the repository's current
permissions, checks and review rules while feature work remains unfinished.
Other sessions check for landed memory at natural turn boundaries and reconcile
only memory paths, preserving local learning, feature history and unrelated
index entries. Offline or review-dependent work stays explicitly pending.

Conflicting claims under overlapping conditions go to the detecting session's
developer. Attribution identifies when clarification with another developer may
be needed; the system does not contact that person automatically. Compatible
updates can continue while the disputed update waits. Routine success is quiet;
conflicts, failures and consequential corrections surface at a boundary.

## Setup and lifecycle

The [README](../../README.md#install-and-first-use) starts with a preview of
the managed-channel installation. Python 3.11+ and Git are required; no existing
bank, identity registry, running agent client, Python package or service is a
bootstrap prerequisite. Defaults create generic Agent Skills, Codex, Claude and
OpenCode discovery targets. Custom targets and link/copy modes use the same
complete `skills/agent-memory/` package.

The managed channel follows this repository's HTTPS `main` branch. For a fixed
release source, obtain the trusted v0.0.1 checkout and use the installation
guide's explicit `--development-source` option; the updater deliberately leaves
development sources alone. Preview and review the chosen source and targets
before activation. A running client may need a restart when its loaded package
changes; the receipt reports affected clients.

Updates, uninstall and interrupted-operation recovery use external ownership
receipts and journals. Ordinary runtime removal preserves repository memory,
backups and unrelated configuration; changed owned targets remain visible as
preserved conflicts. Retain a trusted complete package outside removal targets
for recovery and reinstall. Explicit deletion of one bank requires its separate
inventory and confirmation.

The runtime reads `agent-memory/v1` banks and bundles no schema migrators.
An artifact digest binds relative paths, bytes and file modes. The initial Git
distribution channel is unsigned; its digest does not authenticate a publisher.
Use `version`, `status` and `doctor` for runtime identity, setup and bank checks.
Canonical Markdown remains useful through the constrained
[file-only workflow](../../skills/agent-memory/offline/GUIDE.md) when helpers
are unavailable.

## Validation and limits

Run `scripts/test.sh --release --json` from a complete checkout. The mandatory
registry contains 116 suites; optional future stores are explicitly outside
this release. The gate rejects missing, empty, skipped, timed-out and failing
required suites, and requires complete registered fault-partition proofs.
The release CI matrix covers Ubuntu and macOS with Python 3.11 and 3.15. Exact
source revisions, runtime identities and observed results belong in the
[GitHub release evidence](https://github.com/robertelee78/agent-memory/releases/tag/v0.0.1),
alongside independent acceptance and integration proofs. See the
[test gate guide](../testing/README.md) for receipt interpretation.

Multi-machine scenarios use independent local Git clones, two developer
identities, fixture harness labels and real installed commands. These prove
the portable interfaces and Git reconciliation; they do not claim live tests
inside every agent client or across physical computers. Test worlds isolate
homes, configuration, credentials and remotes and require no live client data.
Their process environment is a trusted test harness, not an OS sandbox for
untrusted code. Windows and other filesystems are not part of this release's
qualified platform matrix.

Semantic relevance, equivalence and contradiction detection remain agent
judgments supported by source-bound proposals. A deterministic validator cannot
prove that every relevant lesson was found or that every contradiction was
recognized. Memory is untrusted project data and does not grant authority.
Required repository review is preserved; publication can remain pending.
Historical Git objects are not erased by pruning a current memory file.

Automatic capture depends on the active skill running the learning loop at turn
boundaries. The explicit `boundary` CLI performs the refresh protocol; it does
not invent semantic judgments or guarantee invocation by a harness. Automatic
hooks remain proposed for v0.0.3. Reliability and recall growth work remains
planned for v0.0.2 and can be refined from first-release experience. Personal
memory, MCP and cross-repository exchange are outside v0.0.1. Possible future
federation still needs a separate design for repositories with different
privacy boundaries.
