# v0.0.12 — Recover normal Python cache directories

This correction lets signed updates recover cache directories created under
normal umask 0002, including mode 0775 beneath the runtime's private 0700 source
root. v0.0.11 incorrectly refused these directories even though other principals
could not reach them. The qualifier now uses the existing shared path-trust
policy instead of a second, contradictory directory-mode check.

Publisher signatures, signed payload bytes/modes, ownership, safe file types,
single-link caches, inventory bounds and complete backup checks remain in force.
Cache contents stay opaque and unexecuted. Reachable writable paths still refuse;
no permissions, receipts or cache files are edited to force an update through.

If an older installed updater still refuses this case, use the signed installer
once to load the corrected updater:

```sh
curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | bash
```

Then ordinary `am update` handles protected cache directories automatically and
returns a no-op when the installation is clean and current. Runtime recovery
preserves repository memory and feature work. The broader roadmap moves to
v0.0.13; this release contains only this correction.

Four actual public fresh-install/upgrade journeys passed on macOS and Linux:
32 commands, zero failures. Beast's signed repair also passed, preserving its
25 cache files in exact old-runtime backups and returning a clean update no-op.
[Actual delivery evidence](https://github.com/robertelee78/agent-memory/blob/67aed15/docs/research/2026-10-30-v012-public-delivery.md).
