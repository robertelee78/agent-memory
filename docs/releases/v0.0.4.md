# v0.0.4: reliability and turn-boundary work

This guide describes the v0.0.4 candidate. A release is published only when its
signed artifacts and release record are available; this document alone is not
proof of publication.

## Install and maintain

Install once per computer on macOS or Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | bash
```

Use `am --version`, `am update --check`, `am update`, `am status --repo REPO`,
`am doctor --repo REPO`, `am uninstall --check`, and `am uninstall` for normal
lifecycle operations. Restart running agent sessions after an update. A runtime
installation is shared across repositories; each repository needs its own
explicit binding and Git-tracked bank. Installing the portable runtime does not
import this development repository's memory. Uninstall preserves repository
memory. The default release channel verifies the publisher signature; the
fetched bootstrap remains the initial HTTPS trust anchor.

**Upgrading from v0.0.3:** If you use `am update`, run it twice. The first
invocation uses the v0.0.3 updater and installs the new runtime but does not
activate newly introduced client hook targets; the second invocation uses the
new updater and reconciles those targets. Restart agent sessions afterward,
review any client hook trust prompt, and use `am doctor` if activation fails.
The first invocation’s success alone does not establish hook activation.

## Turn boundaries

The installed skill and CLI remain harness-independent. Adapters provide the
shared memory instructions for Claude, Codex and OpenCode, subject to each
client's hook support, configuration and normal permissions. Codex uses a
same-turn Stop continuation, which can delay the final response while the agent
works; review and trust its hook in `/hooks` when required by Codex. Claude's
Stop wake and OpenCode's supported continuation use their respective client
mechanisms. A hook firing or an instruction being injected does not establish
that the agent completed refresh, capture or publication.

The agent must inspect existing memory, assess durable learning, and use the
normal admission and memory-only publication workflow. Conflicts, unavailable
authority, missing source, denied permission and interrupted work remain
pending; no adapter grants permission or fabricates a receipt. For Codex,
`am codex-boundary --repo REPO --list-pending` lists retained source identifiers
and prompt hashes, not prompt text; it is a point-in-time observation, not proof
of complete source or an atomic inventory. Acknowledged no-learning is an agent
assessment; a verified landing does not mechanically prove that a lesson came
from the assessed turn. See the [turn guide](../../skills/agent-memory/turn/GUIDE.md)
for the governed workflow and acknowledgment.

Focused tests establish individual adapter and recovery behavior; successful
end-to-end automatic capture and publication under each real client's normal
permissions must be established separately. In particular, an isolated Codex
fixture observed one Stop continuation and correctly retained pending when the
sandbox denied a command; that is not proof of a completed publication or of
production hook trust. Custom harnesses can invoke the skill and CLI explicitly.

## Recovery and validation

The release also addresses actionable lifecycle and sharing diagnostics and
bounded update compatibility observation. Preserve the reported state and follow
the repair instructions when a check fails; do not treat a local admission as a
landed memory. Release qualification is recorded against the actual shipped
source and uses focused local checks on the supported platforms. Individual
routine test invocations should reasonably finish within 10–15 minutes.
