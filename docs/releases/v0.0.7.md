# v0.0.7 — Checkout continuity and actionable Codex hook failures

Previously adopted repositories now remain recognizable when the filesystem's
device number changes, provided the recorded location, inode, project/bank and
authority evidence still agree. Project IDs and memory contents are preserved.
`am doctor` explains recovered continuity; optional `am doctor --fix` persists
the current alias. Prepare older pending proposals again after repair.

Codex prompt and stop failures now report a fixed stage/reason and retain small
private diagnostics. `am doctor` reports each adapter independently. Failures in
one worktree cannot be cleared by another. Safely owned corrupt diagnostic files
can heal; foreign or redirected paths remain protected. Missing prompt source
records require a new actual prompt and are never reconstructed as completed.

This release follows the RCA and independently reviewed ADR-0019. No personal
memory, cross-repository sharing, MCP or consumer adoption of this project's
development memory is introduced. Existing unrelated roadmap work is not claimed
as delivered by these corrections.
