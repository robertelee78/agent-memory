# v0.0.10 — Publication and dispute diagnostics

This corrective release supports memory publication by explicitly allowed GitHub
users on branches with classic push-actor restrictions. AM reads the current API
user and complete allowed-user list, matches stable identity, and rechecks the
policy before the ordinary protected-workflow push. Existing required reviews,
status/check App identities, merge-object validation and source readback remain
in force. Admin or write permission alone does not establish an explicit grant.
Unverifiable, malformed, incomplete and team/App-only eligibility remains pending;
a transport rejection identifies possible API/Git credential mismatch. No
repository protection is changed or bypassed.

A valid dispute-state successor that exceeds capacity now identifies the actual
dimension, proposed amount and supported limit, separately from damaged or
interrupted persisted state. Limits remain 4,096 dispute records, 4,096 predecessor
resolutions per record, and 16,777,216 sealed registry bytes. Exact limits remain
supported; excess refuses before durable replacement. Evidence and pending work
remain intact. Recovery cannot expand capacity; this release does not prune
history, raise limits or introduce automatic archival.

The release implements [ADR-0022](https://github.com/robertelee78/agent-memory/blob/main/docs/adr/0022-restricted-push-publication.md)
and the capacity-diagnosis outcome of [ADR-0018](https://github.com/robertelee78/agent-memory/blob/main/docs/adr/0018-repair-diagnostics-and-observation-bounds.md).
Publication, source assessment and freshness remain distinct; locally admitted
learning is not reported as landed memory. Each repository owns its own
Git-tracked memory bank, and consumer installations exclude this repository's
development memory.

Fully silent native OpenCode completion, Codex workspace-write exchange, full
24-session stress qualification, matched coding-outcome evaluation and optional
federation/graph work remain deferred backlog for v0.0.11. Their approval gates
remain in force. Existing v0.0.9 native behavior and its explicitly documented
OpenCode control-text limitation remain; this release does not claim otherwise.
