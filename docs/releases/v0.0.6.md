# v0.0.6: faster updates and safe repair

Install once per computer on macOS or Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/robertelee78/agent-memory/main/install.sh | bash
```

Use `am update` to check the managed release. When the authenticated release and
owned installation are current, it reports that `am` is up to date without
scanning unrelated repositories or restarting clients. If installed client
integration needs reconciliation, the updater still verifies and applies the
necessary changes. `am update --check` remains a preview.

If upgrading from v0.0.3, run `am update` twice: the first invocation uses the
older updater, and the second activates newer hook targets. Put Python 3.11 or
later first on PATH if the old updater cannot find it. Restart agent sessions
when the command requests it, and review Codex hook trust when prompted.

Run `am doctor --repo /path/to/project` for a read-only audit. Run
`am doctor --fix --repo /path/to/project` to repair supported issues whose
source, ownership and safe action can be verified. It can reconcile missing or
outdated owned runtime and client integration, recover a verified interrupted
runtime activation, and finish cleanup of an unlocked bank transaction whose
verified receipt already establishes the outcome. It reports each repair and
remaining issue. A healthy repeat makes no repair.

The repair preserves unrelated user content and memory. Modified or foreign
targets, unknown or live locks, ambiguous recovery outcomes, migrations and
arbitrary projection files are left intact with a next step. It does not purge
memory. Use `am uninstall` to remove the runtime while preserving repository
memory; `am uninstall --check` previews that operation.

See the [v0.0.4 guide](v0.0.4.md) for the turn-boundary workflow and its
permission and verification limits. Under Codex workspace-write restrictions,
Git metadata writes can be denied and sharing remains pending; support is
tracked in [#217](https://github.com/robertelee78/agent-memory/issues/217).
