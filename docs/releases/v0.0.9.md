# v0.0.9 — Daily-use repairs

This corrective release addresses refresh failures and intrusive routine memory
bookkeeping. It does not add the deferred roadmap work tracked for v0.0.10.

Quick refresh and native state access now share the existing private-ancestor
trust policy. Protected group-writable directories below an owned private barrier
are accepted consistently; unsafe unprotected paths, foreign ownership, symlinks
and changed source observations remain refused. Refresh failures identify their
phase and a safe, specific cause. Doctor checks the relevant local prerequisites
without claiming that it contacted the remote authority.

Codex and Claude can combine routine refresh and an exact no-learning assessment
in one quiet stdin call. No request workspace is needed. OpenCode retains its
queued native control pass; a successful acknowledgment has no receipt body and
the pass must preserve the original task answer without repeating it. Tool cards
remain controlled by each client. A post-answer fallback preserves the original
answer record; SDKs that select the final control record may require callers to
select the original business answer explicitly. The adapter does not repeat it
to disguise that attribution limit. First-use guide loading and task recall remain
separate from routine maintenance.

Combined operation health distinguishes refresh from source assessment. Completing
an assessment cannot turn failed refresh into overall success. Failure notices
identify each failed stage and give a next step; an unchanged known failure does
not repeat the same repair notice every turn, while a new assessment failure is
reported. Pending sources and existing recovery evidence are preserved.

The release implements ADR-0021. Each repository still owns its Git-tracked
memory bank; consumer installations do not inherit this repository's development
memory. Signed verification continues to refuse unexpected installed files,
including executable bytecode caches. Diagnostic imports use isolated Python with
bytecode writes disabled rather than weakening verification.

Native conversation evidence is retained for [Codex](../research/2026-10-28-v009-codex-native.md),
[Claude](../research/2026-10-28-v009-claude-native.md) and
[OpenCode](../research/2026-10-28-v009-opencode-native.md).
OpenCode 2.1.3 with Baseten Kimi K3 completes its combined memory check,
but its queued control pass still emits extra completion text. The tested
request-local terminal optimization failed native qualification and is excluded.
Codex and Claude's quiet-flow qualification is recorded separately. This draft
requires the operator's product decision on that OpenCode limitation before
publication. Public signed delivery checks remain pending.
The source-bound qualification report records actual client behavior and
limits; a passing contract test alone does not establish an invisible workflow or
universal semantic correctness.
