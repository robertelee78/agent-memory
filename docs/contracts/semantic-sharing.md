# Semantic reconciliation before memory exchange

The [portable reconciliation guide](../../skills/agent-memory/sharing/semantic/GUIDE.md)
separates actual source observation, agent meaning judgments, format/currentness
guards, output candidate banks and applied publication/refresh. `reconcile_memory.py`
provides inspect/review/check operations and never writes canonical memory or
pushes a branch. The calling publication/refresh operation must recheck complete
source/Git/scope pins, apply repository/security rules and read back actual writes.

The source set is complete and bounded: ordinary context and typed records from
actual local/landed snapshots, with their exact path/hash, metadata, origin and
scope. Every source pair requires a source-bound meaning judgment, including
cross-file and textually clean Git cases. No deterministic keyword classifier
claims to discover natural-language truth. Unknown applicability cannot become
a proven disjoint condition. Actual lifecycle links distinguish retained history.

Compatible nonoverlapping same-context edits combine from their exact three-way
line deltas after explicit meaning review. Overlapping changes require correction,
not an arbitrary replacement. Equivalent current typed records under identical
conditions/type/validity/trust/visibility consolidate through the existing pure
lifecycle/provenance builder, retaining stable identity, all origins, evidence,
older exact versions, duplicate relations and events. Full currentness includes
qualified invalidators of other kinds or hidden bodies. Grouping never revives
inactive or invalidated learning.

Contradictions/uncertainties disclose both claims and their actual evidence to
the detecting developer. Known other-developer origins recommend clarification
without automatic messages. Only disputed paths and explicitly declared transitive
dependent updates pause. Separate refresh/publication candidates preserve local
unpublished work and existing authority respectively while combining independent
updates. Neither candidate is a truth verdict or an applied refresh.

Actual developer clarification goes through governed correction/supersession.
A subsequent fresh semantic review can consolidate the resolved duplicate while
retaining the decision reference and both origins; stale proofs cannot overwrite
the correction. Code/intent/work conflicts still use the existing authority
matrix and focused product questions, without duplicating AWA or Vox state.

Isolated public tests exercise yellow/blue in separate files, independent work,
explicit dependency isolation, compatible same-file edits, differently worded
duplicates, disjoint and unknown conditions, full pair coverage, stale/tampered
proofs, hidden/other-kind invalidators and an actual clarification/correction/
consolidation path. Optional caches, hooks, MCP and live credentials are absent.
