# A useful bank without federation

One project's Git-tracked Markdown is useful without a federation catalog,
knowledge graph, vector store, daemon, network service, installed harness or
cross-project export. The [offline guide](../../skills/agent-memory/offline/GUIDE.md)
remains the plain-file route. The portable initialization, checkpoint, retrieval
and validation helpers run directly from the copied package with Python and Git.
Actual local developer/project binding and private write receipts are separate
from a federation service; they do not create personal memory.

Public end-to-end cases initialize from actual local documentation, code and
approved intent, checkpoint four useful fields, resume from Markdown and perform
ordinary-text orientation lookup. The intended target and observed code stay
distinct; orientation is explicitly unadmitted. The cases preserve unfinished
code, unrelated staged entries and HEAD. They also version/export the exact bank
through ordinary Git, inspect the same-project backup, remove disposable private
state, edit/read/validate ordinary Markdown and repair a known accidental file
edit from its inspected Git version without resetting unrelated work.

A separate real-process interruption case recovers a provably dead local lock
and replays the exact checkpoint with its retained private evidence. Removing
required recovery evidence is not cache cleanup, and no federation-free claim
allows bypassing unknown locks, journals or project identity. State loss still
requires explicit identity resolution before subsequent mediated operations.

These proofs establish the single-repository baseline only. They do not implement
federation, automatic cross-clone sharing, governed admission, a release-complete
bank round trip or restore of arbitrary lost recovery journals. Required later
exchange and release groups remain pending.
