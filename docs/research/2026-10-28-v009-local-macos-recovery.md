Its pre-repair doctor result is retained at `/tmp/am-v009-macos-pre-repair-doctor.json`. The discrepancy was generated bytecode, rather than changed owned source payloads. Exact-inventory verification correctly refused an unowned executable-cache extension; a valid manifest signature does not automatically authorize extra installed files.

The caches remain outside the signed installed inventory even when their bytes are consistent with compilation of signed source.

This is recovery of a pre-existing local-profile discrepancy. It is separate from the fresh public install/update canaries; it does not establish a new failure in the published archive.

## Preservation and validation

The recovery reused the prior bounded Linux quarantine procedure with the macOS native rename primitive. A standalone `python3 -I -B` standard-library-only helper:

1. Opened trusted directories and regular evidence files without following symlinks; pinned owner, inode, device and mode identities and checked bounded file reads.
2. Acquired the existing lifecycle lock using nonblocking exclusive `flock`, validating its owner, regular-file/link/mode properties and lock schema. It did not replace that lock or rewrite owner metadata.
3. Rechecked the exact source inventory, every expected hash/mode, the 27 exact cache entries, and the cache-directory identity. It retained receipt/journal hashes and identities.
4. Created one exclusive private recovery operation directory and wrote/fsynced its inventory manifest and forensic report before moving anything.
5. Used descriptor-relative `renameatx_np(..., RENAME_EXCL)` to move only the pinned `__pycache__` directory into that private operation's `bytecode` entry. The destination could not overwrite another entry.
6. Verified the moved directory and all 27 preserved files against the prior evidence, and verified that the source now has exactly the expected 190 files. Receipt and journal identities/content remained unchanged during the operation. Parent paths were rechecked and directories synced.

Operation ID: `30c363d6-a9dc-4290-b90b-dff83c024c7e`; completed at `2026-10-28T15:07:14.993956+00:00`.

Read-only forensic report: `/tmp/am-v009-macos-bytecode-forensics.json`. Exact executed recovery helper: `/tmp/am-v009-macos-quarantine-executed.py`. No new model run, release claim, or automatic cache-cleanup feature was added. The parent release workflow performs and verifies the actual upgrade separately.
