# #255 retained failure analysis and replacement-evaluation boundary

Status: retrospective source/evidence analysis and a proposed future comparison, not G1 acceptance. The independent analysis slice made no runtime, endpoint, model, graph, scorer, test or tuning calls. The parent published this derived report and proposal with updated provenance and explicit release-scope limits; the raw private analysis/proposal and all historical observations remain preserved. These document edits do not modify canonical memory, another integration tree or the frozen runtime-qualification clone.

## 1. Decision in brief

Changing a vector-search binding can avoid the observed **wrong signed output score**, and eliminating request-time vector-index DDL can remove that particular DDL operation from the query path. Neither change fixes a model ranking miss, an incorrect eligible-source domain, missing native semantic selection, template/label disagreement, caveat/authority assembly, or deletion accounting. These are separate mechanisms with separate consumers and evidence requirements.

The retained evidence favors eligible exact signed cosine as the correctness baseline, with a separately qualified optional accelerator. It does not support replacing the embedding model, adding neighbor text, or adopting ANN as a semantic-quality repair. The same-weight upstream server is a plausible serving candidate, not a demonstrated semantic improvement. Standalone USearch now has actual numerical evidence, but not AM semantic or native-eligibility evidence.

**Decision authority update:** [Accepted ADR-0027](../adr/0027-managed-core-memgraph.md), published in8a56e0e2e82b7224452a0559652b3f9f5aca4f85 and merged into this candidate, records the operator-selected **AM-managed core Memgraph direction**. Approval is graph direction only, not serving/model selection, licensing clearance, G1 acceptance or dependent implementation readiness. MAGE/9341 remains the historical measurement reference; core does not cure the shared signed-score defect.

## 3. Failure taxonomy: what replacement can and cannot change

### A. Actual wrong signed score, downstream misordering

**Observed [S5]:** for both core and MAGE, unit `[1,0,0,0]` and nonunit `[2,0,0,0]` queries return the antiparallel source with ANN `distance=2`, reported `similarity=+1`, database exact cosine `-1`, and independent host cosine `-1`. Raw engine arrival puts it last. The consuming SSG `search` query yields `similarity`, exposes it in `facts`, sets `ord=-similarity`, then orders by `ord,key`; that query puts the antiparallel source first. This is a demonstrated output-score/consumer-ranking defect, not merely a hypothetical sign convention.

**Source mechanism [S10]:** `SearchNodes` first calls the USearch index search, then wraps `SimilarityFromDistance(...)` in `std::abs` while building its output tuples. For cosine the helper returns `1.0-distance`. Therefore the tagged source predicts exactly `2 -> -1 -> +1`. It also declares a USearch-backed index. This is source-level causal support plus matching pinned-binary observations, **not reproducible-build attribution of those binaries**. Because candidate search precedes `abs`, this source mechanism alone does not prove incorrect ANN candidate selection. Downstream ranking or filtering on the returned similarity can nevertheless be wrong.

**Addresses it:** eligible exact signed cosine; or independently computed signed cosine rescoring of retrieved candidates before any score cutoff/order. The exact database function agreed with independent controls here. A distance-based conversion can be evaluated under an explicitly verified cosine-distance contract; do not silently repair old evidence or trust a field named similarity.

**Does not address:** rescoring cannot recover candidates not returned. Core-only substitution retains the observed defect. Changing the model/server or adding graph edges is unnecessary to fix this arithmetic/output error and cannot justify accepting the old SSG score. The old semantic miss below was already evaluated with independent exact cosine and is not explained by this defect.

### B. Model, renderer, profile and cache-history changes are different from score bugs

**Observed [S3/S4]:** the same-weight serving run changed only the serving build while binding actual loaded local dependencies. Across builds the maximum coordinate difference was `1.1330842971801758e-4`, maximum cosine distance `2.3421633865705616e-7`, maximum ranking-score drift `1.3965302161811355e-4`, and synthetic rank-order changes zero. Same-path cold restarts were exact. Within a process the first versus repeated probe row 0 used `0+9` versus `2+7` cached/evaluated tokens; repeat maximum coordinate differences were `9.326823055744171e-5` for fork and `1.2361444532871246e-4` upstream. Same-split repeats were exact. RAM cache was disabled, **slot-prefix reuse was not**. Alias comparisons used different cache paths and cannot identify alias-induced drift or immutable weights.

Renderer changes are a larger and separate intervention: six own documents used 87 tokens, while appending a neighboring document body after `Related title:` used 193. All four complete ranking orders changed, maximum rank displacement was four, and own-to-relationship cosine distance reached `0.25703618946818574`, without any changed top-1. These are adapted synthetic texts, not a proof that actual SSG renderer bytes or AM guidance improved. The frozen AM-shaped renderer is exact own body plus canonical scope; its query prefix is the AM retrieval instruction. It does not concatenate neighboring bodies.

**Addresses it:** immutable profile identity binding model/artifact, loaded build/dependencies, dimension, normalization, renderer, prefixes, context and batch policy; explicit re-setup/re-embedding on observable changes. A new model or renderer could change semantic quality **[INFERENCE: unmeasured direction]**. A serving build could change numerical behavior **[INFERENCE beyond these probes]**. These require separate paired tests, not interpretation of the old ranking outputs.

**Does not address:** exact rescoring faithfully evaluates the vectors it receives; it cannot repair incompatible old/new vector spaces or missing source text. Graph-core substitution cannot fix embedding-profile drift. Coordinate diagnostic `1e-5` was exceeded and is not relaxed, but it was never an upstream-usability veto or a learned semantic eligibility threshold. Fixed probes remain disabled under §7 until representative fill cost and an independently established cosine tolerance exist; equality cannot attest opaque provider weights.

### C. Wrong source domain and missing native semantic source selection

**Observed [S1/S2/S4]:** case 58 (`e-id-intersection`) was ranked over 10 sources instead of the one current version requested by exact ID. The original `Fixtures.qualify` used `_eligibility` without the ID/path selector restriction, and its crosscheck explicitly cleared selectors. Case 59 is likewise unqualified as a selector control. These are selection/protocol failures, not evidence of poor model discrimination. The new contract is union of explicit IDs OR paths, intersected with other qualification/discovery gates; it is not an intersection between IDs and paths themselves.

A second, broader boundary remains: the research executor computes a complete exact ranking, and the scorer selects its own evaluation K. It does not hand an internal complete source-score map to the native semantic reader or exercise final primary packing and caveat assembly. The source computes `outcome` and `caveats` as unexecuted prerequisites. Literal/path selection cannot be converted into the §8 semantic seam by sorting the already selected native output; literal matching and result budgets may already have discarded sources or flattened external rank. This is missing qualified integration, not an observed end-to-end semantic result.

**Addresses it:** correct source-domain selection before ranking, preserve the native exact-selector union and all scope/lifecycle/trust/visibility/safety/condition/hold gates; then complete source-identity score handoff before native result-count and byte budgets, followed by source/profile/frontier rechecks. §8 explicitly requires this regardless of backend.

**Does not address:** faster exact search, an ANN index, another embedding model, or a different graph cannot add these native selection/packing semantics. A global ANN top-K followed by qualification is not a complete eligible top-K and cannot establish absence. Current corrected helpers must not be cited as evidence that the frozen run had the correct domain, or as fresh validation on the opened labels.

### D. A genuine exact-cosine semantic ranking miss

**Observed [S2/S4]:** overlay case 89 (`ov-batch-attempts`) retrieved three of four required sources at the scorer-only K=5; the replay-result source was ranked eighth. The same special source/query set appears at 1k and 10k, so those are repeated controls, not two independent quality samples. The request limit was 16; this failure is specifically the frozen scorer top-K metric, not a demonstrated omission from a shipped native response.

The canonical overlay includes a result saying replaying the crash trace against sequence-tagged chunks applied every row exactly once. The query asks what was tried for nightly imports and what was settled on. The result is required alongside two attempts and the corrected decision; its `SUPPORTED_BY` evidence is recorded, but no `DERIVED_FROM` result-to-decision assertion exists. The frozen label is retained, not changed to fit the ranking or graph.

**Could address it [INFERENCE]:** a better independently qualified embedding model/own-text representation or an explicit recorded-evidence navigation/assembly mechanism could recover relevant verification. Whether either improves fresh tasks is unmeasured. The graph may navigate recorded support; it must not invent a derivation edge or replace primary-ranking/caveat policy with arbitrary expansion.

**Cannot address it by itself:** another exact-cosine implementation on identical vectors/domain should reproduce the mathematical order within its numerical contract. ANN exact rescoring already had the entire domain here; it cannot move rank eight into top five without changing ranking policy, representation, or model. No upstream-serving quality gain was demonstrated. Increasing K, tuning a prompt, or adding relations after reading this held-out output would be held-out-informed development, not new qualification.

### E. Graph-template/label mismatches, not proved traversal-engine faults

**Observed [S2/S4]:** typed failures occur in cases 85/86/89/98/99. Every returned edge was canonical; missing required paths and primaries have concrete protocol causes:

- `executor_graph.typed` explicitly excludes the seed from `primary_candidates`; labels in these cases require the seed as primary guidance. This mixes primary selection with related-result extraction.
- `component-attempts` only traverses `DERIVED_FROM|IN_SCOPE|SUPPORTED_BY` to a `RecordVersion` target of kind attempt/decision/result. Case 85 requires scope AND condition endpoints; case 86 requires a scope endpoint. The template cannot emit those as its required target paths.
- Case 89 requires the correction edge to an inactive prior decision, but this template excludes `CORRECTS` and qualifies current record endpoints. Its replay result has shared evidence, not a derivation; the template does not promise all evidence-chain semantics needed by that label.
- Cases 98/99 can have legitimate recorded evidence/derivation paths while still failing required-primary scoring because the seed was excluded. Shared evidence is not recorded derivation; shared routing/origin is not task relevance.

The correct template-case accounting is 10 of 15 overlay and 7 of 12 base typed cases executed; historical `replacement-evidence` was 0 of 5. Do not pool different-mechanism cells or promote no-failure predicates into a typed suite pass.

**Addresses it:** independently reconcile the intended query contract, allowed node/edge types, seed-as-primary versus optional related references, historical disclosure qualification, and the oracle before a new freeze. The contract can deliberately keep separate primary and related channels. Any new interpretation must disclose its dependence on opened outcomes and preserve old labels/scores.

**Does not address:** a different graph database faithfully running identical restrictive Cypher would not supply absent relations, include excluded seeds, or implement historical authority. Exact scoring/model changes cannot change these path constraints. This does not prove that the graph concept failed, or that replacing the engine repairs the suite.

### F. Caveat, authority, abstention, disclosure and deletion correctness are separate gates

**Observed [S1/S2/S4/S7]:** outcome/caveat/public-disclosure/literal-status mappings and calibrated abstention were unexecuted. Raw ranking is not a qualified semantic no-match, and a source with no literal overlap is not thereby inapplicable. Mandatory correction/conflict groups precede semantic ordering; optional graph references cannot displace them. Context prose stays orientation-only, regardless of similarity.

Case 76 (`m-delete-receipt-rebuilt`) keeps its frozen provider-canary failure. Its observation contained size-wide sends including the legitimate original `receipt-b` send; neither delete generation issued a document request. That whole-run oracle cannot distinguish the earlier permitted send from a forbidden post-delete send. This is **not evidence of an observed post-delete disclosure**, nor evidence of successful erasure: the shared persisted vector file retained the prior row, and there was no actual temporal delete/purge/readback protocol. Previously retained scientific evidence is not erased data. Separate runtime-control deletion/fencing/disposal receipts are useful mechanism evidence but fill none of this suite cell.

**Addresses it:** independently reviewed contract-derived assembly and native authority mapping, calibration-only cutoff frozen before new blinded outputs, generation-scoped immutable provider/tokenizer attempt attribution, actual controlled source/profile/epoch transitions, derived-store purge and absence readback with exact ownership. Retain earlier authorized requests rather than deleting or retrospectively filtering them. Report provider retention and opaque identity honestly.

**Does not address:** signed cosine, another model/server, a graph replacement, or zero new requests cannot establish caveat completeness, no-help correctness, deletion, erasure, disclosure approval, or authority. Source-backed graph provenance and evidence critics are advisory; valid references do not prove the truth of a claim. §14 retains typed navigation and complete-generation lessons, not reasoning-model acceptance or a required critic dependency.

### G. Storage-access failure is operational, not semantic/model quality

**Observed [S6]:** the frozen 50k run failed at request ordinal 49, `CREATE VECTOR INDEX`, eligible domain 11/capacity 16, with `Cannot get unique access to the storage`. Effective storage-access timeout and an overlapping holder were not captured. A periodic snapshot is one possible mechanism named by the generic error, **not the established historical cause**. The 50k run remains failed; eight canonical generation artifacts do not imply eight completed graph activations.

The separate 8 November contrast used the pinned MAGE image and a newly recorded Python 3.15/neo4j 5.28.2 runtime: idle CREATE succeeded once; a deliberately overlapping read transaction produced the pinned transient error once. Both owned containers/four volumes were disposed, external resources preserved, and no model endpoint was called. This establishes a contention mechanism, not the holder/cause in the historical run. `historical_snapshot_cause_established=false`; `G1_acceptance=false`.

**Addresses or avoids the operation [INFERENCE]:** eligible exact cosine outside request-time graph DDL, or building a candidate-local persistent vector index once before publication, removes per-query CREATE from the read path. Standalone index persistence can separate vector servicing from graph transaction exclusivity, but needs its own ownership/publication/fence/erasure qualification. Appropriate quiescent publication/transaction ownership can be evaluated without assuming snapshots caused the old failure.

**Does not address:** changing the embedding server/model cannot fix graph storage exclusivity. Core has the same observed arm64 engine/vector module and is not a demonstrated cure. Retries, longer timeouts or disabling durability would be new unreviewed policies, not diagnosis. The new contrast and numerical USearch run cannot complete or upgrade the old 50k experiment.

## 5. Smallest useful fresh comparison before a replacement recommendation

This is a proposed bounded screen, not a statistical claim that a particular case count is sufficient for universal quality, and not a reduction of the original G1 ACs. No new calls or experiments are authorized by this document. Parent independent source/design review and exact source/input/profile freeze must precede any run.

1. **Hold the layers apart.** Keep the exact 8B weight, own-body/scope renderer, query prefix, native source policy and exact signed-cosine oracle fixed. Compare the 9341 reference and one explicitly selected upstream b9360 candidate with each build binding its actual platform dependency closure. Compare a standalone vector binding on the same per-profile persisted vectors separately. Do not combine graph, embedding model, renderer and serving changes into one unexplained arm. The core graph direction is recorded; it still needs a reference-versus-core qualification slice, not inherited MAGE passes.
2. **Do not repeat the completed 64-D experiment as the missing semantic study.** Next measure actual 4096-D AM-shaped vectors (and 1024-D only if that model is separately selected), native eligibility and complete source-score handoff at 1k/10k/50k. At least one eligible domain per size must actually exceed the frozen candidate budget 32, with context/ID/path/visibility/condition adversaries; report N, K and budget independently. Exact baseline, candidate recall and exact-rescored overlap are separate outputs. Reuse a persisted vector within an identical frozen profile, not across incompatible profiles. Existing opened-output vectors may support explicitly retrospective numerical/engineering comparisons, never a fresh semantic claim.
3. **Fresh independent truth: proposed 32 newly authored cases, 8 calibration + 24 blinded.** Use new canonical source content/identities/components and new questions, not just new IDs or paraphrases of the 101 opened cases. Calibrate, if needed, only on the new eight. Blinded coverage is 12 coding, eight investigation, four orientation; include eight typed-path cases and 16 semantic-primary cases, together covering no-help, low-overlap paraphrase, multiple required sources, correction/conflict caveats, selectors, hidden endpoints, unknown conditions and recorded-versus-inferred distinctions. Both arms see identical requests and truth. Multiple sizes and base/overlay variants do not multiply the independent denominator. This is a screening proposal requiring independent reviewer approval of adequacy; inadequate power or insufficient calibration yields an inconclusive result, not relaxed acceptance.
4. **Freeze the consumer, not just the emitter.** Before outputs, review the complete native source-score consumer and packing, seed-versus-related semantics, historical mapper if exercised, outcome/caveat/no-match mapper, immutable tokenizer/embedding attempt accounting and explicit state transitions. An unimplemented mapper or transition means that class is unqualified; do not synthesize the expected answer. Labelled truths and proposed numeric pass criteria must be approved independently of outputs. Keep raw ranks even where cutoff calibration is infeasible.
5. **One paired run, no adaptive search.** Freeze an arm order/cold-launch policy and deterministic request/cache history; run paired owned arms serially on the normally busy target host, recording resource inventory and competing activity without requiring a quiet machine. Score blinded labels only after raw outputs are durably hashed and any cutoff method/value frozen from calibration. Report per-case paired wins/losses, exact primary/path recall, forbidden disclosures/current primaries, mandatory caveat completeness, abstention denominators, source coverage and uncertainty. A problem found after opening new blind outputs requires a different future blind set, not relabeling/retrying until pass.
6. **Resource and lifecycle costs are part of the comparison.** Retain tokens, embedding fill, exact search, ANN build/search/rescore, graph load/rebuild, end-to-end native query, peak RAM/disk/model bytes, startup and cold/warm status separately. Three predeclared serial query sweeps per size can expose warm variability; no broad p95 claim from a tiny denominator. Include actual ordinary `activeContext.md` checkpoint commit-to-first-qualified-new-bank-state time, stopped/interrupted controls and exact-owned cleanup. Existing fault controls can inform protocol but are not fresh cells. Remove request-time DDL only as an explicit reviewed design choice, not a hidden workaround.
7. **Recommendation boundary.** A binding-only recommendation can be limited to signed-score correctness and measured resource behavior if native integration and eligible recall are established; it cannot claim semantic/coding benefit. A serving-build/model recommendation additionally needs fresh paired AM quality and no safety/caveat regressions. Any ANN claim must meet the operator-frozen eligible-recall threshold at budget<N or remain optional/unselected. A 0.6B model or different renderer is a separately named, fully re-embedded arm only after explicit selection, never a silent fallback. Full core/profile/platform/license/G1/Ready acceptance still needs the original gates below.

## 6. Research and release boundary

The proposed32-case screen is for a **new semantic/product recommendation** after
opened outcomes have informed development. It is not a newly invented unconditional
v0.0.15 gate, permission to change old labels, a complete production implementation,
or a reduction of the original [ADR-0024 G1 eight research criteria](../adr/0024-ssg-graph-embedding-runtime.md).
Negative measurements and genuine unavailable prerequisites remain valid research
outcomes where those original criteria allow them; absence must not be relabeled
a positive pass. Exact execution decisions, maintenance-cost evaluation, original
required comparisons, human deployment/resource dispositions and final independent
compatibility review remain with#255. Production consumers/daemons need not be
implemented just to finish a research/design contract.

The [measured numeric alternative](2026-11-08-vector-alternatives.md) establishes
correct signed scoring on its fixed64D inputs and exposes actual bounded candidate
misses; it does not establish AM4096D quality. Reuse the retained same-weight
serving/profile measurements for their actual scope. A changed model, renderer,
source policy or production recommendation must earn its own paired evidence.

No raw private bank, transcript or credentials are published. This is retrospective
source/evidence analysis; no additional experiment, runtime change, threshold,
operator/legal approval, G1 acceptance or release is claimed by this document.
