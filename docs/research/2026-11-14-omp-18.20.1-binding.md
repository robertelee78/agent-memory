# omp 18.20.1 source binding refresh

Status: source refresh, written 2026-11-14 for the operator decision that
agent-memory v0.0.15 targets omp 18.20.1 only. It **needs independent review**.
It is source reading, not native qualification, release acceptance or a review
verdict. It re-binds every omp source reference in the
[#249 integration design](../design/v0.0.15-omp-integration.md) and the
[instruction-context design](../design/v0.0.15-omp-instruction-context.md).

## Verified behaviour

### 1–4. Failed path

- **Requeue on throw.** `#promptQueuedHiddenNextTurnMessages` (AS:10664-10687):
  1. copies `#pendingNextTurnMessages` and clears it (AS:10669-10670);
  2. prompts the last message with the rest prepended (AS:10676-10682);
  3. on a throw, restores `[...queued, ...pending]` and rethrows (AS:10683-10686).
- **Scheduler catch.** The scheduled task in `#queueHiddenNextTurnMessage`
  (AS:10631-10662) catches that throw and leaves the messages queued
  (AS:10647-10651).
- **Source-identified causes.** No model throws `PromptPreflightError`
  (AS:9567-9573). A missing API key throws after
  `applyMissingCredentialFallback` fails (AS:9576-9584).
- **Abort during credential fallback.** If setup is aborted during the fallback,
  AS:9579 returns `false` instead. That is the skipped/lost path, as at
  18.16 AS:8881.
- **Next ordinary prompt.** The next prompt pushes its own message, then every
  pending nextTurn message, then clears the queue (AS:9636-9641).
- **Diff.** Each block is textually identical to 18.16.

### 5. Skipped/lost return-false points

- AS:9625-9626 (before nextTurn injection), 9668 (`!preparedMessages`) and
  9705-9706 (after pre-prompt compaction) are the 18.16 points.
- After the queued messages have been taken out (AS:10669-10670), a false return
  does not throw, so nothing is requeued.
- AS:9718-9719 (`autoPrewalk`) already existed in 18.16 (AS:9010-9011).
- **New in 18.20.1:** `autoParallel` (AS:9708-9715). It can return false at
  AS:9710-9711 and can push a hint into the batch. It is created only when
  `message.role === "user"` (AS:9549-9550). AM's continuation is a `custom`
  `session-stop-continuation` message (AS:6023-6033), so this path is not reached
  for it.
- On a human prompt, the hint is one more companion. The empty own-guidance
  companion allowlist already classifies that as combined.
- **AM change:** none.

### 6. Abort

- `abort()` is AS:12189-12314.
  - It bumps `#promptGeneration` (AS:12227) and aborts prompt setup (AS:12231).
  - It clears the hidden-turn schedule (AS:12232) and cancels post-prompt tasks
    (AS:12251).
  - It waits for idle and `agent_end` maintenance (AS:12254-12261).
  - It then runs `#resetSessionStopContinuationState()` and
    `#clearPendingSessionStopContinuations()` (AS:12277-12278).
- `#clearPendingSessionStopContinuations()` (AS:5912-5919) filters every
  `customType: "session-stop-continuation"` message out of the pending nextTurn
  queue.
- **New adjacent line:** AS:12270-12272, `#promoteForcedFollowUps()` (AS:2020).
  It runs only for a user interrupt with `deliverQueuedMessages`, and it reorders
  the agent follow-up queue, not `#pendingNextTurnMessages`.
- **AM change:** none.

### 7. Deferred/unsupported

- Streaming `nextTurn` still queues with the caller's `triggerTurn`
  (AS:10990-10992).
- The three ACP deferral branches now test only
  `this.#clientBridge?.deferAgentInitiatedTurns`. The 18.16
  `&& !this.#allowAcpAgentInitiatedTurns` exception was removed
  (AS:11016, 11056, 11076).
- ACP is not a claimed TUI/print/RPC mode. No stock path that defers AM's own
  trigger-turn `session_stop` continuation was found in 18.20.1.
- The conclusion stays a version-pinned source inference that needs independent
  review.
- **AM change:** none.

### 8. Pending-count blindness

- The `queuedMessageCount` getter (AS:11249-11260) counts pending nextTurn
  messages only while a hidden turn is scheduled. Otherwise it counts only advisor
  cards (AS:11252-11255).
- The scheduled task clears the schedule before prompting (AS:10641-10642), and a
  requeue keeps it cleared (AS:10683-10685).
- RPC `get_state` still reports `queuedMessageCount` (`rpc-mode.ts:2276`).
  `docs/rpc.md:588-589` still describes it as including pending next-turn
  messages.

### 9. Write-conflict `continuationOf`

- Write-conflict recovery calls `#moveOffSessionFile`:
  - after `MAX_WRITE_CONFLICT_RECOVERIES = 3` (SM:148, 1263, 1284);
  - on a replaced file (SM:1269, 1274, 1292, 1298);
  - when the session is open elsewhere (SM:1536, 1704, 1836).
- `#moveOffSessionFile` (SM:1320-1358) does the following:
  - mints a new session ID;
  - writes a header whose `parentSession` and `continuationOf` are both the old
    ID (SM:1337-1345);
  - leaves the old file untouched;
  - republishes the whole transcript into the sibling.
- No `session_switch` is emitted.
- The block is identical to 18.16 (SM:1282-1320).
- **New in 18.20.1:** `isOwnedElsewhere()` (SM:3303-3305). `#recordSessionExit`
  uses it (AS:3981-3985) to skip the exit record when another process owns the
  session, which removes one source of exit-time sibling moves.
- **AM response:** the adapter reads only `parentSession`.
  - `headerValue` at `skills/agent-memory/hooks/omp.ts:136-139` sets
    `fork_status` through `forkStatus` (omp.ts:133-135).
  - The next capture sees a new session ID, starts a new instance and runs the
    transition path (omp.ts:381-387, 441-455).
  - Carried entries stamped no later than the new header are inherited context,
    not new admissions (omp.ts:348-350; `src/omp_transport/observe.rs:1363-1366`).
  - The old instance's final view is recovered from the old file only if
    `retiredView` (omp.ts:180-221) proves the same identity, header and parent
    graph. Otherwise the transition finishes with
    `transition-final-view-unavailable`, which stays pending (omp.ts:444-452).
- **Compatibility limit:** a write-conflict continuation is treated as a fork,
  and the old final view can stay pending. It is not proof of a fresh human root.

### 10. Shutdown

- `#doDispose` (AS:6837-6878) does the following, in order:
  1. writes the exit record (AS:6848);
  2. awaits `emitSessionShutdownEvent` (AS:6854; RN:525-537);
  3. aborts the agent and drains post-prompt work (AS:6859-6876).
- The runner starts every `session_shutdown` handler in load order and awaits
  them all together with `Promise.all`. Each runs under
  `SESSION_SHUTDOWN_HANDLER_TIMEOUT_MS = 2_000` (RN:173, 182-184, 2042-2054).
- This block is identical to 18.16 RN:1842-1854.
- `session_before_shutdown` is a TUI gate that can cancel the close
  (`docs/extensions.md:561`). AM does not use it.
- **AM response:**
  - The shutdown handler takes a final full capture, sends FINAL and waits at most
    1.8 s for the stdin flush (omp.ts:515-539; deadline at omp.ts:516).
  - Other extensions' handlers run concurrently and can append entries after AM's
    final capture.
- **Compatibility limit:** final shutdown coverage is not guaranteed while other
  extensions run alongside AM.

### 11. Manual-read carrier

- For a located URL (`tools/read.ts:2204-2227`), the read tool:
  - fills `details.resolvedPath` (2215) and sets `contentType: "text/markdown"`
    for markdown (2217);
  - sets `details.meta.source = {type:"internal", value:url}` (2218);
  - for a `skill:` URL without a raw selector, prefixes the first text block with
    `[Skill file: <path>]\n` (2220-2226).
- The diff against 18.16 `read.ts:1972-1996` adds only the `plainWindow` option
  passed to `#readFilesystemPath` (2212).
- `details.mediaPath` is added only for Tern media extensions (2241-2244,
  2498-2504; `tools/tern-media.ts:77-84`). Markdown is not one of them.
- **New, opt-in:** the Spotlight shaping experiment (`read.ts:2820-2829`;
  `spotlight/index.ts:61-63`) can reshape a whole-file read. It is off unless the
  experiment is configured, and a shaped or extra key falls back to ordinary
  screening.
- Non-default line-number or hashline settings set `rowPrefixes` to true
  (`read.ts:3217`; 18.16 had the same rule). The recipe requires false, so those
  reads stay screened.
- **omp20 lane measurement:** under default read settings with a scripted stub
  provider, the stored carrier was byte-equal to the AM recipe
  (`src/omp_projection.rs:841-935, 959`) for `skill://agent-memory` and
  `skill://agent-memory/capture/GUIDE.md`, on both copy and link installs.
- **AM response:** the renderer ID stays `omp-18.16-full-skill-v1`
  (`src/omp_projection.rs:56`). It is a closed historical identifier for this
  exact recipe. It does not claim the producer version. A real native read is
  still required.

### 12. RPC

- The `ready` frame is protocol 1 and supports 1 and 2 (`rpc-mode.ts:1424-1426`).
- The `prompt` handler is at `rpc-mode.ts:2037` and `get_state` at
  `rpc-mode.ts:2260`. `get_state` reports `sessionFile`, `sessionId` and
  `isSettled` (2272-2279).
- `session_settled` is emitted by `rpc-session-settle.ts:103`; that file has no
  diff from 18.16.
- `rpc-types.ts` wire changes from 18.16 (`650f3a1`) to 18.20.1, the whole
  `git diff` of that file:
  - Added in 18.19 (`04cd1a7`): optional `bash.excludeFromContext`
    (`rpc-types.ts:125`), and the `ready` capability
    `supportsBashExcludeFromContext` (`rpc-types.ts:382-383`), which
    `rpc-mode.ts:1422-1429` emits as `true`.
  - Added in 18.20.1: the optional `select` UI-request fields `initialIndex`,
    `selectionMarker`, `checkedIndices` and `markableCount`
    (`rpc-types.ts:800-807`).
  - None of these changes the `ready` protocol fields, `prompt`, the `get_state`
    fields or `session_settled` that the smoke uses. Smoke clients must tolerate
    the extra optional `ready` field.
- There is no RPC command for `/clear`.

### 14. `session_clear` (new)

`resetSessionContext()` (AS:7079-7167) does the following:
1. Refuses while streaming or while a bash or eval command runs (AS:7089).
2. Bumps `#promptGeneration` and cancels post-prompt tasks (AS:7102-7103).
3. Drops the pending nextTurn queue, including a queued
   `session-stop-continuation` (AS:7114), and clears the hidden-turn schedule
   (AS:7116).
4. Resets the stop-continuation chain (AS:7122).
5. Appends a durable `reset_boundary` entry (AS:7159; SM:3782-3783).
6. Emits `session_clear` (AS:7164).

The session ID and file are unchanged (`docs/extensions.md:534-539`).

- 18.16 had the same drops (AS:6646, 6654, 6691) but emitted no event.
- The entry point is TUI-only: `/clear` (`slash-commands/builtin-lifecycle.ts:208-216`)
  calls `command-controller.ts:1399-1406`.

**AM response** (omp.ts:466-472):
- It captures a full `ingest`, which carries the stored `reset_boundary`.
  `reset_boundary` is a known non-learning entry type
  (`src/omp_transport.rs:69-80`).
- It cancels any clock window and clears `state.request`.

**Effects:**
- The pre-clear capture keeps the prior trigger.
- Later work is labelled `resume` (omp.ts:359). After a seal, a successor is
  `foreign-hidden`, not `own-hidden-ambiguous` (`src/omp_transport/observe.rs:1350-1360`).
- This is deliberate. Stock has just discarded AM's queued continuation, so
  nothing after `/clear` can be AM's own guidance.
- A native TUI `/clear` control is still required.

### 15. `/fork` aborts

- In-place `/fork` and the fork selector now call `await session.abort()` while
  streaming (`command-controller.ts:1447-1449`; `selector-controller.ts:1539-1541`).
- `fork()` (AS:12482) then emits `session_before_switch` (AS:12504-12514) and
  `session_switch` (AS:12559-12562).
- **AM response:** this is the existing skipped/lost abort path (§6) followed by
  the existing transition path (omp.ts:458-459, 441-455). No code change was made.

## Clock gate (Rust)

- **Helper.** The adapter spawns the receipt-bound absolute `am` executable with
  fixed argv `omp-boundary --stream …`, with no shell (omp.ts:266-268).
  - `src/omp_installation.rs:298-327` (`extension_wrapper`) binds
    that executable.
  - `src/omp_installation.rs:640-653` checks the runtime closure.
  - The entry is `src/omp_boundary.rs:2398-2402`, which uses
    `ClockWindows::system` (`src/omp_stream/run.rs:463`;
    `src/omp_stream/clock_window.rs:220-229`).
- **Local clock.** `clock::monotonic_ns` (`src/clock.rs:7-37`) is Linux
  `clock_gettime(CLOCK_MONOTONIC)` or macOS `mach_absolute_time` scaled by its
  timebase. The retired CPython 3.11–3.15 interpreter self-check is replaced by
  `clock::clock_identity()` (`src/clock.rs:40-50`), which must equal
  `QUALIFIED_CLOCK` (`src/omp_stream/linux_image.rs:18, 159`).
- **Linux image allowlist.** `LINUX_MONOTONIC_IMAGES` (`src/omp_stream.rs:92-97`)
  is exactly the 18.20.1 `omp-linux-arm64` and `omp-linux-x64` digests above.
  The 18.16 and 18.19 images were removed.
  - `LinuxNativeImage::observe`/`measure` (`linux_image.rs:157-231`) holds a
    pidfd and an image descriptor.
  - They record the parent start time and require matching time-namespace
    presence.
  - They hash the parent image to EOF with no trailing bytes, then recheck its
    identity.
  - `valid()` rechecks liveness, start, namespaces and image identity on every
    reservation (`linux_image.rs:253-281`).
- **Window.** CLOCK and CLOCK-ACK use four timestamps
  (`clock_window.rs:241-316`; omp.ts:497-505). `reserve`
  (`clock_window.rs:131-185`) uses E = 0 for a valid Linux image and Darwin's
  provisional 164/10000 rate allowance. It reserves only when
  `now + 100 ms < j_deadline + (p2 − j3) − drift`.
- **Wake support.** READY still advertises `wake_support: unqualified`
  (`src/omp_stream/run.rs:315`).
- **omp20 lane probe.**
  - On Linux arm64, the guard admitted windows under the real 18.20.1 image
    after hashing and refused all 79 rounds under 18.19.0.
  - x86_64 was not probed.
  - Clock provenance still needs independent review.
