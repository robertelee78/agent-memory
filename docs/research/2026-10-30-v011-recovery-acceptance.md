# v0.0.11 recovery and refresh acceptance

Independent implementation acceptance covers candidate
`fa6803b1aa7be48c2038d9d1876655d84ccc259d` for ADR-0021 T5, T6 and T7.
[Retained evidence identities](data/2026-10-30-v011-recovery-acceptance/qualification.json)
bind the actual runtime bytes; signed public delivery is a separate gate.

The first six-case public fixture run took 50.060 seconds and had four passes and
two failures. One was a real defect: a cache writer after qualification left a
preserved installation whose trusted retry could not converge. The fix retains
separate requalification evidence and the exact original journal, source and
backup identities; it permits only a freshly authenticated cache-only source
before exchange, while other targets and signed-payload changes remain refused.
Independent race and late-unsafe controls passed in 24.967 seconds. The other
failure was a fixture retry that changed its client selection; correcting that
fixture produced a passing interrupted-update/recovery/retry result in 10.42
seconds. The original unsuccessful evidence remains retained.

Public fixture coverage includes same-version repair, older-version upgrade,
read-only preview, fresh authenticated acquisition, exact opaque whole-runtime
backups, clean no-op, strict copied-client targets, changed/missing signed payload,
unsafe types/links/modes, metadata changes, capacity refusal, interrupted source
activation and trusted retry. Inclusive limits passed: 256 caches and eight
2-MiB caches totaling exactly 16 MiB. The 257th cache, per-file excess and aggregate
excess remain refused. The boundary run took 18.363 seconds. Foreign-UID behavior
was not exercised by the unprivileged public fixture; production ownership checks
remain strict. Fixture keys and isolated local HTTPS are explicitly test-only.

On Linux, a clean Git archive of source `e9cf344d7abc1aa18624d00cf6b3cf1b0cb5e094`
passed poisoned-cache startup in 0.424 seconds and the public concurrent-cache
preservation/trusted-retry case in 10.033 seconds. Source hashes are retained in
the evidence map. The later one-line wrapper compatibility correction is bound
separately: its generated bytes exactly match signed v0.0.10 and the actual Linux
owned wrapper (616 bytes). Independent final poisoned-cache acceptance, including
that retained wrapper's exact Python body, passed in 0.535 seconds. The poisoned
cache was never executed and its bytes remained unchanged. A separate public
preview/recovery proof preserved the exact old tree with that wrapper.

The final prepared-refresh acceptance controller passed 52 commands and 33 cases
in 99.841 seconds, including direct full-file import/no-op, exact-inner support,
historical retry, metadata and source-pin refusal before effects, unsafe-output
refusal and feature/index/HEAD preservation. The portable controller is retained
at `scripts/evaluations/refresh_handoff.py`; its hashes bind the runtime guard.
Portable skill validation passed at version 0.0.11.

The [RCA](2026-10-28-v011-bytecode-rca.md) retains the actual earlier writer,
qualified Mac/Linux reproductions and private evidence provenance. T5 prevention
is separate from T7's implemented opaque recovery. No cache parser or cache
benignness claim ships. Actual public signed fresh/upgrade journeys and operator
adoption will be recorded after publication; this report does not invent them.
