## Reconstruction and idempotence

Only `sharing_holds.py` changes in the portable runtime. The previous self-write exclusion was correct for a first resolution but erased an actual predecessor when a later resolution replaced it. The new code appends a deep copy of that exact predecessor to the record's ordered `resolution_history`, preserving earlier history. During validation of the current judgment, `filtered_records` restores the last predecessor and removes precisely the history item introduced by that judgment. With one predecessor it removes the optional history field entirely; with several it restores the earlier list. Thus the filtered state matches the exact pre-review record, including its inventory digest, rather than synthesizing a never-observed null resolution.

The filtering works on a deep copy. It neither changes the stored registry nor makes every old proof current. If the stored current resolution belongs to another judgment, no history is popped for the requested old judgment. The reconstructed manifest/page and source binding checks therefore remain responsible for rejecting the old request. If the same current judgment is recorded again, its complete renewed value must match, including the proof digest; a different proof under the same judgment refuses. An identical recheck does not append another predecessor or commit a changed registry.

The first-detection cause, references, dependencies and original judgment/proof identity remain intact. The fix does not replace a detected contradiction with a newer free-form label. The existing special handling for a judgment's own first-detection record is unchanged.

## Authority, disclosure and recovery

History supplies replay/audit context only. `sharing_frontier` still reconstructs current base/local/landed snapshots, maps the retained logical claims onto actual current variants, and checks manifest, ordered pages, selections and judgment binding. `sharing_hold_mapping.cached` revalidates the **current** resolution against exact current endpoint sources and evidence, qualification/visibility/safety and the claimed stronger-evidence basis. Historical entries are not separately presented as valid current guidance, and the descriptor/page construction does not newly export the entire private history.

`semantic_sharing.review` continues checking every proposed resolution against actual known causes and reviewed claim/evidence interactions. The registry writer still rechecks source freshness under actual bank ownership, compares the exact filtered inventory under its private lock, validates the desired state, commits through the existing journal/recovery/anchor path, and checks sources again. A checksum is an integrity mechanism for this private evidence, not a signature or independent proof of semantic truth.

A stale source or changed reviewed inventory therefore does not gain permission to overwrite current evidence by supplying an old resolution. No remote authority, canonical bank schema, source-selection policy, transport authentication or lifecycle permission is relaxed. Publication and refresh still rely on the same actual proof checks; the original publication refused safely, and this patch addresses its self-invalidation mechanism.

The new optional field accepts only a nonempty list of at most **4,096** predecessor objects with the exact six resolution-field names, and requires a current resolution object. Unknown record fields, empty/non-list history and wrong predecessor shape refuse. The existing **16 MiB aggregate registry**, record-count and bounded-read limits cover total retained history, and desired-state validation occurs before journal/registry replacement. An oversized renewal refuses rather than silently pruning old evidence. Historical fields are retained context, not eagerly requalified as old source authority; current evidence still undergoes the semantic validator when used. These finite bounds do not establish workload latency or infinite renewal capacity.

Recovery's source/project/lock ordering and journal compare-before-replace logic are unchanged. Both the recovery copy and desired journal include the complete history as ordinary checked registry content. Readers still accept predecessor registries without the optional field; no nonexistent past history is invented. This is backward readability by the new reader, not a claim that an older binary understands the additional field—its prior exact-field validator will refuse it.
