## Concrete impurity and smallest correction

`bank.validate_files` calls `parse_router`, then `header`, then `remote_identity.normalize` on `canonical-remote`. For **file://** authorities, normalization calls **`Path.resolve()`**. The same header bytes can therefore cease to be canonical after a filesystem/symlink-topology change. Relative authorities also consult cwd/filesystem, although a successful canonical header will normally already use the normalized form. A body-map digest alone cannot memoize that observation safely. `recovery.bounded` transitively contains the same dependency.

The implementer explicitly amended the direction during this review: **preserve fresh authority/header canonicalization before any cache hit, or bypass reuse for filesystem-dependent authorities; do not cache actual scope/identity/time/source/Git observations.** That resolves the design objection, provided it applies to **every** memo entry point, including a `bounded` hit that would otherwise bypass the inner `validate_files` wrapper.

The smallest implementation may initially memoize only the expensive pure format portion and `security.scan`, retaining the inexpensive root header/canonicalization guard on every call. Bypassing file-authority reuse is also acceptable. Add an outer `bounded` memo only if measurement justifies it and it retains that same fresh guard plus exact size/type/flag semantics. Do not rewrite authority normalization or replace current source observations merely to call the whole function pure.

`time_value` parses supplied timestamps; structural inherited-scope checks compare declared metadata to declared ancestor constraints. Those deterministic format checks can be reused under fixed loaded definitions. They are distinct from current clock validity, real session applicability, canonical project/developer authority and scope binding, which remain fresh and uncached.

## Required minimal memo contract

1. **Exact input and separate namespaces.** Every lookup must bind the complete actual path set and UTF-8 body bytes, with unambiguous lengths/serialization or the established complete per-path hash map digest. No case, Unicode, newline, whitespace or path normalization may equate different inputs. Include function namespace and every behavior flag: `allow_absent`, `quarantine_records`, scan `maximum`, and any future format option. Never key by object identity, filename, mtime/stat, commit ID or a previously saved observation alone. Unsupported/malformed argument types bypass the memo and follow the original function path; key construction must not turn invalid input into a hit. Hash and pure computation must concern the same stable invocation inputs—use a bounded owned map snapshot or bypass if concurrent mutation cannot be excluded.

2. **No caller-provided validation authority.** `parsed_records is not None` must bypass format reuse, including an initially empty output map. Existing rejection of nonempty output and actual population of valid parsed output remain unchanged. No public prevalidated parameter, hidden harness switch, environment forcing, persistent cache file, HMAC/key, service or source inventory is introduced.

3. **Success is not permission.** Cache only completed deterministic results, never exceptions, pending states or observed semantic judgments. A completed scanner result with nonempty reasons still means unsafe/quarantine; it must never become an affirmative pass. Caching only no-reason scanner results is a simple conservative choice. If other scanner reports are reused, preserve the exact redaction/reason flags and bounds. Likewise a format result certifies only format, and a quarantine-allowed bounded result is not interchangeable with strict validation.

4. **Copy isolation.** Cache an owned deep copy and return independent values, including on the first insertion. Caller changes to nested entries/routes/reasons must not poison later results, and later source transformations must not mutate a retained key/result. Do not retain whole input maps or unneeded unredacted bodies solely for memoization.

5. **Finite memory and fallback.** Specify finite entry and aggregate retained-byte budgets, covering keys/results and implementation overhead rather than just a single map's raw-bank limit. Multiple transformed maps and returned copies have a separate cost. If an item or the aggregate will not fit, skip reuse/evict conservatively and execute the original check; do not truncate evidence, drop checks or fail a previously valid operation merely because an optional memo is full. Hashing, copying and budget accounting are real work and must appear in measured costs.

6. **Fixed trusted definitions.** The reuse assumes the trusted executing validator, loaded schemas, regexes, constants and relevant defaults stay fixed for this one operation. They are dependencies of these functions even though the functions do not read operator policy on every call. Do not reuse across a supported in-process code/schema/pattern change; invalidate or bypass if such mutation is allowed. This short-lived memo does not need a new persistent engine-witness protocol. It must not be represented as isolation from hostile same-UID code or a changed executing runtime.

## Smallest operation boundaries

Start at the explicit **publication prepare/land operation** where the repeated work is evidenced. A context around those public operations or their owning `memory_publication.main` is sufficient. If independently invoked semantic inspection/review, refresh or recovery also needs this reuse, explicit contexts at **`semantic_sharing.main`**, **`memory_refresh.main`** and **`sharing_recovery.main`** are coherent: each invocation is its own operation.

Use one operation-local owner/token. A nested operation reuses the active outer memo, and only the owner resets it in `finally`; a nested exit must not clear its caller's context. All early returns, pending/error paths, parser `SystemExit` and normal completion release it. Two calls to `main` in a long-lived process receive fresh outer contexts. An inactive context must execute the old uncached path. Do not install an always-active module/process singleton, monkeypatch wrapper lifetime globally, share it between unrelated operations, or persist it across subprocesses/sessions. Where threads/tasks are used, their reuse must remain explicitly inside the owning operation and copy/budget rules; no implicit cross-session sharing is needed.
