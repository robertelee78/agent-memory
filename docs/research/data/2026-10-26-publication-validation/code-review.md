## Exact input, purity and caller isolation

`map_input` accepts only an ordinary dict of ordinary strings within its finite eligibility limits. It captures the items once, sorts the captured pairs, and hashes actual UTF-8 path and body bytes with separate eight-byte lengths. The stable dict passed to the original validator uses that same captured set of immutable strings. No case/Unicode/path/newline normalization, object-identity key, saved disk observation or caller-prevalidated result is introduced. Different path sets and changed bodies cannot share a key except by the ordinary cryptographic digest assumption. Inputs outside eligibility follow the original uncached path rather than becoming invalid solely because an accelerator is unavailable.

The format wrapper is active only when a memo exists and `parsed_records is None`. Every parsed-output request, including an initially empty output dict, still executes the original validator and produces its output; existing invalid prefilled output still refuses. The `_validate_files` algorithm body is AST-identical to the prior `validate_files` body. On each format hit it freshly calls `parse_router` on the captured root text, retaining the filesystem-dependent `file://` canonical-authority normalization identified during design review. A failed fresh guard raises before returning old format data. There is no outer `recovery.bounded` memo that could bypass this guard: its size, quarantine dispatch and source scans remain actual calls.

The scanner wrapper keys by exact UTF-8 text and the supported **integer** maximum. Unsupported types/maximums bypass caching and retain original behavior; the final tightening therefore does not silently turn an otherwise accepted non-integer call into an integer-key hit. `_scan` is AST-identical to the old body. Completed reports with redaction or quarantine reasons retain those reasons; function completion is not treated as permission. Failed checks are never inserted. Strict and quarantine interpretation still happens in the unchanged consumers; source and page limits remain distinct.

On insertion, the memo stores a deep copy and returns the producer's independent value. Hits return another deep copy. Caller edits to nested entries/routes/reasons therefore cannot mutate the stored result, and the cache retains no whole input-map reference. It does retain bounded result text in process memory, including the scanner's normal redacted/untrusted report; this is short-lived trusted-operation data, not a persistent learning-body cache, secret store or source authority. Loaded definitions/schemas/regexes remain fixed for the operation as the module contract states; this does not promise isolation from hostile same-UID code mutation.

## Bounds, lifetime and freshness

The implementation has a finite **65,544-entry**, **eight-format-map**, **64 MiB retained-weight** budget. Weight is the encoded JSON value plus 256 bytes of bookkeeping per entry; it is not a strict resident-memory cap for Python containers, input capture/sorting, encoding or transient deep copies. The RCA correctly calls these serialized-retention limits. LRU eviction updates both retained weight and map count. An individually oversized/non-serializable result returns uncached; capacity pressure evicts old optional entries rather than truncate data or skip validation. Repeated parsing after eviction is legitimate fallback, not a promise of exactly one parse per digest forever.

The four explicit CLI `main` decorators use the contextmanager/ContextDecorator mechanism, which recreates a fresh context for each invocation. Nested contexts reuse the current owner; only the outer creator resets its token in `finally`. Normal returns, pending/error returns, argument-parser exits and exceptions therefore leave no active memo behind. Calls without an operation context remain uncached. This is not a module-global always-on value cache or cross-process/session store.

AST comparison confirms the four `main` bodies are otherwise unchanged. The diff does not remove either semantic recheck, disk/Git observation, source/index/authority/policy validation, known-hold write/readback, pre-push check or post-push replay. Current applicability/time/identity and semantic judgments are not cached. Previously checked exact format/safety bytes can be reused inside those freshly acquired observations; the observations themselves are still acquired and verified.
