# Semantic map coverage: a retained missed lesson

This is development evidence for #98, not complete milestone acceptance. The
original run used exact source `6e10f5adaa82f8dd1807d699e89975f3f1b95435`
and the separately authored `semantic-navigation-v1` fixture with 1,000 lessons.
The original fixed literal corpus is unchanged.

## Observation

An actual Claude CLI model interpreted sixteen fixed questions through current
public start/node/read operations. It received actual maps and qualified source
results, without expected record labels/paths or a lexical-search tool. The
controller allowed batching independent node reads, as an ordinary harness can.
This is a custom fixture harness, not native client integration or a general
semantic-completeness certificate.

Eight of nine questions with expected current typed knowledge found their labeled
sources. One no-match question finished with an empty selection. Six other
questions retained empty selections and explicit uncertainty/clarification when
conditions, visibility, safety or time prevented usable guidance. No unexpected
record was selected. Those uncertain outcomes are not global absence proofs.

The positive miss was: “Can we resume an incremental import using its old
receipt?” with the supplied context `prerequisite: receipt-verified`. The expected
Delta resumption lesson was never requested. The model explored session recovery,
pagination, request identity, financial reconciliation, transactions and source
review, then requested clarification about a different session-bound checkpoint.
Its final coverage assertion remained incomplete; it did not invent an answer.

## Root cause and correction

The fixture placed Delta resumption under request reliability, whose root caption
described retries, failure handling and deadlines. It omitted operation resumption.
The session-recovery topic contained only a session-bound checkpoint. This map
organization concealed the applicable lesson from the observed semantic route
selection. It is a real workflow miss, not storage corruption or proof that the
reader rejected the supplied prerequisite.

A separate fixture-known exact-path diagnostic ran the actual public reader with
the same prerequisite and returned that stored lesson. That diagnostic proves
presence and mechanical eligibility only; it is not a blind semantic success.

The corrected fixture moves this lesson into the recovery topic and describes
that topic as operation resumption, recovery prerequisites and session-specific
context. These descriptions derive from the actual retained subjects. Questions,
expected record identities, facts, conditions and trust/lifecycle policy stay
unchanged. Direct SHA-256 comparison at 1,000, 10,000 and 50,000 distinct lessons
confirms every typed payload byte is preserved, including its provenance and
conditions; only navigation organization changes. The corrected fixture is
explicitly versioned `semantic-navigation-v2-map-correction`.

The skill also clarifies that an excluded candidate alone cannot establish that
the task requires its missing condition. Other plausible knowledge may answer it.
Map purposes/read triggers should describe retained subjects and conditions,
rather than storage buckets or a recent query's wording. Organization requires
fresh discovery and preserves source contents.

## Limits and next verification

All original requests/responses, model usage/cost, failed selection and before/
after source manifests remain retained. Bank, staged feature, index and HEAD
preservation passed. No model timeout, decoding failure or unexpected source
selection occurred in this run. Source and typed-payload preservation are distinct
from semantic recall quality.

Only the 1,000-lesson matrix had run at this checkpoint; no growth-related quality
claim is supported yet. Rerun the same questions against the corrected maps at all
three agreed sizes and retain any further misses. This source-layout correction
does not establish universal recall, automatically repair arbitrary bad maps,
waive the original literal baseline, or satisfy #99's required multi-session
workloads. The milestone remains open.
