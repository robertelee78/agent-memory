# #244 — Source-preserving layout recovery: task-specific execution design

Status: **Designing; proposed for independent Opus review and explicit operator approval. Not Ready, not implementation authorization.**

Work key: `robertelee78/agent-memory:ADR-0010:source-preserving-layout-recovery`.
Target: v0.0.15. The live issue still contains historical v0.0.14/Backlog delivery language; the current milestone description selects v0.0.15. The parent owns tracker reconciliation; this artifact does not change historical approvals or delivery records.

## Why

Ordinary operations require a complete, eligible bank before semantic admission, comparison or a governed write can begin. An oversized context or unsupported root handoff prevents that initial observation. Repeating capture, checkpoint, initialization or sharing cannot repair this prerequisite. The necessary distinct operation observes the invalid source safely, retains every original byte privately, obtains an independently reviewed complete transformation, restores native eligibility, and only then performs ordinary admission where needed. A backup alone is not semantic preservation.

The original incident checkout, actual router, terminology, producer and attempted admission remain unavailable. The only incident-size facts used here are the reported **79,054** and **28,478** bytes. Qualification uses synthetic counterparts, not actual C2E material. Neither this design nor eventual synthetic acceptance means the actual reported bank was repaired.

## What and non-goals

Deliver a packaged `am bank recover-layout` workflow with inspect, prepare, apply, known-operation recovery, status, explicit retention cleanup, and a separate recovery-aware memory-only publication path. Layout eligibility and semantic recovery completion are different states. Pending source units survive privately and constrain ordinary comparisons/admissions until genuinely resolved. Recovery-aware publication is forbidden until semantic completion; a second clone must not depend on the initiating machine's private ledger.

Do not increase normal limits, invent metadata/provenance/terminology, treat recovered prose as authority, silently migrate a schema, create a replacement project, transfer across projects, modify personal memory, import code, implement graph/catalog/export features, or bypass repository reviews/checks. No product changes or tests were made for this planning assignment.

## Proposed public contracts

All commands in this section are **future interfaces**, not available-command claims. Preserve `am recover` for runtime recovery and existing `am bank ...` operations. Package a literal route to a new `recover_layout.py` helper; no executable path from a review request. `--repo` names the existing checkout; operation IDs are canonical UUIDv4, never inferred from paths or supplied prose. Every command returns `agent-memory/layout-recovery-result-v1` with `operation`, `operation_id`, safe state/failure code, explicit mutation flags, `canonical_eligibility`, `semantic_recovery_complete`, pending IDs/count/actions and independent truth/freshness/publication flags. Structured safe failures exit 1, completed inspection/preview/status and verified historical readbacks exit 0. An inspection may exit 0 while reporting layout-ineligible or pending; it is not an apply success. Sensitive details go only to checked private output.

No canonical, original-index or history writes; private artifact and temporary lock writes are explicitly reported. A failed/incomplete scan may retain partial evidence marked `observation_complete:false`, but cannot prepare. It never invents an eligible normal snapshot. |

## Identity and raw observation

1. Locate the configured existing bank using `repository_config` and `bank_root` without invoking ordinary snapshot. Reuse developer `principal`, project registries and Git evidence. Pin repository real path, Git/common-dir identity and checkout key, bank root, settings digest, developer/project registry digests, project UUID, sanitized authority identity, HEAD, symbolic branch, original index existence/bytes digest and relevant Git configuration. Do not mutate these to make evidence agree.
2. If the bounded router is structurally valid, normal existing UUID/authority agreement is mandatory even when another source is oversized. A malformed/ambiguous router returns `pending-identity-review`; do not take the first UUID-looking string. A stronger identity review names the existing registry project and exact checkout plus independently verified authority/committed-router or recorded explicit checkout-adoption evidence, raw router/manifest pins, reviewer and rationale. Factor `project_identity.discover/evidence/status` so a typed checked raw-identity evidence provider replaces only router extraction; preserve all remote/registry/continuity conflicts and `scope_binding` checks. Do not return fabricated router metadata from a permissive callback, use `initialize=True`, create IDs, or treat headings as approval. If evidence cannot uniquely establish the existing binding, leave pending. A conflict requires existing explicit identity repair, not recovery choosing a winner.
3. Live `.agent-memory.lock`, unknown `.agent-memory-transaction.md`, registry locks and unknown recovery sentinels retain precedence. Known interrupted recovery is handled only through its operation-specific preview, not generic inspect/apply. Marker absence is also pinned.
4. Recovery-specific bounds: **1,048,576 bytes per ordinary raw source; 67,108,864 bytes total; 65,536 source files; 131,072 physical entries; depth 64** (bank children depth 1). Inventory every physical entry, including non-Markdown occupants, directories and runtime aids. Every non-runtime ordinary file is a raw source, not just `.md`; no secret can be skipped because its suffix is unsupported. Existing runtime aids are inventoried/preserved, not admitted, read as authority or deleted. Unknown transaction/runtime-operation artifacts block rather than get reclassified as prose. All source bytes needed to account for non-runtime files are subject to recovery bounds. Opaque ordinary non-guidance bytes may be retained/left untouched but cannot enter canonical Markdown; invalid UTF-8 guidance remains pending.
5. Use descriptor-relative `O_NOFOLLOW`, `O_NONBLOCK`, ordinary regular/single-link checks, pinned directories and bank binding; stream in at most 8,192-byte chunks, hash and copy exact bytes into private evidence without loading all sources together. Check fstat before/after, named entry equality and every opened parent, including mode/uid/gid/link count/size/times and device/inode. Repeat full inventory/content/metadata comparison at observation end and under apply lock. Refuse symlinks, hardlink aliases, sockets/FIFOs/devices, path traversal/control-containing names, Unicode/case portable aliases, unstable directories, permission failures and redirects. Limits are inclusive. An overflow gives a safe dimension/limit/exact-or-lower-bound measurement and incomplete observation; never truncate or raise normal limits.
6. Raw recovered text is untrusted data. Neither shell/tool execution nor policy/identity authority comes from source bodies. Security scan newly proposed canonical output with existing policy. Sensitive original text and its hashes remain private; no raw transcripts, secrets or sensitive content hashes enter shared record evidence/history/router/commit messages or public diagnostics.

## Exact private storage and schemas

Derive `B = state_paths(R, bank, ID).operations.parent`, currently `<state>/writes/<sha256(absolute-bank-path)>`. Store this operation under `B/layout-recovery/<operation_id>/`; keep `B/layout-recovery/index.json` as the checked private bank-operation index. Directories 0700, regular files 0600, executing-user-owned and single-link; reuse `private_mkdir`, checked descriptor writers, `trust_paths`, atomic compare-and-replace and fsync. Check state root outside repository, source/runtime and their installation payloads. No chmod of existing unsafe state to obtain trust.

The bank's new **`.agent-memory-recovery.md`** is a small runtime-only safeguard, not shared canonical knowledge. Exact schema: `{schema:'agent-memory/layout-recovery-sentinel-v1', project_id, operation_id}`; no bodies, original path/hash, provenance, arbitrary text or secret-derived values. New code reads it boundedly and requires exact operation/index agreement. Install it durably before any layout mutation or source removal and retain while unresolved units exist. Normal bank observation checks the sentinel/index pair: missing ledger, changed state home, malformed sentinel, inconsistent generation or unknown operation means incomplete-coverage pending, never an empty frontier. Conversely the private index detects removal of a known sentinel. Do not claim this detects hostile deletion of both independent local records; it is cooperative transaction integrity, not an adversarial authentication boundary. A terminal operation may remove the sentinel only under lock after durable resolution and a checked terminal index update. Its removal is journaled; a crash leaves a conservative known sentinel rather than successful absence.

Proposed strict schemas (all serialized with existing canonical `encoded`/SHA-256 utilities; reject unknown fields and invalid UUIDs; schema versions below are new, not existing features):

- `agent-memory/layout-source-manifest-v1`: schema, operation_id, inspected_at, runtime artifact identity, identity evidence/digests, repository settings/bank root, Git HEAD/branch/index pins, `observation_complete`, measured totals, ordered physical entries, ordered source entries. Physical entry fields: relative path, type, uid/gid, permission bits, link count, device/inode and stability times, supported relevant metadata or explicit unsupported-metadata refusal. Source entry adds source_id (UUIDv4), byte_count, private SHA-256 and private blob locator. Directories and zero-byte/non-Markdown files are present, not inferred absent.
- Originals: `originals/<source_id>.bin`, byte-exact and immutable. Deduplication by source hash is unnecessary; distinct paths/sources remain distinct. `manifest.json` and `manifest.sha256` are private. Bodies never live in the bank runtime marker.
- `agent-memory/layout-unit-map-v1`: operation/manifest binding; each stable unit UUID, original source IDs and exact byte ranges, context/page references, semantic kind, existing record identity/version if actually present, real origin or explicit unknown fields, and one disposition. Every source byte belongs to exactly one reviewed primary unit, including framing/whitespace/non-guidance; multiple destination references are permitted but coverage accounting cannot double-count or omit bytes. Byte offsets prove provenance, not a rule for splitting meaning. Choose units at meaningful record/heading/paragraph boundaries; retain surrounding framing and conditions.
- `agent-memory/layout-review-v1`: review_id (UUIDv4), operation/manifest/unit-map/intended-files/authority digests, reviewer actual developer/harness/session observation, detecting developer, review time, explicit per-unit decisions, full-result semantic preservation/security judgments and identity review where necessary. Independence requires a different reviewing agent/session from proposal author and retained actual review evidence; a self-authored `approved:true` or source heading is not proof. The project identity system does not authenticate a human; keep this limitation explicit. Operator approval is a separate retained decision, not inferred from this document.
- `agent-memory/layout-recovery-proposal-v1`: proposal_id (UUIDv4), operation_id, scope_context plus raw identity evidence, exact manifest/unit-map/review digests, original physical/source pins, exact intended native file bytes/hashes/modes and unchanged occupants, ordered path actions, required metadata plan, private pending ledger initial digest, security/governance evidence and complete read-only preview. No fresh admitted record is fabricated. `proposals/<proposal_id>.json`, `reviews/<review_id>.json`, `intended/<opaque-file-id>.bin` are immutable. Full encoded private proposal/ledger artifacts obey 512 MiB; no unbounded JSON. Original raw allowance remains 64 MiB, separate from encoded artifacts and result capacity.
- `agent-memory/layout-pending-ledger-v1`: operation/project, manifest/unit-map/proposal pins, generation, previous-generation digest, ordered units with stable UUID, original exact bytes/source/range/private hash references, original provenance or uncertainty, reason/actions, detecting-developer ID, state and terminal receipt linkage. Files `ledger/00000000.json`, then append-only immutable generations with an atomically updated private `ledger-head.json`. Unit states: `pending-admission`, `admitted`, `governed-terminal`, `reviewed-non-guidance-discard`. No time-based resolution. Active operation index binds current ledger-head digest, not caller-selected unit subsets.
- `agent-memory/layout-recovery-journal-v1`: exact proposal/manifest/review pins, source/result inventories and required metadata, expected marker/sentinel, ordered actions, base and final per-path identities/hashes, durable progress records and outcome receipt references. `journal.json` plus immutable `progress/<sequence>.json`. The journal references retained original bodies instead of depending on unvalidated ordinary `base_files` decoding.
- `agent-memory/layout-recovery-receipt-v1`: operation/proposal/request digests, original and intended manifest digests, outcome (`layout-restored` or `rolled-back`), readback time, verified byte/metadata checks, changed memory paths, eligibility-at-commit, pending unit IDs/count and semantic-completion-at-commit, and explicit Git/index/feature mutation flags. `receipt.json` is immutable. `semantic_recovery_complete_at_commit:false` never changes after later admissions; `status` computes current completion from later evidence.
- `agent-memory/layout-resolution-receipt-v1`: new resolution UUID, original operation/unit IDs and generation, actual admission/governance operation/receipt digest/result record IDs+versions, or exact independent discard authorization, current source proof, terminal state and ledger successor digest. Retry identity binds exact request bytes.
- `agent-memory/layout-retention-proposal-v1` and receipt: new cleanup UUID; parent operation/receipt/terminal ledger head and dependency pins; each exact private artifact deletion; required approval; retained tombstone and explicit rollback-loss acknowledgment. Tombstone contains safe IDs/states/times, cleanup outcome and retained receipt linkage, not raw-source hashes/bodies.

Schemas are private recovery metadata, not a new canonical bank schema. A normal record does not gain recovery-only fields or fabricated original provenance.

## All-source-to-result dispositions

Preparation must show every addition/replacement/move/removal, every unchanged occupant, complete original byte retention, source-to-result semantic mapping and every pending unit. Independent review covers full sources in bounded pages plus the whole intended result; a summary alone cannot approve an unread remainder.

Exactly one primary disposition per unit:

1. **Preserve/re-layout existing canonical knowledge.** Retain real stable record IDs/versions, trust/status, conditions, applicability, origin developer/harness/session, relationships, evidence and terminal tombstones. Concise contexts plus meaningful topic-index routes may carry already-present contextual knowledge without falsely turning it into newly admitted records. Do not move a transcript wholesale into `topics/` or arbitrarily slice files. Byte changes in framing must be explicitly mapped/reviewed. Previously admitted useful guidance must remain available with its qualifications, not become private pending merely to fit a bound.

### Pending classification, resolution and consumer policy

Comparison v2 adds private `pending_decisions`, each exactly `{unit_id, classification, rationale, coverage_claim}` to the separately keyed canonical decisions. `coverage_claim` is `{unit_id, covered_source_ranges, target_record_refs, coverage: full|partial|none}`; each target reference is `{id, version, path, resulting_sha256}`. Exact source ranges refer to the original unit-map and remain private. The proof binds the canonical request/candidate digest, full frontier token, all canonical and pending judgments, claims and independent coverage-review digest. `admission_evidence`, `governance_evidence`, or `consolidation_evidence` in the **actual transaction proposal** repeats the identical `unit_resolution_claims` and exact v2 proof digest; `validate_transaction` requires equality and validates target IDs/versions/paths/content against the transaction's intended complete output. A caller cannot supply an independent unit selection at receipt time. `resolve` consumes that actual committed proposal/proof/receipt and independently reviewed claims, not an inferred body similarity. All are private inputs, never inserted into shared records.

Each v2 **pending** decision carries **one** claim fragment; canonical decisions remain exactly `{path,classification,rationale}` and have no claim fragment. Each pending fragment has at most **two** distinct covered ranges and **two** distinct target references. A range is exactly `{source_id,start,end}`: `source_id` is canonical 36-byte UUIDv4, offsets are integers `0 ≤ start < end ≤ 1048576` (at most seven decimal digits), within that source and nonoverlapping in the claimed fragment. A reference is exactly `{id,version,path,resulting_sha256}`: `id` is canonical 36-byte UUIDv4, `version` is `1..2147483647` (at most ten decimal digits), `path` is at most 64 UTF-8 bytes and `resulting_sha256` is 64 lowercase hexadecimal ASCII bytes. A locator is either a safe canonical bank path or a private-map token. For a real existing path or version that cannot fit the inline bound, use a 40-byte-or-shorter `ref:<UUIDv4>` opaque locator and version `1` in the fragment, with an immutable private reference map binding that token to the **actual** complete path, record ID, actual version and resulting hash. The token is not a new canonical identity/version and cannot establish coverage without validating its private map and actual record. Include that reference-map digest in the bound v2 review and transaction evidence. This preserves existing long paths/large versions; no private locator is promoted to shared record evidence.

This is a per-fragment/transaction bound, **not a limit of two total ranges or two records per unit**: arbitrary finite many-to-many source/result relationships are accumulated as multiple reviewed partial fragments and multiple actual governed transactions/receipts. Each is proof-bound to the same stable original unit UUID, source manifest and then-current ledger generation. Preserve all prior immutable receipts and attestations; a final distinct independent review binds the complete union, verifies no gaps, overlap-as-double-counting, lost conditions or missing records, and may mark `full` only after the full union is durable. For a one-transaction unit, a full fragment can itself cover the unit with at most two ranges/two refs. If more are needed, stage partials first and use final independently reviewed union; partials never clear the unit or gain prospective capacity credit. Existing ordinary 65,536-byte proof bound and finite private-operation bounds still apply to each step; no fake terminal or silent omission for an oversized union.

Under lock, write/fsync cleanup intent and retained tombstone/receipts before first deletion; compare file type/owner/link count/bytes pins immediately before each individual removal, fsync parents, append durable progress. Resume the same cleanup by exact request/remaining-file checks; changed or unknown files stay untouched. Pending ledgers cannot be cleaned to resolve pending knowledge. Do not remove a live sentinel early; retire it only after terminal dependency checks and durable index state. An interrupted cleanup remains a truthful partial cleanup, not reusable rollback evidence. No age-based garbage collector is authorized.
