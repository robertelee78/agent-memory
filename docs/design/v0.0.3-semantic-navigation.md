# v0.0.3: semantic recall and pre-capture discovery (#98)

Status: draft technical supplement; not approved or implemented. Existing work
key: `robertelee78/agent-memory:ADR-0005:growing-bank-recall`.

## Product behavior

The system must find useful existing learning when a task or new observation uses
different wording. Discovery must support recall and comparison before storage,
and use the bank's progressive layout to bound presented context. A successful
literal query, a substring score, a synonym table, or several retries alone do
not demonstrate this behavior. The reader optimization remains separately useful.

A semantic resemblance is a relevance signal. It does not establish equivalence,
truth, authority, applicability or permission to merge lessons. Comparison must
read plausible source bodies, conditions, evidence and provenance before deciding
whether to reuse an identity, refine a record, retain distinct conditions or
surface a contradiction. Recall must keep currentness and applicability gates.

## Operator decisions and primary interaction

The operator answered that both the skill and standalone plain-language
`am search` must provide semantic discovery, and clarified that use within
OpenCode, Claude, Codex or another harness is primary. The current harness should
supply reasoning through shared deterministic discovery/read/compare operations;
ordinary in-harness use must not start a nested reasoning session for every read.
A terminal invocation must support a configured semantic interpreter over the
same discovery operations and source qualification, rather than return a literal
miss as though it completed semantic search.

The operator subsequently directed: “so let's focus on that use case”, referring
to in-harness use. Implement and qualify that primary workflow first. Preserve
the standalone semantic capability as a follow-on requirement; do not block the
primary fix on selecting a standalone provider or build a nested model runner
for normal harness operation. A new mandatory local model, subscription, vector
database or service is not part of this design.

## Common design direction to review

Use the existing bounded root, topic groups and leaf routes as a semantic map.
Purposes and read-when descriptions must describe the concepts in their actual
children, rather than repeat generic boilerplate. Grouping by insertion order or
opaque numeric buckets cannot be evidence of useful semantic organization.
Maintaining informative navigation must be part of capture/consolidation as the
bank grows; a hand-curated evaluation map alone does not prove daily operation.

Discovery must expose bounded navigation choices for interpretation by meaning,
then complete selected source records for final qualification. Exact IDs/paths
and ordinary full-text search remain useful additional tools. A lexical miss
must not prevent semantic navigation or count as absence. Plausible neighboring
topics and qualified relationships must remain discoverable when a concept cuts
across the primary topic. Arbitrarily selecting the first route or first result
is insufficient evidence for novelty.

Use current canonical Markdown as the authority. Any derived navigation or
ranking aid must be replaceable and tied to the current source versions. A
missing/stale aid must not suppress known corrections, deletions or disputes.
Retain existing source/identity/scope observation and write-time verification;
do not let a routing shortcut revive superseded guidance. Complete bank
validation I/O must be measured separately from bounded model context rather than
hidden behind a small output metric.

Comparison discovery must include relevant historical and differently conditioned
learning as review data. Recall-only filters cannot establish that an observation
is novel. Uncertain or incomplete coverage must remain visible to the invoking
agent, which must broaden or clarify before creating a potentially duplicate
memory. Do not claim mechanical proof of semantic completeness.

## Evaluation before acceptance

Keep the frozen literal scale corpus and its v0.0.1 results unchanged. Build a
separate, identified semantic-navigation corpus with informative routes derived
from its source learning independently of the held-out questions. Give the
invoking agent only the task/new observation, truthful context and ordinary bank
interfaces. Withhold relevant IDs/paths, expected classifications and oracle
query expansions.

Exercise at least these distinct outcomes across increasing bank sizes:

- Recall a differently worded relevant lesson without shared content words.
- Find an existing paraphrased lesson before proposing a new identity.
- Preserve separate learning whose similar prose has different conditions.
- Find both incompatible assertions and surface the dispute without choosing by
  landing order or recency.
- Retrieve the applicable correction and withhold obsolete guidance.
- Follow plausible neighboring topics for a cross-cutting concept.
- Distinguish a genuinely novel observation from an unavailable/incomplete bank.
- Preserve source labels, evidence and developer attribution throughout.

Record relevant memories found/missed, incorrect selections, duplicate proposals,
condition flattening, unresolved-conflict handling, actual navigation/source
reads, cumulative context bytes, named token counts when available, model usage,
latency and complete validation I/O. Preserve failed searches and attempts. Run
at 1,000/10,000/50,000 distinct lessons without loading all lesson bodies into
model context. Do not infer semantic recall quality from successful storage or
from faster whole-bank scanning. Agree any additional quantitative targets before
claiming a pass, and distinguish model variability from deterministic contracts.

## Concrete primary workflow proposed for technical review

Reuse the current harness and its ordinary bounded file tools. The portable
skill must teach one shared discovery procedure for recall, pre-capture comparison
and changed-learning sharing. No new model service or framework is needed for
that path.

1. Resolve this repository and actual task/context, check the existing boundary
   operation, then read its bounded MEMORY.md. Interpret route purposes and
   read-when descriptions by meaning. These are navigation data, not current
   guidance or permission. Do not turn the question into mandatory literal AND
   words as the primary discovery strategy.
2. Follow one or several plausible topic branches. Read only the bounded index
   files needed to compare their subjects; consider neighboring topics when the
   concept crosses boundaries. At a leaf, choose plausible source paths by their
   meanings. If captions are generic or inconsistent with inspected children,
   broaden the inspection or perform a separate source-preserving organization
   step; never call an opaque numeric map adequate semantic coverage.
3. Read selected complete sources through the existing exact-path/ID retrieval
   operation before using them as current guidance. The existing reader retains
   all source, replacement, lifecycle, visibility, security and applicability
   gates. Ordinary file-tool navigation alone is explicitly unmediated inspection
   and cannot be reported as verified current guidance. Exact source selection
   after semantic navigation does not require wording overlap.
4. Before capture, pass the discovered plausible paths to the existing comparison
   request's read_paths, together with broad supporting searches and provenance
   identities. Comparison considers inactive and differently conditioned learning
   as review data. Read every returned match, and classify equivalence, refinement,
   distinct conditions, contradiction or uncertainty before the existing governed
   admission/consolidation operation. Repeat against current landed sources before
   publishing. Searches supplement semantic navigation rather than replace it.
5. Keep the actual navigation/tool transcript for evaluation. A compact optional
   discovery trace may bind task, visited node hashes, selected paths and rationale
   to the existing request/proof. It must describe an agent assertion, not certify
   semantic completeness. A changed observed node must trigger renewed navigation;
   the existing complete-bank write-time source checks remain mandatory.

This workflow already fits existing Markdown and file tools; its current product
gaps are useful generated map content, mandatory skill guidance, source-bound
navigation handoff and actual blind end-to-end evidence. Do not implement a
standalone model runner before those gaps are repaired.

## Admission and map maintenance proposed for technical review

The admission writer currently appends generic learning and event rows to the
root. Replace that behavior for the supported semantic workflow with explicit
agent-reviewed navigation in the admission evidence. Keep the existing stable
record identity/path and preserve all bodies, conditions, history and provenance.

The optional navigation object has exactly learning, history and indexes. Learning
and history each specify an existing or newly declared parent index path plus a
meaningful purpose and read-when caption. Parent MEMORY.md is allowed when useful
and bounded. Indexes is a bounded list of new topic nodes, each with path, parent,
purpose, read-when and scope. Paths remain within the native topic-index format;
every new node must connect to an existing root/index through these declarations.
New index scope defaults to repository and must preserve actual inherited child
constraints. The writer derives child routes and each node's metadata itself; it
must not accept arbitrary replacement source bodies through navigation input.

The agent chooses durable concept/component/workflow groupings from the inspected
map and records. Distinct capture sources or sessions are not separate semantic
topics. Purpose and read-when must name useful concepts rather than repeat
“project learning”. History has separate provenance navigation. Root/index count,
encoded-byte and native two-level depth limits remain enforced. A saturated node
requires a governed meaningful split/reorganization before retry; no truncation
or raising the node cap. First use of a generic existing map requires the same
explicit source-preserving organization workflow, not a silent migration.

The object is part of the source-bound admission evidence, preview, locked apply
and replay so it cannot be substituted after comparison. Existing legacy request
formats may remain readable for compatibility, but the updated portable skill
must use meaningful navigation for new admissions. A reader/writer compatibility
claim does not prove old generic captions satisfy the new supported workflow.

The existing generic bank transaction operation can perform a bounded, reviewed
map-only organization. It must preserve exact payload bytes and identities while
changing routes/captions/index files. Because changed inherited scope or framing
can change meaning, preserve effective scopes and review any consequential
framing changes through the existing sharing protocol before publication.
