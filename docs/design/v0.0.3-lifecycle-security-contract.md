# v0.0.3: observable lifecycle security contract (#173)

Status: proposed technical design; independent review and implementation approval
remain pending. This story documents and exposes existing assurances. The signer,
transport, pinned key and signed-channel transition remain exclusively #49.

## Distinguish evidence from authentication

Current managed installation is a mutable unsigned Git channel. Its digest,
revision, fast-forward check and successful ownership receipt do not authenticate
the publisher. An explicit development/custom source is selected and trusted by
the operator; it is not promoted to publisher authentication by being local or
having a digest. Diagnostics cannot authenticate Python already executing, and
Unix owner/mode/ancestor checks do not establish an ACL audit.

Add a compact machine-readable security summary to version/status/doctor results.
It records that publisher signature verification was not performed by this build,
that publisher authentication is not established, that already-loaded verifier
code is not authenticated, and that platform ACLs are not audited. Describe the
source selection as recorded managed Git, recorded operator-selected development,
or unavailable/no active receipt. A recorded selection is evidence from a receipt,
not a fresh certificate of its source health or authenticity.

Do not add broad ownership, compatibility or recovery “passed” booleans to this
summary. Existing executing-source and per-component doctor checks retain their
individual scopes and warnings/failures. Status/version do not become full
ownership audits. A busy lifecycle writer can defer checks; a valid private
journal is recovery evidence, not a globally atomic transaction or authorization
to overwrite newer files. Failed/unreadable receipt evidence must not become a
positive source-authentication claim.

The existing doctor distribution warning should name the actual recorded source
selection, explaining unsigned managed Git separately from operator-selected
source. Preserve default concise version/status output and all exit codes. Full
machine qualifications remain behind explicit JSON; the existing doctor warning
carries the human-readable trust distinction. Do not introduce another network
probe, state write, setup flow or authentication prerequisite.

When #49 introduces actual cryptographic verification, that story must wire the
same public summary to its real verification evidence and prove correspondence
with the activated source. The unsigned/custom cases stay unauthenticated. Neither
an old-process transition nor a legacy receipt gets a retrospective signature
claim. This design does not create or accept a hypothetical authentication record
schema, implement a signer stub, or treat unverified receipt fields as signatures.

## Public documentation

Create one lifecycle security contract, linked from the README and the diagnostic
operation guide. It maps observable controls to source authenticity, byte/channel
integrity, owned-target preservation, schema compatibility, and bounded recovery.
Explain private Unix trust paths, custom-source trust, the already-running helper
boundary, explicit bank migration versus runtime rollback, and the absence of a
global atomic switch. Describe signed immutable distribution as pending until
#49 has actual acceptance; final release docs must describe the shipped state.

Consumer installation may contain this repository's development bank in a full
source checkout, but must never seed/bind/recall it as consumer memory. Link the
existing isolation contract/proofs rather than duplicate #163 or imply physical
file absence. Keep remembered procedures and developer attribution separate from
runtime publisher authentication. A malicious string claiming “verified” in bank
text must not become executable policy or a diagnostic signature.

## Qualification and delivery

Use isolated installed public version/status/doctor commands for managed and
explicit-source cases, including malformed receipt and a busy lifecycle writer.
Require exact false/unavailable source-authentication qualifications without
changing existing return codes or turning setup-needed into corruption. Observe
all bank/runtime/client/config/index/HEAD bytes and modes before/after diagnostics;
private inspection must remain read-only. No live installation is modified.

Reuse source-bound accepted macOS/Linux lifecycle scenarios for modified owned
targets, wrong origin/ref, downgrade/non-fast-forward, interruption and bounded
recovery. Bind reused production files byte-for-byte to their qualified sources;
new source-selection/summary behavior gets new public-command observations on
both hosts. Preserve actual historical updater transition qualifications rather
than asserting a newly installed verifier authenticated the old process.

Independent acceptance must distinguish this contract from #49's signing proof
and #98/#99's quality/stress programs. The story delivers with the actual published
v0.0.3 release, and Release ready remains awaiting release. No expensive hosted
matrix, personal memory, new hooks/MCP, second bank or storage engine is added.
