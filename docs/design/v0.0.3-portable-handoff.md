# v0.0.3: portable scoped handoff (#169)

Product authority: ADR-0014's accepted portable-scoped-handoff outcome.
Independent technical approval is required before implementation.

## Selection versus inspection

Current checkpoint conditions are preserved in Markdown but ordinary retrieval
only gates inherited route scope. Add one bounded checkpoint assessment shared
by retrieval and explicit inspection. Parse the existing managed checkpoint
section grammar and its JSON conditions, preserving unknown conditions. Reuse
the existing scope/condition evaluator with the actual observed Git branch/HEAD
and truthful supplied task/component/environment. Do not infer another session's
task or adopt its next step as an assignment.

Ordinary recall excludes a managed checkpoint whose required conditions are
unknown or mismatched, before ranking or context budgets. Exact current lookup
does not bypass that gate. Matching checkpoints remain qualified orientation,
not typed admitted guidance; add explicit `assignment: false` and retain the
actual conditions, provenance and evidence assessment. Assembly consumes the
same gated rows, so its normal or disputed-source path cannot reintroduce an
inapplicable checkpoint. A conflict missing one qualified side still refuses.

Malformed, duplicated or missing condition framing on a managed checkpoint must
remain unqualified, not become `{}`. Legacy manually written orientation that
has no managed checkpoint fields remains ordinary orientation with explicit
unassessed statement applicability; it does not become an admitted handoff.
This work does not parse arbitrary prose into facts or universally certify all
statement-level conditions in ordinary context. #168 separately preserves
implementation observation provenance and semantic conditions.

Add explicit bounded ordinary-context inspection to the existing `am inspect`
surface, using `--path activeContext.md` (ordinary context paths only). It reads
the actual same-project canonical file with source hash, condition assessment,
evidence/provenance and clear `historical-orientation`, `assignment: false`,
`usable_as_current_guidance: false` labels. This is the deliberate way to inspect
an unrelated or historical handoff, rather than weakening current `get`/search.
The existing structural `am inspect` output stays compatible. Explicit content
inspection requires the common same-project resolver and security checks; it
cannot bypass terminal typed-record invalidation, unsafe-content withholding,
pending bank markers or incomplete source snapshots. Typed records are outside
this ordinary-file inspection selector.

## Evidence availability across clones

Preserve source reference strings and their original provenance. Extend new
checkpoints with a bounded managed evidence-observation section: identify each
declared reference and whether the observed bytes are repository-published,
local/unpublished, external-unverified or unavailable. Local byte observations
include a SHA256; an observed HEAD alone is not proof those bytes are committed
or published. No link is fetched and no referenced command is executed.

Repository-relative references may be checked against bounded current bytes and
Git blobs. A matching committed blob establishes a source revision, not remote
publication without independent publication evidence. Absolute/outside-repo,
untracked or changed working-tree evidence remains local/unpublished; never
claim another clone has it. External URLs remain unverified unless separately
reviewed. Do not read arbitrary large files or follow symlinks while assessing
availability. Missing evidence qualifies the handoff, rather than erasing its
useful question or treating unavailable material as a proven result.

The reader compares recorded references/hashes with local observations and
retains unavailable/changed qualifications. Old checkpoints without the new
section have unknown evidence transport, not fabricated provenance. An old
writer may preserve that section as unrelated prose while changing the evidence
list; mismatched references must therefore be detected and qualified instead of
trusting a stale observation section. Duplicate/ambiguous framing fails closed.

The checkpoint renderer/revalidator share the intended evidence observation and
retain the current observed-write/source guards. It must not silently recompute
new source interpretations during replay. Existing conditions, attribution and
unrelated sections survive. No personal namespace, machine identity registry,
automatic messaging, cross-repository transfer, bank schema or new service is
introduced. Runtime downgrade readability remains separate from new semantics.

## Acceptance

1. Through installed public operations create a task/branch-qualified checkpoint
   in one clone/worktree and publish/refresh it through the existing memory-only
   path. Another clone on a different task/branch excludes it from ordinary
   recall and context assembly, while explicit file inspection retains the
   historical text, conditions, source hash and no-assignment qualification.
2. The matching task retains bounded useful handoff content with developer and
   session provenance; unknown required conditions never qualify by default.
   Exact current path lookup follows the same gates. No next step is assigned.
3. Include committed repository evidence, changed/untracked local evidence,
   unavailable machine-local artifacts and an external reference. The second
   clone does not claim access or publication merely from link presence or HEAD;
   inspection explains missing/changed/unverified evidence without deleting it.
4. Preserve legacy/manual context, malformed condition/evidence sections,
   duplicate headings, stale evidence lists and ordinary checkpoint/router
   invariants. Unsafe content and pending writes remain refused/withheld.
5. Run the focused installed/checkpoint/retrieval/assembly/inspection scenarios
   locally on macOS/Linux, bind exact candidate/artifact hashes, and retain
   independent review. Reuse unchanged sharing proofs with their real source
   qualifications; no broad hosted matrix or general semantic-currentness claim.
