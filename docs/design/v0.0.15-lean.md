# v0.0.15 lean `am`

Operator decisions, 2026-11-15. This replaces every requirement agents added after the approved v0.0.1 design: `docs/mission.md` and ADR-0001–0012 as approved on 2026-10-22. Where the two differ, the operator's 2026-11-15 answers win.

## Product

A fresh coding agent entering a project quickly knows:
- what the project is and why;
- how it is built;
- the lessons: fixes, dead ends, your corrections, your decisions.

Memory is plain Markdown in the repo's `memory-bank/`, shared through git. Memory never makes the user wait.

## Memory bank (unchanged format)

- `memory-bank/MEMORY.md` is the route map.
- Six context files: `projectbrief.md`, `productContext.md`, `activeContext.md`, `systemPatterns.md`, `techContext.md` and `progress.md`.
- Lessons are notes under `topics/`, linked from `MEMORY.md`, each with the existing record frontmatter (id, kind, status, source, evidence, conditions). Existing banks keep working as they are.

## Commands

| Command | Behaviour |
|---|---|
| `am install` / `update` / `uninstall` | Signed release, owned files only, plus takeover of a v0.0.14 install. Kept from the current code. |
| `am status`, `am doctor` | Installed? Hooks present? Bank healthy? Problems explained in plain words; doctor never rewrites memory. |
| `am init` | Create the bank from the template. |
| `am recall [QUERY]` | Print the project summary plus the matching notes. |
| `am remember` | Write an approved note (from stdin JSON or flags), skipping duplicates, and link it in `MEMORY.md`. |
| `am share` | Commit only `memory-bank/` changes; push to a memory branch or PR via the existing repo rules. |
| `am refresh` | Bring others' memory changes into the working tree without touching code. |

## Hooks

- **Session start** (Claude, Codex, omp): inject the project summary and how to use `am recall`/`am remember`. Fast; no git beyond finding the root.
- **Milestones:** the skill tells the agent to suggest a memory when a fix is confirmed, a decision is made or a task is done, and to ask the user to approve it. Nothing runs at the end of each turn; there are no seals, nonces, clock windows, proofs or waiting.

## Git use

- Once per command: repo root, remote URL (project id), `user.email`, and bank path (config or `memory-bank/`).
- `remember`/`share`: write the note atomically under one lock on the bank, then check `MEMORY.md` hasn't changed since it was read before replacing it.
- No other repository re-verification.

## Cut

- omp/Claude/Codex per-turn seals, sources, streams, nonces, clock windows and wake diagnostics;
- layout recovery, frontier, holds and recovery queues;
- authority proofs, source fingerprints and review receipts;
- repeated identity/config/bank re-checks;
- every unit/contract test and the obligation ledger.

## Quality

- No unit tests.
- A real-use QA script drives the actual `am` the way a user would, on macOS arm64, Linux arm64 and Linux x86_64, and records results and timings: install, init, recall, remember, share between two clones, refresh, update, uninstall, and v0.0.14 takeover.
- Targets:
  - every command under 200 ms on a normal repo, excluding network;
  - the session-start hook under 100 ms.
- Then a few real omp sessions on the cheapest model.
