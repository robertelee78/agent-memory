# v0.0.3: actionable setup diagnostics (#170)

Product authority: ADR-0014's accepted actionable-first-use-diagnostics outcome.
This design requires independent technical approval before implementation.

## Classification and evidence

Keep `status` shallow and read-only. Add a bounded setup assessment alongside
the existing bank/runtime observations; do not convert a locator observation
into full bank validity or an exhaustive proof of absence.

| Observed evidence | Setup assessment | Appropriate next step |
| --- | --- | --- |
| No current router or tracked router evidence | `setup_needed` | Inspect project evidence and existing locations; use `am doctor` before initialization |
| A current valid router but no checkout binding | `binding_required` | Inspect `am identity status`; review evidence before explicit link/bind/fork |
| A current router and a different recorded checkout project | `binding_mismatch` | Preserve both identities and reconcile through the identity operation |
| No current router, but a bounded valid router blob exists in the current Git index or HEAD | `missing_known_bank` | Inspect Git state and restore/reconcile the known bank; do not initialize a replacement |
| Current router, matching local binding | `bound_not_audited` | Use doctor for full authority/content checks; do not imply setup is certified |
| Malformed/unreadable competing locator or registry | `inspection_required` | Preserve evidence and inspect the failed component |

An explicit bank-root setting or a project binding alone does not establish
that a bank ever existed. A pre-created identity is a supported first-use state.
An indexed or committed recognized router is positive historical evidence, not
proof that the user accidentally deleted it: staged deletion and an intentional
purge still need explicit interpretation. Pending purge remains its own recovery
state, with no advice to initialize or resume deletion without its original
authorization.

Use the repository locator's existing bounded Git-object reader and router
recognition for historical evidence. Include indexed and HEAD paths, retaining
custom bank roots and linked worktrees. Do not infer history from an old local
registry entry, network fetch, filesystem timestamp or another repository. A
malformed or unavailable candidate cannot establish absence. Status still does
not read every routed context file or scan the entire physical repository.

Doctor uses the established complete bank locator and validates canonical
contents, preserving its existing runtime/bank component reports and refusal
behavior. When complete discovery establishes no bank and no positive tracked
history, report `not_initialized` with an initialization action. If a tracked
router exists but is missing locally, retain `missing_known_bank`. Only a
validated bank plus verified current project authority permits `ready`; malformed
runtime state must continue to appear as an independent failure even if the bank
is healthy. A missing bank is not itself runtime corruption.

## Public behavior

Expose an additive `setup` object with `state`, bounded evidence labels,
`absence_verified` and a concrete `next_step`. Human status/doctor prints that
next step without dumping records. Identity warnings must distinguish missing
binding from conflicting binding and avoid asking an untouched repository to
reconcile a mismatch that does not exist. No diagnostic creates, binds or repairs
identity, makes a network request, writes bytecode, removes markers, acquires a
write lock or performs a filesystem write probe.

Existing bank states retain their meanings; setup assessment does not certify
publisher trust, memory currentness, useful learning or task assignment. No
schema migration or automatic first-use bank creation is introduced.

## Acceptance

Exercise installed public human and JSON status/doctor on native macOS/Linux:

1. New repository with no bank/identity, then a pre-created project identity but
   no bank: actionable setup guidance, no fabricated mismatch/corruption and
   byte-identical repository/config/runtime snapshots.
2. Existing useful bank without a binding, matching binding, and actual distinct
   binding: distinct assessments and identity-specific next steps. Doctor alone
   verifies complete authority; no implicit binding occurs.
3. An indexed or committed bank removed from disk, including a custom location
   and separate worktree: known-missing guidance preserves Git/index/HEAD and
   refuses to imply that a replacement bank is safe. Include a staged deletion.
4. Malformed/unreadable locator, damaged receipt and a healthy bank beside
   damaged runtime: independent actionable components and preserved source bytes.
   Reuse existing runtime diagnostic regressions where the contract is unchanged.
5. Untracked/ignored possible existing bank remains subject to full doctor
   discovery; shallow status does not claim exhaustive absence. Preserve the
   existing pending-purge and busy-bank behavior with no mutation.

Bind final focused results and portable file hashes to the exact candidate. A
test receipt verifies the stated observations, not general production health.
