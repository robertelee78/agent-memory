# v0.0.4 update compatibility performance

The v0.0.2 to v0.0.3 update took 6 minutes 25 seconds on the operator's Mac.
A read-only profile of one compatibility pass on 2026-10-27 inspected 598
available worktrees and 144 banks, reported 70 discovery gaps, and spent 49.36
seconds across 4,832 subprocess calls. The updater performs multiple passes to
observe before and after activation. The slow path is real; the profile does not
attribute the entire elapsed update to this one function.

A v0.0.4 fix must reduce elapsed compatibility-scan time across independent
worktrees and repeated observations, while preserving discovery,
bank-schema checks, gap reporting, fresh observations around activation, and
safe rollback. Use bounded parallel reads without caching Git objects or
worktree contents, indexes, local configuration, branch state or the result of
an idle check across activation boundaries. Unknown or unavailable
worktrees must remain reported, not silently dropped. The updater must remain
safe on source changes and concurrent writes.

Acceptance uses a local representative many-worktree fixture and the operator's
real inventory as an optional read-only observation, plus controls for changed
HEAD, index, local configuration, banks and transient locks. Compare repository,
bank, schema and discovery-gap output against the existing implementation; no
bank may be silently skipped. Record timings and subprocess counts. Each test
must reasonably finish within 10–15 minutes. A release artifact must retain
signed source verification and existing rollback and installation behavior.
