# v0.0.4 current-memory observation prototype

Issue: #19. This is a proposed read-only optimization, not evidence of automatic capture or a change to semantic admission.

## Scope and evidence

The OpenCode trial spent approximately 132 seconds and 18 tool calls at turn-start refresh, even when its fixture had no incoming memory delta. Introduce a separate `am refresh current --repo REPO` observation, rather than modifying the existing inspection/review/prepare/apply APIs. It may report `bank-synchronized` only at a point-in-time when it proves the observed canonical bank matches the freshly read authority and no currently observed memory import is needed. It MUST report pending capture and publication as unknown, because private proposals are not centrally registered. It must not claim semantic truth, appropriate recall, publication, feature-code freshness or a completed capture.

## Conservative checks

- Use normal non-quarantine boundary and fresh authority observation, complete bounded bank validation, `recovery.tree`'s ordinary Git blob/mode checks, and the existing identity/config guards. Fail closed for missing/invalid bank, unavailable/advancing authority, unknown base, nonordinary trees, ignored/untracked/excluded memory, lock/marker or unsafe/unadmitted content.
- Compare complete base, local, landed and current feature-HEAD memory path/bytes, not only semantic component or hash summaries; require all four equal. Validate every index entry has exactly the HEAD blob and ordinary mode/stage, and the complete index bytes are unchanged; do not stage or repair anything. Require every physical bank file's mode to match the agreed ordinary representation.
- Independently examine every validated record for hidden/quarantined/candidate state; the empty changed frontier alone does not disclose unchanged hidden records. Use the complete known-hold store reader, refusing any retained hold, legacy/invalid recovery state, active lock or journal, and re-read/recompare it before success.
- Pin developer/project/authority configuration, HEAD and branch, complete index bytes, cursor state and source data; verify them after observation. Verify authority head again via the server, and repeat source/index/mode/hold/pending checks before returning. A concurrent change means `review-required` or an explicit recoverable pending diagnostic; never return bank-synchronized from an incomplete check.
- Inventory and fail closed on runtime-owned unresolved transaction journals, malformed known-hold registry entries, locks, markers and unknown recovery state. Private capture and publication proposals can exist outside the runtime inventory; report their status as unknown rather than asserting there is no pending work. The result is never a completed turn or a completed publication receipt.
- Git observation may use existing bounded disposable refs/object fetch and clean them; describe these as Git metadata writes. The operation MUST NOT mutate canonical memory, the feature index/HEAD, cursor, authority or known-hold state.

## Verification

Use isolated public CLI fixtures and independent review. Prove exact equal banks; changed local bytes, mode, staged file/deletion, untracked memory, nonordinary/changed HEAD; hidden/candidate/quarantined/unsafe records; held/corrupt/legacy state and transaction markers/journals; offline or advancing authority; changes to source/index/HEAD/config/hold/authority between first and final observations; missing/damaged cursor and common-base handling. Check negative cases preserve all prior state and never report `bank-synchronized`. Verify no truth, recall, publication or feature-code freshness claims. Every test stays within the user's 10–15 minute per-test budget.
