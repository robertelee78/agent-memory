## Proposed implementation

Keep the existing exact path, exact ID and ordinary-text selector semantics and
all hard qualification gates. Reduce redundant filesystem traversal, parsing and
source reads within one public operation before considering a persistent index.
No required vector store, mutable shared database, daemon, background rebuild,
new memory schema or cross-repository data path is introduced.

A complete operation-local observation records actual canonical path/hash maps,
validated router/index/record structure, raw file bytes and parsed typed records.
It belongs only to that invocation and actual repository/bank/settings/lock owner.
It cannot be supplied by a caller as authority, reused across invocations or
substituted for a final source check. A source is parsed once from the exact bytes
whose hash is bound to the observation; the validator and recall selector consume
that same observation. All complete-bank and per-source resource budgets remain
explicit and distinct from returned context limits.

Reuse the pure `validate_files`/layout/record validators. An optional internal
parsed-record output may carry the already validated metadata/body to the recall
selector. Do not weaken duplicate version, route topology, inherited conditions,
tombstones, marker/lock, symlink/alias, trust, lifecycle or invalidation checks.
The ordinary public validator response must not dump an extra complete body cache.
Unknown formats, unsafe/oversized typed invalidation sources and incomplete reads
remain unavailable, never successful empty selections.

Read a complete canonical inventory with before/after exact content hashes, stable
path topology and original lock/transaction markers. Hash large bytes in bounded
chunks; do not allocate unbounded individual files merely to hash them. Recheck
the complete canonical hashes/topology and lock/transaction markers at final
readback, together with actual Git branch/HEAD, developer/project/settings/scope
observations. If any source changes, refuse and reread. A final hash-only recheck
may replace a second full parse only because the earlier exact validated bytes
remain bound and all current bytes/topology/markers are re-observed. It does not
provide an atomic filesystem snapshot or continuing authorization.

Current qualified replacement relations must still be discovered across all
applicable active records before query, visibility, kind, safety or result budgets
can select older guidance. A hidden/unsafe replacement must not reactivate its
old version. Inactive and unknown metadata cannot vanish because an accelerator
finds no query hit. Context orientation remains separately labeled with no typed
trust, and working/staged code is never certified by a HEAD observation.

Keep private content-free audits and exact source labels, conditions, evidence
and provenance. No cache miss, corrupt local state, lost projection, empty exact
selector or performance budget may bypass source validation. Existing caller-owned
write locks and deferred conflict sets remain supported. The shared operation-local
reader can serve sharing/recovery after its exact integration is independently
qualified; #99 retains its own full-path workload obligations.

## Evaluation and claims

Before optimizing, retain the exact reviewed 24-query labels and actual baseline
curves at 1,000/10,000/50,000 distinct lessons. Both baseline and comparison use
separate disposable identities and their own installed public helpers. The
preserved output includes raw commands/failures, source/fixture/label identities,
actual selected source ID/version/body/hash, excluded reasons, safety failures,
canonical bytes and body-length distribution. Relevance hits summed across
queries are not a count of distinct lessons learned.

Publish isolated sequential reader observations separately from contended quality
requests. No cold-cache, provider token/cost, complete disk-I/O or statistical
speedup claim is supported by the present apparatus. Selected encoded payload
bytes and whole JSON response bytes are available; assembled harness context and
tokens remain unavailable without actually measuring them with a named tokenizer.

Preserve zero allowance for unsafe, stale, or incorrectly applicable guidance.
Do not invent numeric recall/latency/context tolerances after seeing a candidate.
Use the complete baseline to present proposed acceptance targets for operator
review, including the known no-overlap lexical miss. Implementation may proceed
from an independently approved technical design, but neither #98 nor #99 can
claim a quantitative pass until the operator's target decision is recorded.

Exercise changes during initial read and final recheck; marker/lock/symlink and
configured-root changes; invalidated/hidden/unsafe replacement metadata; same-ID
corrected versions; expiry; conditional/unknown applicability; source corruption;
read-only source/bank/index/HEAD preservation; and exact body/version/hash results.
Run meaningful existing reader/assembly/governance/sharing contracts locally on
both supported platforms after integration. Do not rerun the entire lifecycle
matrix for every isolated reader edit; broaden tests when actual dependencies or
failures justify it.

A fixed-query quality plateau with lower measured cost is distinct from improved
paraphrase understanding. The companion skill may teach ordinary question-to-concept
query reformulation, but any claimed workflow gain must be measured separately
using an actual agent supplied only the task/question and available bank/tools,
without expected record labels, fixture-specific expansions or oracle answers.
Keep a raw literal curve alongside any such agent-assisted result. A synthetic
scripted synonym map is not an independent agent measurement.
