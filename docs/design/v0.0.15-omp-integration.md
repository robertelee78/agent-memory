# #249 — concrete omp integration execution design

Status: proposed for independent technical review and operator approval. No implementation authority is implied. Work key `robertelee78/agent-memory:ADR-0004:omp-first-class-integration`; delivery signed v0.0.15. Supersedes the provisional source-capture assumptions in initial research comment https://github.com/robertelee78/agent-memory/issues/249#issuecomment-6621353203. Operator-approved completion policy: https://github.com/robertelee78/agent-memory/issues/249#issuecomment-6621596937.

## Why / outcome

Make omp a first-class native peer of Codex/Claude using the same skill, memory files, admission/retrieval/Git semantics and verified writes. Automatic invocation must survive a model forgetting the skill without taking over the substantive task, losing original sources, or bypassing permissions. A failed/refused/cancelled memory operation leaves source-bound pending work and allows the task to finish.

## Evidence pins and limits

Agent-memory baseline `33c95bbebef61e3ac6e58c5c59e0d411b6dc63e8`; upstream omp v18.16.0 `650f3a108229ee11bf68ba3377f4e8c3391cd424`; actual installed macOS arm64 binary SHA-256 `d4a10d97488d6054d2b18198bd24f461079952c7e0fb75ba66336ca0df0cb99e`. Source/binary equivalence is not established by matching version strings.

Actual binary + real openai-codex/gpt-6.1-sol provider exercised eight disposable RPC scenarios: approved tool, headless approval refusal, explicit approval rejection, in-flight tool cancellation, new human steering during continuation, injected unavailable-authority tool error, message-persistence ordering, and advisory continuation cap. All exited 0 and reached settled state; the original task answer appeared exactly once; continuations were hidden custom messages attributed to agent, never user. The permission-refused/rejected tools never entered execute and wrote no sentinel. Cancellation reached the executing tool's AbortSignal and prevented its sentinel. Steering was retained as a separate native user entry and acknowledged once. Native advisory cap produced exactly eight continuations, not completion proof. The injected error is failure-path feasibility, NOT a real Git/network outage test.

Separate model-free native scratch probes exercised new_session, switch/resume across process restart, both forks and shallow snapshot mutability. Fork retains entry IDs but changes session ID; parentSession differs in shape (ID vs path) across fork variants. Snapshots expose mutable nested values. These synthetic identity fixtures do not establish real-human provenance or memory functionality.

Important observed constraint: message_end handlers run before that message is appended to SessionManager. RPC msg-N IDs are not durable session entry IDs. session_stop snapshots contain terminal messages, but cancellation can skip session_stop. A terminal-only observer or assigning the current leaf to the just-ended message is incorrect.

Raw evidence roots: `/tmp/agent-memory-omp-native` and `/tmp/agent-memory-omp-identity`. No agent-memory integration, real memory-bank mutation, Linux, TUI, actual offline authority, Git publication/recovery, or full source coverage is qualified by these fixtures. Existing user authentication was used through the normal installed client for real-provider probes; no credentials were copied into evidence. Ambient extension/skill/rule/context discovery was disabled; session directories and cwd were disposable. Unlike the earlier startup probe, real-provider probes used the existing authentication/config root, so they are not fully config-root-isolated; explicit CLI approval mode and disabled ambient loading bounded this surface, and no settings were changed by the driver.

## Component and permission boundary

Proposed files (not existing exports): `hooks/omp.ts`, `scripts/omp_boundary.py`, `scripts/agent_memory/omp_boundary.py`; update existing installation/console/diagnostics/artifact/skill routes and user documentation as required. Reuse `turn_sources.py`, `boundary_assessment.py` and ordinary shared workflows. Do not extend legacy OpenCode boundary_ledger as an omp memory engine.

The executable extension may only observe native sources, persist private pending-source metadata via the trusted fixed helper, request one advisory continuation and relay bounded status. This is executable installation authority, not passive skill content and not a tool-approval grant. It must never execute canonical admission, consolidation, refresh, publish, arbitrary commands or model-selected subprocesses from callbacks. Those operations remain ordinary approved model tool calls using shared skill/CLI. Do not change approval mode, active tools, permissions, model, provider or user's configuration to make memory succeed. No MCP or separate harness memory semantics.

Private enrollment is a deliberate narrow exception to 'no callback writes': retaining original source evidence and pending metadata is the purpose of the installed observer, does not mutate canonical memory or Git, and is separately previewed/authorized by installing the executable integration. Use a fixed absolute receipt-owned Python helper/executable and structured stdin, no shell, no interpolated source/command arguments. Helper validates trust paths/project identity and action-specific exact schemas before private writes. Callback helper invocations have a five-second deadline; cancellation/failure records an actionable observation gap if possible and never claims durable enrollment. Original native transcripts remain recovery sources; missing/deleted/unreadable transcripts or an unpersisted interrupted message are explicit coverage gaps, not guaranteed recovered learning.

## Source capture and durable identity

Add `omp` to shared `turn_sources.HARNESSES`; preserve v2 reference/receipt shape, existing bounds and all peer behavior. Each source uses the existing opaque observation UUID + digest as primary durable identity. Native session ID is mandatory; use the actual runtime value, not parentSession. Scope is actual bound repo/project/checkout + harness + session + lifecycle; lifecycle is an opaque UUID for one original human request, persisted in private metadata, not the resetting native turn_id.

At message_end synchronously copy/serialize only source-relevant native event values before any await. Source envelope `agent-memory/omp-native-source-v1` contains native session, capture UUID, lifecycle UUID, event ordinal, previous durable leaf/cursor, role/attribution, exact content blocks including tool inputs/results, toolCallId/toolName/isError/details where present, timestamps as descriptive data, and immutable references/hashes for external payloads. Preserve additional raw native metadata in the private snapshot; exclude credentials and unrelated credential_pin/config entries. Hash canonical UTF-8 JSON with shared sorted compact encoding. No text matching, timestamp, RPC messageId or most-recent-user heuristic may establish identity.

Persist the snapshot under a dedicated private content-addressed `omp-source-snapshots-v1` subtree adjacent to shared turn-sources-v2, with 0700 directories, 0600 ordinary single-link files, no-follow trust-path validation, exclusive create, fsync/readback and immutable digest verification. This is evidence storage, not a second pending/completion ledger. Use the shared turn_sources registration/index/completion ledger; source_reference names only a verified private snapshot reference. Write snapshot before registering its reference; on registration failure preserve snapshot and record an observation gap. Source payloads over 16 MiB or exceeding existing source/turn capacities remain explicitly unassessed/coverage-incomplete, with native transcript reference and a bounded repair action; never truncate and mark assessed. Snapshot cleanup is not tied to runtime uninstall: retain pending snapshots, and do not automatically purge source evidence in v0.0.15. State this retention/privacy limit publicly; no new purge feature is introduced.

Because durable native entry IDs arrive later, initial `native_source_id` may be null (already allowed by turn_sources). Keep the original observation immutable. On the next native event, session_stop, or resume, reconcile the captured FIFO against entries after the recorded preceding cursor on the same session branch. Append a separate verified mapping observation-ID -> native entry-ID/parent-ID/project/session and native snapshot digest. Compare the ordered semantic projection (role, attribution, complete content, timestamp, tool identifiers/result fields), retaining both raw snapshots; assistant persistence adds contextSnapshot/errorId fields, so full raw equality is not required or claimed. Repeated identical text cannot resolve identity without ordered cursor/parent continuity. Ambiguity, branch movement, missing cursor, mismatched content or unavailable artifacts stays pending and ineligible for completion. Reconciliation must not mutate live session entry objects or rewrite native transcripts. Do not substitute synthetic native IDs. Pin the exact semantic projection schema in implementation and review it against actual fixtures before accepting source coverage.

Map assistant tool-call IDs to the request/control lifecycle at invocation; tool results retain that mapping even if new human steering arrives meanwhile. Genuine new user input gets its own lifecycle. Agent-attributed session-stop-continuation and its exclusively memory-maintenance descendants are control evidence, not new human learning; never suppress actual user entries arriving during the control interval. Persist maps/cursors privately with identity/hash checks and atomic write/readback. On first installation attach to new admissions and the current open request only, not indiscriminately replay every historical/fork-inherited message. Resume uses the same source namespace and deduplicates registered sources; fork uses the new session identity and captures only new admissions, while preserving parent's existing pending records. Parent lineage is informational, not a typed ID or authority.

## Public helper contract (new, proposed)

Follow existing boundary CLI conventions, exposed as `am omp-boundary --repo PATH`:

- `--observe --stdin`: validated native source/event snapshot, provisional native mapping, or stable reconciliation action. Private metadata only. Returns exact observation/reference/digest, enrollment verified or explicit coverage gap; no completion flag or canonical mutation capability.
- `--list-pending --offset N`: existing bounded shared omp backlog with source references, unknown/incomplete rows and next cursor. No implicit assessment, refresh or publication. Do not call this global completeness proof.
- `--source OBSERVATION --session ID --lifecycle ID`: read the exact trusted snapshot and mapping, verify digest/project/session and show complete source/reference coverage. Machine output must identify unresolved/oversized/unavailable sources; it is not no-learning.
- `--stdin` acknowledgement: exact fields session, lifecycle, observation_id, source_sha256, outcome, assessment, optional publication_request. Require matching retained source and verified native mapping, then existing turn_sources.verify_assessment and complete; reject extra/foreign/mismatched input. No-learning uses existing bounded assessment schema; published uses existing request/proof/replay witness. Retain assessment_is_agent_assertion:true and source_publication_link_verified:false. Do not claim deterministic semantic proof or source-caused publication. The model's source-bound assessment carries the semantic judgment; native qualification must demonstrate correct original-source use and peer readback.
- `--quiet --refresh` combined acknowledgement follows existing quiet boundary convention, but refresh outcome remains separate from source assessment/completion. A refresh failure cannot become a green workflow; no-learning and witnessed publication remain distinct. Every mutation-capable invocation still uses the normal approved tool path.

Invalid action combinations and missing exact source identities refuse before private/canonical changes. Keep stdin payloads out of argv/logs. No new always-running service, retry daemon, public automatic permission grant, or separate recovery engine. Later recovery is an explicit ordinary approved invocation against the retained original observation, or a later eligible boundary under the policy below.

### Exact action/schema invariants

All JSON uses unique object keys and strict UTF-8; unknown envelope keys refuse. UUIDs are canonical UUID strings, IDs/references retain shared bounded-string checks, ordinal is a nonnegative integer (not boolean), hashes are lowercase SHA-256. Source content is JSON data only, never executable input. A per-factory serialized event queue preserves admission order; do not launch concurrent unawaited capture helpers.

`--observe` accepts exactly `{schema,action,session,lifecycle,payload}`, with schema `agent-memory/omp-observer-request-v1` and action one of `capture`, `reconcile`, `wake`. For `capture`, payload is exactly `{capture_id,ordinal,previous_leaf,message,native_reference}`: previous_leaf is null or actual durable entry ID; message is the full source-relevant native message snapshot; native_reference is null or a checked session-file/artifact reference, never read as a command. Role must be user/assistant/toolResult/custom and the corresponding native shape must validate; control custom messages cannot be admitted as original human work. Session and lifecycle are checked against the trusted private cursor registry. Store capture_id before source registration; recovery detects the exact existing capture record and returns its observation rather than registering a fresh duplicate. The cursor registry is transport metadata only and cannot acknowledge a source. Resume reconciliation runs before accepting new observation sequences.

For `reconcile`, payload is exactly `{previous_leaf,leaf,entries}`; entries are ordered native branch records containing id, parentId, type and the message/custom-message data appropriate to that type. Nonmessage chain nodes carry only identity/type, never credential payload. Chain continuity, current session, private captured ordinal order, and source projection equality must all hold; persist per-observation native mapping with readback, not mutation of the original ledger source. The equality projection is exactly the keys present from `[role,attribution,content,timestamp,toolCallId,toolName,isError,details]`; absent and null remain distinct. Keep complete raw source-message snapshots separately for hashes/provenance. This projection matched every user/assistant/toolResult pair in the native capture-order probe; no claim is made for untested message classes.

For `wake`, payload is exactly `{observation_ids,fingerprint}`: sorted unique observation UUIDs, each retained/pending/native-linked and in the exact repo/session/lifecycle; helper recomputes fingerprint from that inventory and validates the native-generated continuation digest through shared reserve_wake. Return only a request reservation and fixed guidance/reference strings, never a completed-source result. Caller cannot supply arbitrary continuation text or mutate canonical memory through this action. Helper stdout distinguishes enrollment_verified, native_mapping_verified, wake_reserved, coverage_incomplete and canonical_writes_performed:false; none is interchangeable with assessment/publication verification.

Acknowledgement envelope has exactly `{session,lifecycle,observation_id,source_sha256,outcome,assessment}` plus publication_request only for published outcome, with no schema alias or caller-provided verified flags. Every acknowledged source requires retained complete snapshot, verified native mapping and exactly matching shared ledger observation. Response is the existing verified shared receipt plus a separate refresh result when requested. Never overwrite the existing mandatory false source_publication_link_verified qualification. CLI input is at most 16 MiB; larger original sources remain explicit coverage gaps and require inspection rather than weakening that validation.

## Continuation and pending-state transitions

`captured-provisional -> enrolled-pending -> native-linked -> advisory-requested -> assessing -> verified-complete`; refusal/error/cancellation/coverage gap returns or remains pending, never fabricated complete. Private helper actions cannot acknowledge completion. The shared verifier rechecks assessment/publication under its existing lock. Refresh has an independent status. No callback return, wake, agent_end, prompt_result or session_settled is memory success.

At session_stop reconcile terminal sources, inspect exact pending inventory, and use the existing reserve_wake mechanism to deduplicate one advisory request for a newly eligible source-set fingerprint. Return `{continue:true, additionalContext:...}` with fixed guidance naming exact observation references and ordinary shared tool routes. Never `decision:block`, synthetic sendUserMessage, output/tool-result replacement, or transcript surgery. Do not re-enroll memory control output and thereby manufacture a new wake fingerprint. No eligible stable sources means no continuation. Empty/no-learning turns still need shared refresh and assessment through ordinary tools when applicable.

Advisory-requested is not host acceptance. A scheduling failure, aborted generation, native cap, model refusal/omission, disabled tool or malformed assessment retains the original pending record. Do not automatically repeat the same fingerprint in a tight loop or on every restart. Later genuinely new eligible sources may carry an earlier-pending notice; explicit operator recovery may assess the old observation with ordinary permissions. Do not retry an effective refusal behind the user's back. Consequential failures get bounded native diagnostics with exact pending identity and a recovery action; routine verified success need not narrate memory. The user's original answer is never replayed or hidden; new steering remains native input with its original attribution.

## Installation, ownership, diagnostics and compatibility

Add a first-class omp preset alongside peers; installation plans require the exact omp agent root from the host or explicit operator path rather than duplicating omp's evolving profile/XDG resolver. Preview `skills/agent-memory` and `extensions/agent-memory.ts` separately, plus exact activation guidance needed by the native skill. Use existing receipt-owned copy/link/hook-link policies, collision refusal, artifact verification, transactional update/rollback and preservation of modified owned/unowned paths. Never modify global extension lists, provider/auth/approval settings or delete a skill/extension root. Persist chosen root in receipt; update/uninstall use that receipt, not current environment. Preserve source evidence, pending state and banks on ordinary uninstall.

Prevent duplicate execution if the same physical adapter loads through distinct discovery paths: per-process session-local activation guard keyed by canonical receipt artifact identity + actual session ID, released on disposal/switch. A duplicate reports duplicate-binding status and registers no second capture/wake handlers; do not deduplicate different concurrent native sessions. No module-global mutable per-session capture state. Verify actual default/profile/config-root discovery, deliberate --no-extensions/--no-skills controls and foreign-provider collisions before support claims.

Status/doctor distinguish owned artifact integrity, discovered/loaded extension, source observer invocation/enrollment coverage, pending assessment, refresh and witnessed publication. Disk health alone never proves callbacks ran. Version mismatch or disabled discovery produces unsupported/inactive status and preserves explicit skill/CLI use without pretending automation works. Initial implementation target is omp18.16.0; no wider version range without source review and actual qualification. Required release qualification: macOS and Linux, native TUI plus print/RPC modes wherever support is claimed; Codex/Claude and retained OpenCode regressions. Current probes cover macOS RPC only. Missing platform/mode evidence prevents claiming support and accepting #249's required platform matrix, not permission to silently narrow it. Agent-memory raw invocation must remain usable by existing custom clients.

## Execution order and acceptance

1. Obtain independent technical and operator approval of this concrete design, including the action/source projection schemas, receipt mapping, metadata-only callback authority and completion semantics. Later code review must verify these contracts rather than invent unrelated APIs.
2. Implement private source observation/reconciliation through shared ledger, prove exact source identity and inability of metadata routes to mutate canonical memory; then thin native event adapter and bounded advisory policy.
3. Integrate owned omp preset, activation, diagnostics/update/rollback/uninstall and progressive skill guidance with the existing installer. No hard dependency on graph #56 or unrelated v15 performance stories; coordinate integrated candidate/fixtures.
4. Independent actual-installed native acceptance: initial recall; native automatic search/read-before-write for duplicates/distinct candidates; governed capture; no-learning + turn-boundary refresh; real memory-only Git exchange and peer applicability-qualified readback; actual offline authority/refusal/lost-response and successful bounded recovery of the same original observation; concurrent sessions/clones; cancellation; steering; large/partial source payloads; lifecycle preservation; platform/mode matrix and peer regressions. Fixtures and mocks do not satisfy this gate.
5. Update public setup/support/privacy/retention/troubleshooting limits, independently accept the exact candidate, integrate and verify signed v0.0.15 delivery. Research/design approval is not implementation acceptance or delivery.

Qualification must show exact snapshot bytes/hashes, original native session/entry provenance, source coverage and honest unknowns, task answer once, refusal/cancellation control and unchanged unrelated config/Git/index/worktree data. Prior failures stay retained. Source-publication linkage remains explicitly qualified as an agent assertion plus witnessed delta, not an invented cryptographic causal proof.
