## Why, scope and evidence

omp is the operator's primary harness, peer of Codex/Claude. Use the shared skill/files/CLI/semantic and Git contracts, not a harness-owned memory engine or MCP. Automatic invocation must not lose substantive results, confuse generated control with human input, or bypass permissions. Operator-selected failure policy: let the task finish, retain source-bound pending work, report consequential failures; never indefinite completion blocking or fabricated success.

Pins: agent-memory33c95bbebef61e3ac6e58c5c59e0d411b6dc63e8; native upstream650f3a108229ee11bf68ba3377f4e8c3391cd424; actual macOS arm64 omp18.16.0 binary SHA256d4a10d97488d6054d2b18198bd24f461079952c7e0fb75ba66336ca0df0cb99e. Source/binary equivalence is unproven. Eight real-provider macOS RPC fixture probes exercised approval, headless refusal, explicit rejection, executing-tool abort, steering, injected unavailable-tool error, persistence ordering and advisory cap. Original answer appeared once; hidden control had agent attribution; denied tools did not execute; abort reached the tool; steering was retained; cap was eight. Separate synthetic/model-free probes exercised new/switch/resume/forks and shallow snapshot mutability. See the retained feasibility report/traces; none is actual agent-memory or platform-wide qualification. Offline was injected, not a real Git outage. Native message_end precedes persistence and exposes display content that can be deobfuscated; native IDs are not RPC msg-N IDs. Identity forks copy entry IDs into a new session. These facts drive the contracts below.

## Architecture and authority

Proposed transport files: hooks/omp.ts, scripts/omp_boundary.py, scripts/agent_memory/omp_boundary.py. Reuse turn_sources, boundary_assessment, admission/retrieval/sharing and existing lifecycle/installer code. Do not use the older experimental OpenCode ledger for omp. Add only native source transport/aggregation, first-class opt-in installer ownership and necessary shared private-state capability checks.

The trusted executable observer may read native stored source representation, retain private source/transport metadata and reserve bounded advisory wakes. These metadata writes are explicit executable installation authority. Callbacks may NEVER perform canonical memory admission/mutation, refresh, consolidation, Git exchange, assessment acknowledgement or arbitrary model-selected subprocess execution. Those require ordinary model tool calls under unchanged native approval/sandbox policy. Do not change tools, permission mode, provider, model or host settings to make memory succeed. Callback actions have exact schemas and no canonical-mutation operation. Reuse the existing receipt-owned /bin/sh python3.sh interpreter-selection launcher with a fixed absolute helper path and argv/stdin; no shell -c, interpolation or executable path from source data. Do not falsely call this interpreter-pinned: qualify the existing supported-interpreter selector and signed artifact ownership.

Unbound/nonrepository/no-bank contexts are inactive, not an observation fault on every message. Resolve configured banks with the existing project/bank rules; do not create a bank implicitly. Unknown binding, unsupported native version or unreadable private state gives an actionable inactive/pending diagnosis. Explicit skill/CLI invocation remains available. --no-session mode may retain safe in-memory native snapshots privately but cannot promise host transcript recovery after process loss; missing sources remain explicit gaps. Persistent native modes and both required platforms must pass acceptance before #249 is accepted; ephemeral mode's limits are documented rather than silently treated as persistent support.

## Bounded sources: at most two shared observations per lifecycle

Private per-message evidence is not a shared source observation. A source lifecycle is one bounded substantive segment linked to its original genuine human request, not a new human-authority claim. Ordinarily one human request has one segment. A foreign native continuation that adds substantive work after sealing opens a new segment with origin=foreign-continuation and the same human_root, never mutating/reopening completed sources or pretending the continuation is a human admission. Each segment has at most:
1. An admission source for its safely available stored initiating user/foreign-context representation, registered as soon as that representation is available and retaining its real origin/attribution.
2. One sealed segment source: an ordered hash-linked manifest of all safe relevant stored captures, contextual references, and coverage qualifications for that lifecycle up to its seal.

Never register every assistant/tool message in turn_sources. Thus a long task does not exhaust MAX_SOURCES=128 merely by executing many tools. Keep existing shared MAX_SOURCES/MAX_TURNS bounds and their honest capacity diagnostics. Each substantive segment needs at most two acknowledgements; a single approved native tool invocation can chain two explicit CLI commands, each accepting one exact acknowledgement object and returning its own receipt. There is no array input or synthetic merged receipt. Additional foreign substantive boundaries may require another segment, not one acknowledgement per ordinary message; user-facing limits must not claim two acknowledgements per arbitrarily continuing human request.

At session_stop prepare source evidence and seal once for the currently completed substantive segment before requesting memory control. On agent_end seal only when willContinue is not true; willContinue:true/awaiting-async/compaction/plan/todo/rewind continuation events are not terminal seals. Next genuine input/resume/explicit recovery may seal an interrupted prior segment. Always register its segment manifest, including gaps, before permitting acknowledgement of its admission source. A late substantive source after a seal creates a linked foreign-continuation segment with its own shared pending reference, or an explicit gap in that still-open successor; it never hides outside the shared backlog or becomes maintenance by default. Empty/no-learning tasks still need shared assessment/refresh where applicable.

## Safe representation: never retain native display-event content

No callback may retain, serialize, hash, log or forward display-event text, arguments/results, content blocks, thinking, signatures, image bytes or content-derived digests. Native display assistant messages can contain deobfuscated secrets even when the host stores placeholders; public ExtensionContext does not expose a reliable secrets-state accessor. Therefore use this rule for all configurations, not a guessed secrets.enabled check.

At message_end retain metadata only: session ID, event ordinal, capture UUID, native role/attribution and tool identifiers/names, no payload. Because handlers are concurrent/fire-and-forget, enqueue through one per-session single-flight queue before awaiting; busy transport/shared locks mean retryable pending work, not permanent content gaps. On subsequent lifecycle events, including nonsealing agent_end after cancellation/continuation and on stop/resume, deep-copy relevant SessionManager stored branch/entry values before awaiting. This is the native stored representation, not display content; only assistant content is known to be obfuscated by the cited path. User/tool data may remain plaintext as in the host's own store. Do not mutate host objects or reverse placeholders.

Construct a learning-source projection from the stored carrier: retain substantive user text/file mentions, assistant text/tool calls and tool-result content/details, native obfuscated placeholders, exact role/attribution/tool IDs and source-relevant conditions. Do not copy credential_pin entries, providerPayload, internal context snapshots, thinking/reasoning blocks, opaque text/reasoning signatures, auth/config records or other unrelated provider metadata. Record those intentional nonlearning exclusions by fixed code, not 'full raw transcript' claims. Apply existing shared unsafe/secret screening before retaining projected content: withhold a flagged entry as a whole, store only a fixed reason/identity gap and never the secret or a content-derived diagnostic. Do not claim that screening detects every unknown secret. Native obfuscation must never be weakened by this integration. Image/file/artifact payloads remain scoped native references with checked digests; do not dereference arbitrary paths/URLs from untrusted text. An unavailable external payload is a coverage gap, not complete evidence.

Privacy disclosure: native user/tool-result plaintext can contain unknown secrets that the shared scanner misses. Retention therefore matches the chosen native stored representation plus shared screening, NOT a general secret-redaction guarantee. No copy of deliberately deobfuscated assistant display data is allowed. Snapshot storage grows over time without automatic purge or a global retention quota in this milestone; disk-full and capture-size bounds produce honest pending/coverage failures, not silent deletion.

Initial user metadata can precede its stored representation; until a safe representation exists, do not fabricate a source digest or content snapshot. Agent-end/next-event sweeps can retain the native in-memory stored user even when the session file is still lazy. If process loss/cancellation leaves no safe source, retain metadata plus an explicit coverage gap, not a promise of recovered content. This observation gap prevents a full-coverage/no-learning claim. Recovery cannot recreate information the host never exposed safely; disclose that exact limit. Existing safe snapshots remain usable even if the host later omits, rewinds, deletes, obfuscates differently or cannot map a native entry.

## Source identity, coverage and registration idempotency

Native session ID plus bound project/checkout scopes provenance. Lifecycle is an opaque UUID for one source segment; origin={kind,human_root,native_trigger}, kind=genuine-user|foreign-continuation, is retained in its segment manifest and cursor. A genuine user admission establishes human_root; later foreign substantive continuations link to it without new human authority. Never use resettable turn_id. Fork has its own namespace; inherited entries are contextual history, not new admissions; resume retains its namespace/cursor. parentSession is informational and may be a path or ID.

Native mapping is a provenance qualification (verified/unverified/absent), never an acknowledgement precondition. Acknowledgement requires the exact safe snapshot/manifest digest and shared assessment, not host-file survival or event-to-entry bijection. Origin is an observer assertion, not cryptographic proof. A safe source with absent mapping remains assessable. Metadata-only gaps cannot fabricate human content, but their real bounded gap manifest is itself registered so the shared backlog remains authoritative; it is explicitly unassessed while substantive gaps remain.

Sweep the stored branch by native IDs/parent links and cursor. Native stored-only user entries with user attribution open genuine admissions, including crash recovery/direct /btw appends; deduplicate by project/session/native entry ID under the transport lock, not module identity or random capture UUID. Other stored-only entries are included with native-origin qualification. Known nonlearning native exclusions need structural evidence, not text heuristics. A rewind/cursor discontinuity does not discard snapshots: reconcile retained native IDs via getEntries/getEntry and mark branch membership qualification; if ambiguous, register a named gap. A missing/rewritten mapping does not invalidate a digest-verified safe snapshot.

Gap end state is explicit: every sealed manifest, including a gap-only manifest, is registered and remains pending-coverage-gap in the shared ledger. Admission acknowledgement is refused until that manifest is durably registered. While a substantive gap remains unresolved, BOTH no-learning and published acknowledgement of that segment are refused; even a separately witnessed publication cannot certify unseen source coverage. It intentionally retains one MAX_TURNS slot and the omp reader requirement, possibly indefinitely if no safe evidence can be recovered. No source is silently complete, dropped or removed to permit downgrade. Recoverable gaps resolve through an append-only private resolution record binding the original gap/manifest digest to recovered safe evidence; acknowledgement verifies that resolution and the original immutable source ID, never replaces the original manifest. Permanently unavailable sources stay honestly pending; no new automatic gap-dismissal/purge outcome is introduced. Known structurally nonlearning exclusions are not substantive gaps. Expose this backlog/capacity/rollback consequence in support and activation preview.

Store metadata under bank-bound operations state beside shared turn-sources-v2: omp-source-v1/<session-hash>/<lifecycle-uuid>/. This is source/cursor evidence, not a second completion ledger. Permissions 0700 directories/0600 ordinary single-link files; shared no-follow ownership/ancestor checks, bounded unique-key UTF-8 JSON, exclusive immutable snapshot create, hash/fsync/readback; atomic replacement only for cursor records under a private transport lock. Per-source payload limit16MiB; oversized/unavailable payloads produce gaps, never truncation-as-assessment. Snapshots and manifests are retained on normal uninstall; no automatic purge of pending evidence. Publish privacy/retention limits. No purge/daemon feature is added.

Exact metadata records (all unknown keys refused):
- admission.json schema agent-memory/omp-admission-v1: {schema,session,lifecycle,capture_id,event_ordinal,role,attribution,tool_call_ids}; UUIDs canonical, ordinal nonnegative integer excluding booleans, IDs bounded; no content/hash.
- captures/<entry-hash>.json schema agent-memory/omp-capture-v1: {schema,session,lifecycle,capture_id,native_entry_id,native_parent_id,snapshot_ref,snapshot_sha256,representation,mapping,exclusions}; representation='native-stored-learning-v1', mapping enum above, exclusions fixed codes. Snapshot projection encodes carrier type and validated native role-specific content, not an invented role for custom_message.
- gaps/<uuid>.json schema agent-memory/omp-gap-v1: {schema,session,lifecycle,gap_id,native_entry_id,reason}; reason fixed enum unsafe-representation, missing-stored-source, ambiguous-lifecycle, missing-payload, oversized-source, cursor-discontinuity, late-substantive-source. No arbitrary diagnostic content.
- cursor.json schema agent-memory/omp-cursor-v1: {schema,session,lifecycle,origin,last_native_entry,event_ordinal,control_interval,tool_lifecycles}; at most1024 ACTIVE tool bindings, releasing a binding immediately after its result is safely captured; reconstruct old bindings from retained native call/result evidence, not an ever-growing cursor map. Cursor<=1MiB; metadata queue<=4096 admissions; <=16384 safe captures per segment and <=16MiB segment manifest. Busy locks/callback budgets retry without a permanent gap. At a real capacity bound retain an explicit shared pending capacity/coverage manifest; do not LRU-delete unresolved sources or write shared permanent fault.json merely for ordinary message growth.
- segment.json schema agent-memory/omp-segment-v1: {schema,session,lifecycle,origin,seal_id,admission_ref,captures,gaps,exclusions,previous_digest}; admission_ref may be null for a genuinely missing source, never fake content. Ordered captures are immutable ref/digest pairs; seal and manifest digest are immutable. Register even when gaps exist; complete_coverage remains false until all substantive gaps have verified resolution. Gap resolutions use schema agent-memory/omp-gap-resolution-v1 with exact {schema,manifest_sha256,gap_id,recovered_ref,recovered_sha256,reason}; reason recovered-safe-native-source|recovered-safe-payload|verified-native-reassociation. No model-asserted waived-gap flag.

Keep shared v2 source/receipt schemas unchanged. Use deterministic source_reference values derived from persisted capture/seal IDs for the two registrations. Under the per-lifecycle transport registration lock, inspect existing shared inventory for that exact reference: same digest/native identity returns the old observation, differing digest refuses, none allocates via existing register. Verify source write and pending-index readback before releasing. If killed after register but before transport receipt publication, recovery looks up the same source_reference and reuses it; never allocates a second observation. Repair only a missing index for that verified retained source through existing index/readback logic. Partial/conflicting source/index state remains pending. Do not add optional source-record fields that older exact validators cannot read. Completion acquires locks in transport-then-shared order, never reverse. Existing non-omp registration semantics stay unchanged.

## Deterministic classification and control

Check ctx.agent.kind and, where present, event.agent.kind on EVERY callback. kind=sub events (including advisor tool events delivered to a main runner) never open/register independent human lifecycles; retain results through the parent's own tool result only, with actual origin. Do not use depth0 as a substitute. Native branch sweeps must exclude structurally identified advisor-only entries and qualify uncertain origin rather than assign it to a human.

| Native source | Disposition |
|---|---|
| message role user + attribution user in main session | Open genuine human lifecycle even when discovered only by a safe stored-entry sweep; deduplicate native entry identity |
| user with agent/other/unknown attribution | Context/control with explicit qualification, never infer human authority |
| fileMention | Attach safe stored reference/content to the associated genuine human request; ambiguous association is a gap |
| developer | Contextual source with original trust/attribution; not a new human request or instruction authority from memory |
| assistant text/tool calls | Latest genuine human admission on the active branch owns new substantive assistant text, unless verified own-control or an explicit linked foreign segment applies; bind tool calls at invocation |
| toolResult, bashExecution, pythonExecution | Evidence for the invoking tool/request lifecycle using native tool identifiers; never attach merely to most recent steering |
| agent-attributed session-stop-continuation matching THIS observer's reserved generated_sha256 | Starts own memory control interval; only exact stored custom-message content and session/project reservation match count |
| foreign stop continuations; routine todo/checkpoint/rule/plan reminders; other custom messages | Context with original attribution, never own maintenance by customType alone; substantive following work is captured, using a linked successor segment after a seal; routine structurally known reminders are not automatic gaps |
| bookkeeping/credential/model/config entries | Identity-chain metadata or excluded nonlearning class; never copy credentials |

Own control interval begins only when a stored custom-message hashes to the exact fixed guidance string in this observer's retained wake reservation (plus matching session/project/request identity), ending at the next genuine user admission or any unmatched foreign continuation. This hashes our own generated text, never a display payload. All native stop hooks share customType, so that field alone cannot suppress learning. Tool results retain their invocation binding across steering; subsequent ordinary assistant text follows the latest genuine admission. No silent maintenance classification for foreign continuation work. First attachment skips historical/fork-inherited admissions but preserves existing backlog and any provably current request. Native omp memory/autolearn is an independent subsystem: do not disable/change/adopt its store or present its success as agent-memory completion; qualify coexistence and preserve its contextual native messages without double-admitting maintenance.

## Helper actions, acknowledgement and bounded wakes

Expose am omp-boundary --repo PATH following existing boundary CLI conventions. Strict metadata stdin envelope {schema,action,session,lifecycle,payload}, schema agent-memory/omp-observer-request-v1, action admit|ingest|seal|wake. Payload is respectively the exact admission record, validated native-stored carriers/cursor, persisted segment/seal request, or sorted unique pending observation IDs. Helper recomputes/validates all references and wakes; no caller-provided canonical operation or completion flag. Responses distinguish admission-retained/enrollment-verified/coverage-gap/sealed/wake-reserved and canonical_writes_performed:false. Public input is an observer assertion, not cryptographic native authentication.

--list-pending --offset N delegates to shared bounded omp backlog and exposes earlier lifecycle/gap qualifications; --source OBSERVATION --session ID --lifecycle ID verifies the retained snapshot/manifest/digest and reports mapping/exclusions/gaps honestly. No global completeness or no-learning inference from a successful read.

Acknowledgement --stdin accepts exactly {session,lifecycle,observation_id,source_sha256,outcome,assessment}, with publication_request only for published outcome. Retrieve the exact retained shared observation plus safe snapshot/manifest and verify digest, source identity and existing shared assessment/publication replay. Mapping absent/unverified is allowed, not upgraded. No-learning retains bounded source_review/candidate dispositions; published requires the existing explicit source assessment and witnessed intended delta. Preserve assessment_is_agent_assertion:true and source_publication_link_verified:false; do not invent deterministic semantic/causal source-publication proof. --quiet --refresh uses the existing combined convention with refresh status separate from source completion. Canonical operations and acknowledgements run only through ordinary approved tools. Invalid combinations/extra fields/foreign identities refuse before changes.

For a gapped segment the acknowledgement helper first verifies every substantive gap resolution; otherwise both outcomes refuse and the shared source remains pending-coverage-gap. Admission acknowledgement requires its segment already registered, so a gap cannot disappear when the admission is marked done. The segment manifest is registered even when it contains no substantive content, with its real gap metadata; it is not a fabricated human message or a successful no-learning assessment.

At stop: one branch sweep and one batched helper invocation seal current source segments and independently reserve wakes. Use each existing shared inventory()['fingerprint'] EXACTLY as reserve_wake expects, not a separately invented source-set hash; validate supplied IDs against that inventory. One advisory message lists only successful reservations in stable order. Its generated_sha256 hashes the exact same fixed UTF-8 guidance string persisted for ALL those reservations. Matching that stored string to a reservation is required to recognize our own control; control_origin_hint is unused for omp. Partial reservations remain explicit and unreserved lifecycles stay pending, never marked requested.

Return continue:true only; never decision:block, synthetic user input or answer/result rewrite. Each callback enqueues single-flight work and stops awaiting after one second (or a shorter native handler budget). This is NOT authority to terminate/kill a helper during shared writes: helper checks its work budget before entering a transaction, then finishes atomic-write/fsync/readback once begun. A timed-out caller treats the result as unknown/pending and reconciles the retained transaction before scheduling another helper. No N serialized helper calls at stop. Busy locks are retryable pending, not permanent gaps. Measure/qualify fsync and batched-stop latency on Linux/macOS. Native cap, failed scheduling, aborted generation, model omission or denied tools never imply completion or repeated same-fingerprint retries. Explicit recovery uses original source IDs and ordinary permissions.

## Private-state compatibility and rollback (B5)

Adding omp to HARNESSES is a private-index compatibility boundary: an old index() validates every pending slot and rejects omp even while registering Codex/Claude. A marker alone cannot protect an already-running old binary. Therefore native activation requires quiescing all omp-unaware agent-memory processes for the participating bank(s) and upgrading peer runtimes to this reader capability before the first omp reference. Mixed-version concurrent use on a bank containing omp references is unsupported and MUST NOT be claimed safe. Enabling requires an explicit operator attestation of this rollout prerequisite; installer cannot infer remote process quiescence from local process lists. If unavailable, retain passive skill/explicit CLI use and do not enable native source enrollment.

Before first omp registration, exclusively write/readback/fsync private turn-sources-compat-v1.json adjacent to turn-sources-v2, exact {schema:'agent-memory/turn-sources-compat-v1',minimum_reader:'omp-harness-v1',harnesses:['omp']}. Marker creation precedes shared index visibility; retain on partial registration. Omp-aware readers check malformed/unknown requirements before source index access; capability declares support in trusted runtime compatibility metadata. Keep one shared pending index/backlog/completion mechanism, not a separate hidden omp memory ledger.

Install/update/preflight/exact-runtime rollback/downgrade/recovery inspect durable bank AND private source-reader capabilities before restoring executables/hooks. Unknown/malformed markers or incomplete inventory refuse incompatible execution without deleting pending state. Native activation records every enrolled bank in the existing local bank registry before first omp registration; lifecycle preflight expands rollback_repositories from that registry and saved bindings and includes offline/missing entries as unknown, not absent. Banks outside that inventory, remote clones and manually invoked old binaries are NOT protected by this guard; docs must state this discovery limit. No claim of a universal old-runtime fence.

Marker clearing is a defined phase of the AWARE lifecycle command, not a permanent undisclosed block or an added reset command. Invoker: actual approved update/downgrade/exact rollback or uninstall preflight after the omp executable binding is disabled and all participating old/aware writers are quiesced. Lock order: existing runtime lifecycle lock -> bank-wide source barrier (new omp-aware shared-source operations take its shared side) -> transport registration lock -> shared source completion locks in stable namespace order. Under the exclusive barrier enumerate the complete shared pending index plus all omp source namespaces, orphan registrations and transport admissions; verify no indexed/unindexed incomplete omp observation, unresolved gap, in-flight helper or new enrollment remains. A capped/unreadable/offline/unknown inventory refuses clearing and incompatible execution. Completed immutable snapshots may remain because old readers do not enumerate unindexed completed omp namespaces. Durably unlink/readback the compatibility marker only after that proof, then continue candidate activation; otherwise preserve marker/state/journal and report pending IDs. --check previews this phase read-only. This never purges source evidence, invents completion, or requires a permanent ban once references are safely drained.

## Explicit opt-in ownership and receipts (B6)

Omp is NOT added to all: all remains agents,codex,claude,opencode. Fresh all install and existing saved all updates never install executable omp code. Enable only via explicit --presets list containing omp, --omp-agent-dir ABSOLUTE_ROOT, and rollout attestation --omp-peers-upgraded. An explicit preview shows executable extension authority, private evidence retention and exact skill/extension/activation targets before mutation. No root inference from profile/HOME/XDG; same-root reinstallation is idempotent. A different root is refusal unless explicitly uninstalling/reinstalling the binding, not an environment-driven move.

Continue reading legacy install-receipt-v1 with no omp ownership. Emit install-receipt-v2 only for explicit omp installations; it adds exact omp_binding={agent_dir,skill_target,extension_target,activation_target,peer_reader_capability,rollout_attested}, where target paths are canonical absolute owned destinations or null for omitted activation, capability='omp-harness-v1', rollout_attested=true from the explicit selection/attestation event. Validate selected omp preset iff binding exists and exact target membership agrees with existing receipt targets/artifact identity; no current-environment reconstruction. Source compatibility metadata declares this receipt reader capability. Old runtimes must fail closed on v2 receipt, not silently adopt it; aware runtimes accept v1 and v2. Non-omp installs keep v1 to avoid needless peer cutover.

Persist skill/extension/activation ownership separately using existing target policies; never edit provider/auth/approval/global extension settings. Update/recovery/rollback/uninstall/preflight use saved omp_binding/targets, never environment-derived omp paths. Mismatched explicit root or inconsistent receipt refuses before touching either location. Omitted update presets preserve saved omp selection/root. Explicit update --presets all on an installation with omp_binding REFUSES the implicit removal: use explicit owned uninstall/reinstall for that cutover. Saved all remains non-omp. Incompatible restore/recovery obeys the private capability/clearing protocol; uninstall preserves modified/unowned files, banks, snapshots and pending state.

Use a process-global namespaced activation-token registry for module instances, with per-session-local capture state only. Key guard by actual session plus bound project/observer family, record canonical artifact identity as the owner; a second artifact/manual copy reports duplicate-binding and registers no second handlers rather than using a different artifact key to evade dedup. Additionally ingest is idempotent under the bank transport lock by project/session/native entry identity, so a second process/factory cannot assign a fresh random human lifecycle to the same admission. Release token on disposal/switch; never transfer capture state to children. Native subagent callbacks remain inactive. Disabled discovery/loading is honest inactive status, not bypassed.
