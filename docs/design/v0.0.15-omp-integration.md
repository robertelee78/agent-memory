## Bounded sources: at most two shared observations per lifecycle

Private per-message evidence is not a shared source observation. A source lifecycle is one bounded substantive segment linked to its original genuine human request, not a new human-authority claim. Ordinarily one human request has one segment. A foreign native continuation that adds substantive work after sealing opens a new segment with origin=foreign-continuation and the same human_root, never mutating/reopening completed sources or pretending the continuation is a human admission. Each segment has at most:
1. An admission source for its safely available stored initiating user/foreign-context representation, registered as soon as that representation is available and retaining its real origin/attribution.
2. One sealed segment source: an ordered hash-linked manifest of all safe relevant stored captures, contextual references, and coverage qualifications for that lifecycle up to its seal.

Never register every assistant/tool message in turn_sources. Thus a long task does not exhaust MAX_SOURCES=128 merely by executing many tools. Keep existing shared MAX_SOURCES/MAX_TURNS bounds and their honest capacity diagnostics. Each substantive segment needs at most two acknowledgements; a single approved native tool invocation can chain two explicit CLI commands, each accepting one exact acknowledgement object and returning its own receipt. There is no array input or synthetic merged receipt. Additional foreign substantive boundaries may require another segment, not one acknowledgement per ordinary message; user-facing limits must not claim two acknowledgements per arbitrarily continuing human request.

At session_stop seal a completed original segment before memory control, EXCEPT an open integration/foreign successor, which accumulates until terminal agent_end (willContinue is not true), next genuine user or explicit recovery. willContinue:true/async/compaction/plan/todo/rewind paths do not prematurely seal that successor. Admission acknowledgement requires its manifest registered first. Late substantive work never mutates completed sources: use a linked successor retaining human_root and real origin. At most one successor is OPEN per root at a time; genuinely new foreign work after a prior terminal settle may open another, and is not relabeled maintenance. Preserve every such source in shared/joined pending inventory.

## Safe representation: never retain native display-event content

No callback may retain, serialize, hash, log or forward display-event text, arguments/results, content blocks, thinking, signatures, image bytes or content-derived digests. Native display assistant messages can contain deobfuscated secrets even when the host stores placeholders; public ExtensionContext does not expose a reliable secrets-state accessor. Therefore use this rule for all configurations, not a guessed secrets.enabled check.

`message_end` and `tool_call` are neutral hints, never source-origin authority. Do not read their role, attribution, body or reported tool IDs. Each notification assigns its counted attempt before copying cheap checked session/header-ID/cwd/file/leaf metadata; the closed wire identity is {kind:'hint',session,header_id,cwd,leaf_id}, without body, full graph or source digest. Worker hints use fresh fast binding checks and record metadata only: never observe, transport lock, source origin, gap, assessment or wake. Null leaf is neutral. A known nonnull leaf is covered only by an exact safely retained native-ID disposition or a verified full source attempt from any same-session instance, earlier or later; unknown/refused attempts and role/order/count are not proof. Uncovered known leaves stay joined pending without blocking transport CLOSE. Hints never change the full-view baseline or OLD T anchor.

One trailing macrotask performs a checked FULL stored sweep at most once per second; hints arriving before it are individually counted but do not repeatedly copy/serialize the session. Every lifecycle, agent start/end, stop, shutdown and pre-compaction/navigation boundary still captures a FULL view immediately. FULL views detach actual SessionManager session/header, manager cwd, original header cwd/timestamp, file, leaf, all native parent/timestamp identities, branch and safe projection before any await, then recheck identity. Source authority remains those exact stored entries. A delayed OLD hint can trigger a NEW actual view, never an old-event origin. Real unavailable tails remain pending rather than inferred from mapping absence.

Construct a learning-source projection from the stored carrier: retain substantive user text/file mentions, assistant text/tool calls and tool-result content/details, native obfuscated placeholders, exact role/attribution/tool IDs and source-relevant conditions. Do not copy credential_pin entries, providerPayload, internal context snapshots, thinking/reasoning blocks, opaque text/reasoning signatures, auth/config records or other unrelated provider metadata. Record those intentional nonlearning exclusions by fixed code, not 'full raw transcript' claims. Apply existing shared unsafe/secret screening before retaining projected content: withhold a flagged entry as a whole, store only a fixed reason/identity gap and never the secret or a content-derived diagnostic. Do not claim that screening detects every unknown secret. Native obfuscation must never be weakened by this integration. Image/file/artifact payloads remain scoped native references with checked digests; do not dereference arbitrary paths/URLs from untrusted text. An unavailable external payload is a coverage gap, not complete evidence.

Privacy disclosure: native user/tool-result plaintext can contain unknown secrets that the shared scanner misses. Retention therefore matches the chosen native stored representation plus shared screening, NOT a general secret-redaction guarantee. No copy of deliberately deobfuscated assistant display data is allowed. Snapshot storage grows over time without automatic purge or a global retention quota in this milestone; disk-full and capture-size bounds produce honest pending/coverage failures, not silent deletion.

Stored persistence may follow a notification. Subsequent checked lifecycle views capture available native source even while its host file is lazy; no role/order/count heuristic resolves a gap. A normal cloned notification does not manufacture a permanent source gap. Genuine unsafe/unavailable payloads, known unpaired stored calls, active interrupted tails and failed/partial handoffs remain explicit pending qualifications. Existing safe snapshots remain assessable if a later host view disappears or cannot map them; no claim covers source the host never exposed safely.

The adapter hands each counted attempt immediately to one detached finite FIFO worker per native session instance, rather than lazily spawning one process per callback. The wire accepts at most 16 MiB per source frame, 64 MiB/4,096 retained encoded frames, one decoded observer operation, bounded independent responses, and explicit refusal/unknown accounting. Busy BEFORE source writes may retry within the fixed 30-second contention bound; unknown AFTER start is never replayed. EOF drains accepted work without signalling a shared-write helper. READY requires a committed, verified installation/bank binding; no-bank is INACTIVE and activation-required is REFUSED.

Shutdown first disables future worker creation and cancels the trailing hint timer. It sends the final full capture and FINAL, then asynchronously awaits actual stdin finish/write completion for at most 1.8 seconds within the native 2-second shutdown cap. This waits for pipe transfer, not observer transactions; a timeout leaves OPEN/partial coverage honest. A normal-print success claim requires actual large-frame flush/CLOSE evidence. Detached helpers continue draining accepted bytes without a signal or kill.

Keep the OLD instance open through before-switch. At a checked committed identity change, start NEW independently; defer bounded OLD recovery through the exact previously checked getSessionFile and public pure parseSessionContent, never a constructor, BlobStore or transcript walker. Require a stable owned no-follow descriptor, strict UTF-8/header/version, original anchors and validated native graph. Public resolveSessionLeafId handles activeLeafId only after AM checks parent closure/cycles. Reuse existing captures by native ID; persisted truncation/blob payloads remain unavailable. The provisional 16 MiB retired-file cap and host-loop blocking/support require qualification. Missing/lazy/unsafe/oversized/malformed old files retain non-actionable transition qualification T; the safe prefix remains assessable. Cancelled transitions do not close the continuing instance.

## Source identity, coverage and registration idempotency

Native session ID plus bound project/checkout scopes provenance. Lifecycle is an opaque UUID for one source segment; origin={kind,human_root,native_trigger}, kind=genuine-user|foreign-continuation, is retained in its segment manifest and cursor. A genuine user admission establishes human_root; later foreign substantive continuations link to it without new human authority. Never use resettable turn_id. Fork has its own namespace; inherited entries are contextual history, not new admissions; resume retains its namespace/cursor. parentSession is informational and may be a path or ID.

origin.native_trigger is a closed enum: human, human-with-own-guidance, own-hidden-pure, own-hidden-combined, own-hidden-ambiguous, foreign-hidden, resume. kind=genuine-user permits human or human-with-own-guidance; kind=foreign-continuation permits the other five, with root retained. own-hidden-pure is a classified nonlearning control interval and creates NO source segment unless unexpected substantive work forces reclassification to own-hidden-ambiguous. Trigger suppression is additional to the ONE-root-wake budget, not an exception allowing foreign-hidden to wake repeatedly. Immutable segment/cursor bind the enum; later ambiguity captures work rather than dropping it.

Native mapping is provenance (verified/unverified/absent), never an acknowledgement precondition. Genuine roots require exact deterministic project/session/stored-human-native-ID binding plus the retained safe user capture or a matching typed unavailable-payload gap. A later real user capture attached to an old random metadata root does not retrospectively authenticate that origin. Filter the entire invalid root family from selection, source mutation, tool ownership and recovery. Pending legacy roots cannot receive new acknowledgements; exact retries of already completed immutable receipts require the original request hash and perform no new writes. Historical completed assertions remain explicit history, never silently rewritten or upgraded.

Only an actually completed, immutable historical family with all registered and unregistered source references accounted for may be inspected/drained with its origin explicitly unqualified. This does not authenticate a phantom root or permit a new/different assessment; exact historical receipt replay is read-only.

Sweep the stored branch by native IDs/parent links and cursor. Native stored-only user entries with user attribution open genuine admissions, including crash recovery/direct /btw appends; deduplicate by project/session/native entry ID under the transport lock, not module identity or random capture UUID. Other stored-only entries are included with native-origin qualification. Known nonlearning native exclusions need structural evidence, not text heuristics. A rewind/cursor discontinuity does not discard snapshots: reconcile retained native IDs via getEntries/getEntry and mark branch membership qualification; if ambiguous, register a named gap. A missing/rewritten mapping does not invalidate a digest-verified safe snapshot.

Gap end state: every sealed gap manifest is retained and enrolled when shared capacity permits; otherwise it stays explicit enrollment-pending in the joined public backlog. Admission acknowledgement is refused until its manifest is durably registered. Any substantive unresolved gap refuses BOTH outcomes; a witnessed publication alone cannot certify unseen coverage. Once registered it retains one MAX_TURNS slot and reader requirement, possibly indefinitely. Unregistered/faulted enrollments likewise block compatibility clearing and are never hidden. Recoverable gaps use the exclusively written resolution record defined below; acknowledgement verifies recovered safe evidence against original IDs/digests. Permanently unavailable sources remain pending, not automatically dismissed/purged or called no-learning. Structurally known nonlearning exclusions are not substantive gaps. Activation/support must disclose capacity and rollback consequences.

Store metadata under bank-bound operations state beside shared turn-sources-v2: omp-source-v1/<session-hash>/<lifecycle-uuid>/. This is source/cursor evidence, not a second completion ledger. Permissions 0700 directories/0600 ordinary single-link files; shared no-follow ownership/ancestor checks, bounded unique-key UTF-8 JSON, exclusive immutable snapshot create, hash/fsync/readback; atomic replacement only for cursor records under a private transport lock. Per-source payload limit16MiB; oversized/unavailable payloads produce gaps, never truncation-as-assessment. Snapshots and manifests are retained on normal uninstall; no automatic purge of pending evidence. Publish privacy/retention limits. No purge/daemon feature is added.

## Deterministic classification and control

Check ctx.agent.kind and, where present, event.agent.kind on EVERY callback. kind=sub events (including advisor tool events delivered to a main runner) never open/register independent human lifecycles; retain results through the parent's own tool result only, with actual origin. Do not use depth0 as a substitute. Native branch sweeps must exclude structurally identified advisor-only entries and qualify uncertain origin rather than assign it to a human.

| Native source | Disposition |
|---|---|
| message role user + attribution user in main session | Open genuine human lifecycle even when discovered only by a safe stored-entry sweep; deduplicate native entry identity |
| user with agent/other/unknown attribution | Context/control with explicit qualification, never infer human authority |
| fileMention | Attach safe stored reference/content to the associated genuine human request; ambiguous association is a gap |

## Helper actions, acknowledgement and bounded wakes

Expose am omp-boundary --repo PATH for source inspection and ordinary acknowledgements. Native writes use ONLY the private finite --stream pipe, not the obsolete one-shot --observer stdin route. The internal v2 observer envelope is {schema,action,session,lifecycle,payload}; source observe accepts ingest|seal|wake, while neutral hint is handled entirely by stream metadata. Checked source payloads carry the full closed view; seal adds request_wake. Every source operation freshly verifies opaque executable/receipt identity and the existing new marker before writes; it cannot lazily enroll or upgrade. No serialized trust/bypass flag exists.

The public command's `--stream` dispatch is the same internal framed transport, not an assessment API or proof that caller-supplied source bodies came from a native callback. It grants no additional publication/assessment authority. Actual native qualification must load the receipt-owned hook and exercise its exact `/bin/sh hooks/python3.sh scripts/omp_boundary.py --stream` spawn route; a public-command finite-pipe smoke is recorded separately.

--list-pending --offset N returns a bounded joined inventory of shared omp sources and transport enrollment-pending/registration-fault namespaces, with distinct cursors/statuses and no fake observation IDs for unregistered work. Enumerate omp-source-v1 enrollments so a full shared index or pre-registration failure cannot hide a source; status and compatibility clearing use the same complete-inventory rules. --source OBSERVATION --session ID --lifecycle ID verifies retained digest/manifest and reports mapping/exclusions/gaps; an unregistered enrollment is inspected by its capture/seal reference, not misrepresented as a completed shared observation. No global completeness or no-learning inference from a successful page.

Acknowledgement --stdin accepts exactly {session,lifecycle,observation_id,source_sha256,outcome,assessment}, with publication_request only for published outcome. Retrieve the exact retained shared observation plus safe snapshot/manifest and verify digest, source identity and existing shared assessment/publication replay. Mapping absent/unverified is allowed, not upgraded. No-learning retains bounded source_review/candidate dispositions; published requires the existing explicit source assessment and witnessed intended delta. Preserve assessment_is_agent_assertion:true and source_publication_link_verified:false; do not invent deterministic semantic/causal source-publication proof. --quiet --refresh uses the existing combined convention with refresh status separate from source completion. Canonical operations and acknowledgements run only through ordinary approved tools. Invalid combinations/extra fields/foreign identities refuse before changes.

For a gapped segment the acknowledgement helper first verifies every substantive gap resolution; otherwise both outcomes refuse and the shared source remains pending-coverage-gap. Admission acknowledgement requires its segment already registered, so a gap cannot disappear when the admission is marked done. The segment manifest is registered even when it contains no substantive content, with its real gap metadata; it is not a fabricated human message or a successful no-learning assessment.

ONE automatic request per genuine human_root is enforced ONLY by the omp root record. Under the transport lock exclusively create/fsync omp-source-v1/<session-hash>/root-wakes/<human_root>.json, exact {schema,session,human_root,native_user_entry,request_id,status}, schema agent-memory/omp-root-wake-v1 and status=requested. It is ROOT-keyed, never lifecycle-keyed; successors/new fingerprints cannot reset it. Omp does NOT call shared core reserve_wake for current or earlier namespaces: its two-slot/repeated-fingerprint policy cannot govern human-root carry-forward. Each new human-rooted wake offers checked current sources and earlier suppressed OR UNSUPPRESSED pending work from ANY root/session of this bound project, through bounded inline references plus explicit pending cursors/faults as defined above. An older source P omitted by the model remains offered at H2, H3 and later roots with original identity, inline when it fits or through the explicit cursor otherwise; neither old reservations nor foreign contention/faults suppress the healthy new root. Guidance never asserts that referenced work was assessed. Integration-only/foreign stops for a requested root never reserve another wake. Lost/capped/blocked/aborted scheduling stays pending. At most one successor is OPEN per root at a time until terminal settle/new human/recovery; later truly separate foreign runs may create another, without new automatic budget. In plan/goal mode combined wakes can leave a final pending successor when the person stops; later human-rooted wake or explicit recovery is required. This limit is public, not a false claim that memory always finishes before the task.

The one-real-human budget also survives old random-root to deterministic-root cutover: bounded, closed, SAME-session root-wake records are compared by exact stored native_user_entry. An already requested native human is suppressed without a second ledger or a role/time heuristic; a different actual human remains eligible. Unknown/malformed wake state suppresses new automatic reservation with explicit pending faults, but cannot prevent retaining/enrolling real source. Public inventory/drain still validates the whole wake namespace.

Prepare and enforce the complete 8,192-byte guidance bound before reserving the root wake, then check the real delivery window immediately before the exclusive reservation. Guidance overflow leaves no new reservation. Wake preparation failures cannot turn an already verified source seal into unknown execution: return explicit pending wake status. A failure during/after reservation remains unknown-after-reservation for that single wake attempt; retain any actual reservation and never automatically retry it. Source transaction failures themselves are not suppressed.
