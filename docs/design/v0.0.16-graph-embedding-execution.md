## 4. Physical isolation and checkout binding

The physical isolation unit is **one complete project-bank-state generation per
dedicated database instance and owned storage root**. No Enterprise database,
label-only partition, or shared global ANN index is assumed. Candidate and active
instances MUST be distinct. Every index ranks only one generation's authorized
project data. The baseline does not materialize cross-project relations.

A private namespace binds full project UUID, normalized bank path, resolved
checkout/common-Git identity and storage-owner receipt. Service names may use a
bounded hash prefix only if the receipt verifies the complete identity; a name
collision or missing receipt MUST refuse adoption. Ports are allocated under a
private ownership lock and pinned to exact instance/owner identity, never SSG's
7690/11492 conventions. Endpoints bind loopback by default.

A reader's bank-state key binds complete canonical bytes/framing, actual Git
context, applicable authority/policy and **fresh private hold/frontier state**.
Matching project UUID alone is insufficient. Distinct branches/worktrees/clones
may reuse immutable vectors only when rendered-source/profile identity agrees;
they MUST NOT share an active graph as complete unless their full bank-state
keys match. Cross-clone reuse is an explicitly verified private local artifact
optimization, not federation. Unknown/mismatched state yields `stale` or
`unavailable`, never an apparently complete other-branch result.

## 5. Typed graph schema and provenance

All identifiers are tagged, preventing record/context/route/variant collisions.
Each node carries `project_id`, `generation_id`, source/framing digest and type.

| Node | Stable logical key | Required projection fields |
| --- | --- | --- |
| Project | tagged project UUID | Canonical bank/authority identity, not raw credentials |
| RecordVersion | `(project UUID, record UUID, version)` | Canonical path/hash, kind, lifecycle/trust/visibility, conditions, evidence and origin references |
| ContextSource | `(project UUID, canonical path)` | Exact source hash, orientation-only label, framing |
| Route | `(project UUID, index path, target path, ordinal)` | Source assertion/hash, purpose, inherited scope/conditions |
| Scope/Component | Tagged canonical scope expression | Exact component predicate; no guessed entity normalization |
| Condition | Tagged normalized canonical predicate | Key/value and declaring source; unknown remains unknown |
| Evidence/Source | Tagged canonical evidence reference | Original reference/provenance and source assertion; disclosure qualification |
| Origin | Tagged recorded origin tuple | Developer/harness/session/code-state provenance, subject to disclosure |

Edge types: `CONTAINS`, `ROUTES_TO`, `IN_SCOPE`, `HAS_CONDITION`, `SUPPORTED_BY`,
`ATTRIBUTED_TO`, `CORRECTS`, `SUPERSEDES`, `DERIVED_FROM`. Every edge carries the
asserting canonical source/hash, endpoint keys, inherited conditions/provenance
and generation. Canonical `derived-from` retains deletion-closure meaning.
Missing/historical endpoints MUST NOT reconstruct deleted bodies or disclose
hidden identifiers. New durable domain relation types need a separate canonical
schema/governance decision. Optional `SIMILAR_SUGGESTION` edges are disposable,
explicitly inferred, and bind model/renderer/vector/source generation; never
reinterpreted as a recorded assertion or automatic admission.

No graph node, edge, label, reason, count or body is exposed until **both**
endpoint and relation-provenance disclosure qualify. Final native reader gates
remain authoritative. A hidden correction withholds obsolete guidance without
revealing its replacement; graph absence MUST NOT reactivate the old claim.

## 6. Named query templates

Only packaged, digest-bound, typed, read-only templates are callable. Reader
credentials/protocol MUST have no write authority where the chosen deployment
can enforce it; template validation alone is not a database ACL.

| Template | Parameters | Bound and semantics |
| --- | --- | --- |
| `replacement-evidence` | Source-bound record-version reference; optional explicit historical mode | ≤4 hops, ≤64 candidate paths, ≤250 ms database execution; return correction/supersession/supporting-source chains with assertion provenance |
| `component-attempts` | Qualified seed references and truthful task/component predicates | ≤2 typed hops, ≤64 candidates, ≤250 ms; traverse scope/evidence/origin/prior-attempt relationships, not similarity-only neighbors |
| `recorded-related` | Qualified seed reference, relation-type allowlist and page reference | ≤2 hops, ≤32 candidates/page, ≤250 ms; recorded and inferred channels separately labeled |
| Shared entities (deferred) | Not part of G1; schema, parameters and bounds are owned and independently reviewed by #56 | Unavailable until #55/#57/#253/#56 qualify admitted shared records and authority; never a sibling-bank route or local acceptance prerequisite |

These are proposed conservative query bounds, not observed latency passes.
Parameters MUST be values, never interpolated Cypher, labels, procedures or
paths. DDL/index/build writes have separate owned builder APIs. The allowlist
rejects arbitrary model-generated Cypher and write-capable procedures. Static
review and actual `EXPLAIN` plan checks both apply; a changed database/query
version needs fresh qualification. Budget exhaustion is `partial`/`unavailable`,
not complete no-match. Mandatory caveats are obtained through native assembly,
not an optional exploration budget.

[ADR-0025](../adr/0025-project-and-shared-memory.md) replaces named-foreign-project
expansion with installation-configured shared recall. A shared dataset MUST use
its own physical generation/isolation domain; its dataset/clone/authority-freshness
namespace binding is defined by #55/#253 and qualified separately. G1 qualifies
only project-bank generations. Local/shared results merge after separate
qualification under #253's reviewed ordering/coverage/budget contract.
Configuration is once per installation, not per project or developer
identity; authorized operators MAY select the same team/ecosystem repository.
There is no #253 per-lookup operator receipt. Export authorization and its trusted
confirmation/policy channel belong to #57, independently of shared read authority.
G1 and local G3/G2/P1/#200 acceptance MUST NOT wait for shared implementation.

## 7. Embedding connection and profile identity

Existing service setup accepts base URL plus optional API key; an explicit model
is needed only when the provider requires one or metadata is ambiguous.

1. Treat URL as an API base. A root URL normalizes to `/v1`; an explicit non-root
   API prefix is preserved. Append `/models` and `/embeddings` exactly once.
   Do not probe alternate provider paths or route to another service silently.
2. A provided model is used for documents and queries. If metadata is available,
   verify it names that model; do not accept an arbitrary echoed request alias.
   If model is absent, exactly one unique metadata model MAY be selected.
   Multiple/no models require explicit model selection or a typed refusal.
3. Metadata alone does not prove embedding support: run a bounded synthetic
   embedding capability probe. A chat-only/erroring route is incompatible.
4. Validate response model/profile evidence, complete unique integer indices,
   exact count/dimension, finite nonzero vectors, bounded bytes/time and batch
   coverage. Missing/duplicate/extra indices, malformed/partial results fail the
   batch without publishing partial coverage.
5. Normalize documents and queries identically for cosine. Profile identity
   binds endpoint/model/reported revision or weight digest, dimension,
   normalization, own-text renderer, prefixes, token/chunk limits and enabled
   probe specification. Key material is not included in public hashes/receipts.
6. The observed llama.cpp 9341 endpoint accepts an unknown requested model name
   and echoes it while computing with the loaded model. The contract MUST check
   separate metadata/configuration evidence and MUST NOT call an echo verified
   weight identity. A malicious/opaque provider remains unverifiable.

The reference document renderer is the record's own body plus declared necessary
scope/framing, not neighboring records. Query prefix version 1:
`Instruct: Retrieve applicable saved project guidance for the question.\nQuery: `.
Document prefix is empty. Other profiles may use versioned empty/custom prefixes;
SSG's security-review instruction is not the AM default.

Rendered source is hashed exactly; no silent clipping. Known-profile tokenizer
and server-declared context limits MUST be checked. Real reference over-context
inputs were refused with HTTP 400 and explicit `n_prompt_tokens`/`n_ctx`; the
reference's configured context was 8192 and alternate 4096, not each model's
larger training window. Opaque endpoints lacking tokenizer/declared no-truncation
evidence MUST report processing/truncation assurance as unverified; successful
API response is not proof that all tokens were used. Unknown assurance MUST NOT
be represented as complete semantic absence or inherit reference quality passes.
An existing compatible URL/key/model must still work without installing a local
server or requiring the operator's reasoning-model name.

Observable profile changes invalidate vectors and inferred state. Opaque aliases
show **`provider model identity not verifiable`** in machine and human status;
cross-time reuse reports reliance on provider alias stability. Full re-embed is
always available. Fixed synthetic probes can diagnose drift, not prove immutable
weights; G1 must measure probe-at-fill overhead/tolerance before enabling them.
A chat-model change has no embedding invalidation effect.

## 8. Native ranking and coverage

Proposed structured recall request adds only an explicit ranking policy:

```json
{"ranking":{"mode":"semantic","profile":"configured-profile-id","fallback":"none"}}
```

It supplements, not replaces, the existing project/query/IDs/paths/context/kinds/
trust/limit/include-context/discovery fields. With no `ranking`, literal/exact
behavior remains unchanged. Semantic mode and exact selectors follow an explicit
intersection contract: exact selectors constrain the candidate domain, they
never supply ordering or bypass native qualification. No caller-supplied raw
score/vector is accepted as source or authorization evidence.

The orchestrator obtains a complete, current, authorized generation and query
vector. The native reader then applies scope, lifecycle, trust, visibility,
conditions, safety, supersession, held-path/frontier and source qualification.
Only **then**, before count/byte budgets, compute final semantic ordering over
the eligible candidate domain. Stable ties use canonical tagged identity.
Mandatory caveat/conflict groups cannot be displaced by ranking. Final source,
policy, profile and private-frontier rechecks occur before emission.

The initial persisted vector store MUST support eligible **exact cosine**.
The scratch numerical reference uses float32 normalized storage and float64 dot
accumulation; non-finite scores refuse. ANN is optional only after eligible
recall/resource comparison. A global ANN top-K followed by filtering cannot
claim eligible top-K completeness or absence. No all-pairs 50k similarity build
is the default. Comparison/admission and three-view sharing keep their separate
exhaustive/semantic-judgment contracts and MUST NOT accept retrieval top-K as
novelty, compatibility or frontier coverage.

## 9. Complete generation protocol

Private manifest schema: `agent-memory/semantic-generation-v1`:

- project/bank/checkout identity, generation UUID and authority/privacy epoch;
- exact canonical source/framing hashes and independently observed private
  frontier/hold token; actual Git context; policy/validator/producer identities;
- graph schema/query-template digests and exact instance/storage ownership pins;
- embedding profile/renderer/prefix/tokenization/assurance identities;
- per-source rendered hashes and vector keys/dimensions; required/filled/excluded
  counts with private eligibility reasons; graph/vector completeness separately;
- artifact digests, build journal/phase, capability qualification and timestamp.

State machine: `planned → building-graph → filling-vectors → validating → ready
→ active → retiring → erased`, with `pending`, `stale`, `interrupted`, and
`erasure-pending` as explicit non-success states. A failure never advances by age.

1. Snapshot eligible inputs and authority/frontier at a safe boundary; release
   the bank write lock before graph/model work. Allocate isolated candidate
   instance/volume/vector files and durable owned journal.
2. Build typed graph, fill/reuse exact compatible per-source vectors, create
   candidate-local indexes. Record each completed batch durably. No active graph
   or pointer mutation while these phases are incomplete.
3. Validate exact expected coverage, artifacts/query plans and complete original
   source/policy/frontier/profile/epoch pins. Revoke/delete fences win over stale
   builders. A source change discards/rebases the candidate; no pretend complete
   build with omitted sources.
4. Under a short generation-publication lock, recheck the epoch and pins, fsync
   manifest/artifacts, then compare-and-replace the private active routing pointer.
   Readers pin one complete manifest/instance; never mix graph/vector generations.
5. A previous generation is reusable only while **still qualified** for that
   reader's bank state and current policy/epoch. Otherwise status is stale or
   unavailable. Interrupted candidate fill/publish does not make old bytes current.
6. Readers recheck privacy/source/profile/frontier before output. Retire obsolete
   generations after reader leases are fenced; preserve owned recovery evidence
   until safe erasure. Exact completed retry returns the historical receipt,
   never publishes again over a later active generation.

## 10. Automatic maintenance and resource controls

Explicit setup/start/disclosure approval precedes maintenance. Canonical writes
only enqueue a content-free bank-state-change hint; model/database work never
runs while holding the bank write lock. At a safe boundary, coalesce hints,
observe current complete eligibility and process changed compatible sources.
Never project/send secrets, quarantined/deleted/unadmitted material or infer
current-task applicability from indexing eligibility.

Proposed conservative maintenance limits pending measured/operator disposition:
one builder per bank namespace; one in-flight embedding batch; maximum eight
inputs/batch, 8192 aggregate tokens for the reference context, and a 30-second
interactive boundary work budget. Larger rebuilds are explicit resumable jobs;
limits do not permit truncation or publication of incomplete generations.
Requests use declared provider limits when stricter. Approved remote profiles
also require an operator-set spend/token ceiling; no automatic remote work
until that ceiling is explicit. These proposals are not frozen numeric passes.

Services stopped/unavailable means maintenance remains pending. Maintenance MUST
NOT start/download a service, change endpoint/model, or silently disclose to a
fallback provider. Disable cancels/fences publication and preserves the bank.

## 11. Deletion, fencing and erasure authority

A monotonic private privacy epoch fences all readers/builders before prohibited
content can be served or republished. Deletion/consent changes invalidate related
vectors, caches, inferred relation payloads, graph instances, active pointers,
snapshots, WAL and owned model logs. Canonical deletion and derived erasure are
separate receipt fields until all owned persistent copies are verified erased.

The baseline erasure strategy retires and removes each affected **whole owned
generation store/volume**, then rebuilds currently permitted content. Do not
pretend `DETACH DELETE` compacts WAL/snapshots. AM ownership receipts identify
exact volume/container IDs, directory/owner pins and build UUIDs; no recursive
cleanup of unknown paths or adoption by matching names. Failure leaves
`erasure-pending`, a persistent fence, and actionable owned-resource IDs.

BYO graph acceptance requires an explicitly dedicated, AM-owned erasure domain
with verifiable disposal/fencing rights and no unrelated data. If that cannot be
established, refuse the profile; do not wipe a shared SSG/user graph. Remote
embedding-provider retention/backup/deletion limits are separately disclosed,
including unknown terms. Local purge cannot claim provider-side erasure or
recall already disclosed bytes/Git history/external backups. Do not retain query
vectors or raw prompts by default; content-bearing diagnostics are disabled.

## 12. Public CLI and machine outcomes

Proposed commands, not existing-command claims:

- `am graph setup|status|start|stop|build|rebuild|diagnose|purge --repo R`.
- `am embeddings setup|status|start|stop|reembed|diagnose|purge --repo R`.
- Setup accepts managed or BYO; embedding setup accepts `--url`, optional private
  key-file/secret-store reference and optional `--model`. Credential values are
  never printed or written to Git, banks, prompts, receipts or logs.
- `am search --repo R --request REQUEST` is #256's structured acceptance surface.
  #200 later supplies `am search --semantic QUERY` and `am related REFERENCE`.
- Purge uses explicit inspect/preview plus owned-resource confirmation. Diagnose
  never starts/stops/modifies a BYO service. Search never starts/downloads one.

All new semantic operations return `agent-memory/semantic-result-v1` with:
`operation`, safe `status`/`reason_code`, project ID, requested/effective mode,
qualified guidance and mandatory caveats, source/version/evidence/conditions,
selection reference, recorded/inferred relation labels, generation/profile
identity assurance, independent source currency/semantic coverage/remote
freshness, and separate mutation/resource flags. Credentials, raw query,
excluded foreign metadata and private source bodies are absent from diagnostics.
Selection references bind generation/source/policy/epoch/context, not standing
authority; every follow-up is freshly qualified.
This v1 schema qualifies the local-project surface only. #253 MUST add explicit
local/shared authority labels, shared dataset/record versions, and per-domain
coverage/freshness through a separately reviewed additive schema revision before
shared acceptance. Local consumers MUST NOT infer shared absence from v1.

For an operator plain-terminal invocation, `--repo R` selects one current project,
not a multi-bank union. In a harness-bound session, a mismatched repository/bank/
path or foreign selection reference MUST be refused without sibling access.
The trusted distinction and binding/origin mechanism remain explicit #200/#253
execution-design gates; a caller flag or claimed operator origin is not proof.

| Exit | Status | Meaning |
| --- | --- | --- |
| 0 | `qualified` | Completed requested mode; only qualified saved guidance, possibly empty within explicitly stated coverage |
| 1 | `unavailable`, `stale`, `incompatible`, `refused`, `approval-required`, `pending`, `erasure-pending` | Requested semantic result unavailable; actionable safe reason, never semantic no-match |
| 2 | `invalid-request` | CLI/schema/type error before any content query/disclosure |

`approval-required` here is reserved for AM-initiated endpoint/provider disclosure,
not an authorized shared read; a sibling-bank request returns `refused`.

An explicitly requested literal fallback can exit 0 with `effective_mode:literal`
and `semantic_status:unavailable`; it MUST NOT call itself semantic success.
Baseline existing literal operations keep their existing schemas/exits unless

## 14. SSG runtime lessons retained and deliberately strengthened

Actual SSG build observed 974 units, 62,251 advisories, 84,277 nodes and 103,339
edges; 0/63,225 embedding coverage was explicitly reported, not assumed complete.
Typed named queries and source digests are reusable patterns. SSG commits its
graph transaction before separately attaching vectors and similarity edges;
AM uses isolated complete generations instead. SSG's exact all-pairs similar
edge construction is not copied as a 50k default.

Transient code workspaces can supply explicit code-context evidence to named
queries, but remain separate disposable stores. Parser omissions are unknown
coverage, not absence or durable lessons. Evidence-resolved critics can help
human/agent review distinguish source-backed claims from unsupported ones;
judgments stay advisory and source/version bound. Neither a code indexer,
critic, forced Qwen model, llama.cpp installation for BYO, nor another reasoning
agent is a prerequisite for retrieving saved guidance.
