## 4. Physical isolation and checkout binding

The physical isolation unit is **one complete project-bank-state generation per
dedicated database instance and owned storage root**. No Enterprise database,
label-only partition, or shared global ANN index is assumed. Candidate and active
instances MUST be distinct. Every index ranks only one generation's authorized
project data. The baseline does not materialize cross-project relations.

A private namespace binds full project UUID, normalized bank path, resolved
checkout/common-Git identity and storage-owner receipt. Service names may use a
bounded hash prefix only if the receipt verifies the complete identity; a name
collision or missing receipt MUST refuse adoption. Ports are allocated under a
private ownership lock and pinned to exact instance/owner identity, never SSG's
7690/11492 conventions. Endpoints bind loopback by default.

The bank-state key is the tuple `(project UUID, bank_observation_sha256,
frontier/hold token, authority/settings digest, validator engine digest, profile
identity, privacy epoch)`. Use the canonical observation and the same
authority/settings binding as `recall_catalog`; hash a canonical encoding of
the tuple. Namespace identity additionally binds the checkout and owned storage
above. Branch and HEAD revision are not bank-state key components: record them
as observed context in the manifest, and freshly recheck actual branch/revision
and all request applicability at every read, including after a clone copy.
Every graph or vector read requires strict equality of the complete freshly
observed bank-state key with the generation key, before and immediately before
disclosure. Any canonical write, including a checkpoint, makes semantic reads
stale until a new candidate is published; no per-source delta exception exists.
The new candidate MUST copy verified compatible vectors for unchanged exact
rendered-source/profile keys and embed only changed/new eligible sources or
sources lacking a verified compatible copy. A new bank-state key never waives
fresh projection, eligibility or publication checks. Profile changes require a
full newly bound fill; an explicit full re-embed remains available through
operator-approved re-setup, not as the default after every checkpoint.
Native literal recall remains an explicit fallback, never labelled semantic.
Matching project UUID alone is insufficient. Graph instances are NEVER shared
across namespaces, even for matching keys. Cross-clone reuse MAY only verify and
copy immutable content-addressed vectors with matching rendered-source/profile
identity into the target candidate's independently owned store, after checking
the source namespace is not `erasure-pending` and rechecking both epoch fences.
It transfers no erasure ownership or completeness/applicability assertion.
Unknown/mismatched state yields `stale` or `unavailable`, never an apparently
complete other-branch result.

## 5. Typed graph schema and provenance

All identifiers are tagged, preventing record/context/route/variant collisions.
Each node carries `project_id`, `generation_id`, source/framing digest and type.

| Node | Stable logical key | Required projection fields |
| --- | --- | --- |
| Project | tagged project UUID | Canonical bank/authority identity, not raw credentials |
| RecordVersion | `(project UUID, record UUID, version)` | Canonical path/hash, kind, lifecycle/trust/visibility, conditions, evidence and origin references |
| ContextSource | `(project UUID, canonical path)` | Exact source hash, orientation-only label, framing |
| Route | `(project UUID, index path, target path, ordinal)` | Source assertion/hash, purpose, inherited scope/conditions |
| Scope/Component | Tagged canonical scope expression | Exact component predicate; no guessed entity normalization |
| Condition | Tagged normalized canonical predicate | Key/value and declaring source; unknown remains unknown |
| Evidence/Source | Tagged canonical evidence reference | Original reference/provenance and source assertion; disclosure qualification |
| Origin | Tagged recorded origin tuple | Developer/harness/session/code-state provenance, subject to disclosure |

Project only visible, security-safe active and inactive standalone versions
permitted by canonical authority; exclude candidate, quarantined, hidden, unsafe
and deleted material. Inactive means `superseded`, `revoked` or `expired` and
does not make it current guidance. Context and metadata are projected only when
their asserting source is permitted. An absent, excluded, deleted or unresolved
endpoint causes its edge to be omitted, not a reconstructed placeholder.

Each directed edge below has `from`, `to`, `asserted_by` (tagged source key),
`source_sha256` (exact asserting source bytes), `channel`, inherited conditions,
provenance, `project_id` and `generation_id`. `channel` is `recorded` for a
canonical assertion, or `inferred` only for `SIMILAR_SUGGESTION`. Source keys
identify the record or context/index source actually asserting the edge, not
the target; a source must itself qualify for the request. `component` means a
canonical repository-relative component condition from the scope or conditions,
not an inferred entity, and can be absent or unknown.

| Edge | Direction and canonical assertion |
| --- | --- |
| `CONTAINS` | Project → RecordVersion or ContextSource; canonical bank inventory/path and its source framing |
| `ROUTES_TO` | Route → RecordVersion or ContextSource; index source's explicit target path and ordinal |
| `IN_SCOPE` | RecordVersion, ContextSource or Route → Scope/Component; source scope and inherited route scope chain |
| `HAS_CONDITION` | RecordVersion, ContextSource or Route → Condition; source-declared or inherited condition |
| `SUPPORTED_BY` | RecordVersion → Evidence/Source; record `evidence` reference |
| `ATTRIBUTED_TO` | RecordVersion → Origin; record `origin` tuple |
| `CORRECTS` | RecordVersion → RecordVersion; asserting newer version's `corrects` exact reference |
| `SUPERSEDES` | RecordVersion → RecordVersion; asserting newer version's `supersedes` exact reference |
| `SUPERSEDED_BY` | RecordVersion → RecordVersion; asserting old version's `superseded-by` exact reference |
| `DERIVED_FROM` | RecordVersion → RecordVersion; asserting version's `derived-from` exact reference, retaining deletion-closure meaning |
| `SIMILAR_SUGGESTION` | RecordVersion or ContextSource → RecordVersion or ContextSource; disposable inference binding model/renderer/vector/source generation, never a recorded assertion or automatic admission |

`SIMILAR_SUGGESTION` is a reserved conditional relation, not built by this v1
graph projection. Selecting it, alone or with recorded relations, MUST return
`unavailable`/`graph-unavailable`, never a qualified empty suggestion set or
silently omit it. #257 MUST separately specify and qualify a bounded builder
and model/renderer/generation provenance before enabling it; until then no
inferred edge may claim a canonical asserting source. This condition does not
defer recorded typed traversal, embeddings or semantic search.

New durable domain relation types require a separate canonical schema/governance
decision. No graph node, edge, label, reason, count or body is exposed until
every path node and every edge's asserting source qualifies for disclosure.
Metadata nodes must be permitted by the qualified asserting source and request.
Final native reader gates remain authoritative. A hidden correction withholds
obsolete guidance without revealing its replacement; graph absence MUST NOT
reactivate the old claim.

### 5.1 Projection eligibility is not embedding or current-guidance eligibility

The builder MUST maintain distinct inventories for graph metadata, document
vectors and request-qualified current guidance. V1 MAY project permitted inactive
RecordVersion metadata and recorded assertions for historical/provenance paths;
it MUST NOT embed or copy vectors for superseded, revoked or expired versions,
or persist their bodies in graph properties. A historical pointer therefore
does not require a historical body or vector. The historical native seam MUST
inspect the canonical version's disclosure metadata without promoting it through
`lifecycle.current`; unknown qualification remains unavailable under §6.
Deleted/compacted canonical content MUST NOT be recovered to fill that seam.

Document-vector eligibility MUST use the source-change operation's native
security, visibility, admission, lifecycle and disclosure gates, not the last
query's task applicability. A permitted active task-conditioned source MAY be
indexed before a request supplies that task, but MUST NOT pass current recall
without the required context. A graph-only inactive node is outside the required
vector inventory, not `missing-score`, `empty-input` or incomplete fill.
The manifest MUST record each inventory and its exclusion basis separately.
An ordinary current search MUST score only the active vector inventory and then
apply all fresh request gates in §8. The current native reader's active-only
selection in `retrieval.evaluate_sources` remains unchanged; no historical-body
search or historical-body fetch is introduced by this candidate.


## 6. Named query templates

Only packaged, digest-bound, typed, read-only templates are callable. Reader
credentials/protocol MUST have no write authority where the chosen deployment
can enforce it; template validation alone is not a database ACL.

All templates receive `generation_id: UUID`, `seed: tagged RecordVersion key`,
current-qualified and historical-disclosable sets of `(tagged source key,
exact source_sha256)` and `page_token: string|null`. Construct both freshly
before ranking or budgets for the actual request context. For `related`, use all
native record kinds, `minimum_trust: reviewed`, and `include_context: true`.
Current qualification applies native authority, lifecycle, scope, conditions,
trust, visibility, security, supersession and hold/frontier gates. Historical
disclosure is a proposed new native qualification seam owned by #257, not an
existing API. Only visible, security-safe superseded, revoked or expired versions
permitted by scope, conditions, trust and authority qualify. Deleted, hidden,
quarantined or unsafe material never does. Historical material is never current
guidance. Until that seam is implemented and qualified, any template requiring
a historical intermediate or target returns `unavailable`, not a partial path.

Templates return paths of ordered rows `{from: tagged key, rel: enum, to: tagged
key, asserted_by: tagged source key, source_sha256: lowercase SHA-256 hex,
channel: recorded|inferred}` in stored edge direction, without bodies. Every
source-bearing path node and asserting source must be fenced against its exact
key and hash in the appropriate freshly qualified set; each edge assertion hash
must equal its asserting source hash. Other metadata nodes require disclosure
permission from that source and request. Fence every path before counts, ordering,
pagination or caps; refuse if qualification is unknown. Nonhistorical paths may
use historical nodes only as intermediate correction/provenance nodes, never as
targets. `historical:true` may target them as labelled body-free pointers.

Index-asserted `ROUTES_TO` and inherited `IN_SCOPE`/`HAS_CONDITION` assertions
require a separate proposed #257 navigation-source qualification seam. The
current `retrieval.evaluate_sources` excludes indexes as `non-guidance-format`;
it cannot qualify these assertions by treating an index as current guidance.
The new seam MUST freshly bind the canonical index path/hash, actual inherited
route chain, authority, scope/conditions, visibility/security and frontier, and
authorize only the assertion's disclosure. It MUST NOT emit an index body as
guidance or a semantic result. Fence its exact asserting-source key/hash like
every other edge. Until implemented, a traversal needing such an assertion is
`unavailable`/`graph-unavailable`, not an unfenced path or complete empty set.

The seed MUST be a freshly qualified current RecordVersion selected through
native recall. A historical selection reference can identify a returned
historical pointer, but MUST NOT become a traversal seed in v1: return
`refused`/`invalid-related-seed`, exit 1. `historical:true` widens permitted
intermediates/targets only, never seed authority. Related paths MUST be nonempty
and simple (no repeated node); their target MUST differ from the seed and be a
source-bearing RecordVersion or ContextSource with a canonical path/hash.
Scope, Condition, Evidence/Source and Origin nodes MAY be qualified intermediates,
not fabricated source pointers. A terminal evidence identifier with no canonical
source is an assertion in the projection, not an independently fetchable body.
Rows MUST retain stored `from`/`to` direction even when traversed in reverse;
the ordered row list MUST describe a connected walk starting at the seed.
Neither a reverse traversal nor a two-hop common-evidence path asserts a new
inverse, derivation or causal relation.

The primary recall result, its mandatory caveats, and optional related pointers
are three separate outputs. Templates MUST NOT manufacture a zero-hop seed
pointer or promote path targets into primary guidance. A seed needed as primary
guidance MUST be obtained and scored by §8, even when it also asserts a returned
edge. Scope/condition assertions on that seed remain auditable projection facts;
they are not extra current bodies or attempt records.

Order paths by `(target tagged key, complete ordered edge tuple)` in canonical
byte order, deduplicate identical paths, and fetch cap + 1 *after* qualification.
Return at most cap and mark `partial` when the extra path exists; timeout or
unresolved qualification cannot imply complete absence. The opaque authenticated
keyset token binds the template execution described in §12, not its emitting
CLI operation or the outer search query. Reject mismatches or stale
generation/authority rather than resuming. No offset pagination is allowed.

| Template | Additional typed parameters | Bound and semantics |
| --- | --- | --- |
| `replacement-evidence` | `historical: boolean` (required) | Traverse `CORRECTS`, `SUPERSEDES`, `SUPERSEDED_BY`, `SUPPORTED_BY` in either direction, 1–4 hops, ≤64 qualified paths/page, ≤250 ms; historical targets require the proposed historical disclosure seam above |
| `component-attempts` | No additional arguments; derive component/task from effective native context | Traverse `DERIVED_FROM`, `IN_SCOPE`, `SUPPORTED_BY` in either direction, 1–2 hops to a RecordVersion, ≤64 qualified paths/page, ≤250 ms. Target kind MUST be canonical `episodic-attempt`, `project-decision`, or `result`; this is a kind filter, not a fabricated attempt edge. Every `IN_SCOPE` join requires actual applicable component conditions, never a shared generic hub. Native scope/conditions decide applicability: a declared component must be the observed component or its ancestor, never a descendant. Required component context missing/unknown is invalid input; an unknown task cannot qualify a task-conditioned record. |
| `recorded-related` | `relations: nonempty set<edge enum>` | Only `CORRECTS`, `SUPERSEDES`, `SUPERSEDED_BY`, `DERIVED_FROM`, `SUPPORTED_BY`, `SIMILAR_SUGGESTION` and guarded `IN_SCOPE` are permitted, in either direction, 1–2 hops, ≤32 qualified paths/page, ≤250 ms. `IN_SCOPE` joins require actual applicable component conditions, not a shared generic hub. Never use `CONTAINS`, `HAS_CONDITION` or `ATTRIBUTED_TO` as lesson relatedness. Provenance may explain a result but shared origin alone is not relevance. Label recorded and inferred channels separately. |
| Shared entities (deferred) | Not part of G1; schema, parameters and bounds are owned and independently reviewed by #56 | Unavailable until #55/#57/#253/#56 qualify admitted shared records and authority; never a sibling-bank route or local acceptance prerequisite |

Each pointer's `relation_channel` MUST be `inferred` if any row in any returned
path is inferred; otherwise it MUST be `recorded`. Search-result `related`
arrays stay empty unless the request explicitly selects one of these templates;
its qualification, page cap and timeout apply unchanged.

The common structured query is the closed object
`{"template": NAME, "arguments": OBJECT, "page_token": STRING_OR_NULL}`.
All three keys are required. `replacement-evidence` arguments are exactly
`{"historical": BOOLEAN}`; `component-attempts` arguments are exactly `{}`.
It derives its required component and optional task from effective native
context, never a second selector or override. Apply the existing native
`condition_value` validator to every context value; an unknown kind, invalid
component, rejected value or missing required component is `invalid-request`,
exit 2. Additionally bound each supplied task to 1024 UTF-8 bytes, reject control
characters and apply the shared security screen before template execution.
`recorded-related` arguments are exactly `{"relations": NONEMPTY_UNIQUE_EDGE_ARRAY}`
using that template's allowlist. Unknown names/keys, wrong types or arguments
for another template are `invalid-request`, exit 2. The reserved similarity
relation is syntactically recognized but operationally unavailable as above.
The machine shapes are also defined as `related_query` and `related_request`
in the result schema's `$defs`.

Standalone core input is
`{"schema":"agent-memory/related-request-v1","selection_ref":REF,"context":CONTEXT,"query":QUERY}`.
No other keys are permitted. `REF` is an authenticated current selection
reference, not an asserted source path or authority; re-observe native context
and qualify the seed and all returned sources. `CONTEXT` uses the existing
native recall context types/gates, not caller-supplied Git truth.
Each emitted `next_page` is reused as `query.page_token` with the same reference,
context and arguments. Foreign/stale/invalid references retain their named
refusals. The core input is shared by #252 and #200; it is not a terminal-only
parser convention.

Code workspaces supply native request context and qualification, not an
additional template parameter or an independently indexed workspace corpus.

These are proposed conservative query bounds, not observed latency passes.
Parameters MUST be values, never interpolated Cypher, labels, procedures or
paths. DDL/index/build writes have separate owned builder APIs. The allowlist
rejects arbitrary model-generated Cypher and write-capable procedures. Static
review and actual `EXPLAIN` plan checks both apply; a changed database/query
version needs fresh qualification. Budget exhaustion is `partial`/`unavailable`,
not complete no-match. Mandatory caveats are obtained through native assembly,
not an optional exploration budget.

[ADR-0025](../adr/0025-project-and-shared-memory.md) replaces named-foreign-project
expansion with installation-configured shared recall. A shared dataset MUST use
its own physical generation/isolation domain; its dataset/clone/authority-freshness
namespace binding is defined by #55/#253 and qualified separately. G1 qualifies
only project-bank generations. Local/shared results merge after separate
qualification under #253's reviewed ordering/coverage/budget contract.
Configuration is once per installation, not per project or developer
identity; authorized operators MAY select the same team/ecosystem repository.
There is no #253 per-lookup operator receipt. Export authorization and its trusted
confirmation/policy channel belong to #57, independently of shared read authority.
G1 and local G3/G2/P1/#200 acceptance MUST NOT wait for shared implementation.

### 6.1 Route orientation uses native navigation, not lesson relatedness

Topic indexes and router entries MUST remain canonical navigation, not semantic

## 8. Native ranking and coverage

Proposed structured recall request adds an explicit ranking policy:

```json
{"ranking":{"mode":"semantic","profile":"configured-profile-id","fallback":"none"}}
```

It supplements the native `project_id`, `query`, `ids`, `paths`, `context`,
`kinds`, `minimum_trust`, `limit`, `include_context` and optional `discovery`
fields. With no `ranking`, literal/exact behavior remains unchanged. `fallback`
is `none` or `literal`; semantic mode requires a nonempty, non-whitespace query.
An unknown profile is `invalid-request`; an incompatible configured profile is
`incompatible`. A `qualified` or `partial` semantic result MUST be retained even
when fallback is `literal`: opaque assurance or incomplete related exploration
does not discard usable semantic primaries. For other semantic failures, `none`
returns the nonqualified status. When literal fallback is requested and §12
permits the switch, the reader MUST run the ordinary native literal reader,
labelling both modes and the semantic failure without pretending literal output is semantic.

A request containing `ranking` MAY also contain `related: QUERY` using the §6
closed query object. Its `page_token` MUST be null: each primary result supplies
its own freshly qualified seed. Each result carries `related_next_page` for its
own bounded reference page; resume that page with a standalone related request
using the result's `selection_ref` and that token. Standalone responses instead
use top-level `next_page`. A malformed `related` object is v1 `invalid-request`,
exit 2. Without `ranking`, no new request keys are recognized and existing literal
behavior remains unchanged. Omission of `related` leaves all result reference
arrays empty and `related_next_page` null; no exploration is implicit.
Embedded and standalone templates use the identical §6 qualification policy:
all kinds, reviewed minimum trust and context included, independently of the
outer search's selection filters. Orientation-only results are not RecordVersion
seeds: their arrays stay empty with null `related_next_page`. A standalone
orientation reference returns `refused`/`invalid-related-seed`. Selecting reserved
similarity inside a search returns the whole operation `unavailable` before
primary results are emitted; it cannot silently omit failed exploration.

All embedded related work shares a 250-ms wall budget, measured from its first
qualification/query work, and at most 16 KiB of serialized optional references.
It also MUST fit the remaining native `MAX_RESULT` byte budget after primary
guidance and mandatory caveats; never remove either to make room for references.
At exhaustion report overall `partial` with reason `partial-coverage` and graph
capability `partial`, preserve independently qualified primary results, and give
each unfinished record seed a non-null `related_next_page`. A seed not yet visited gets a signed start cursor
with a null last tuple; a visited seed resumes after its last completely emitted
path. No incomplete path is emitted. Requalification happens on continuation;
an unqualified seed gets no cursor or disclosure. Vector coverage remains
independent. These are proposed caps, not measured latency passes.
#252/#200 skill and tool guidance MUST explain that this exit-1 `partial` response
still carries independently qualified primary guidance; do not discard it merely
because optional exploration exhausted its budget or claim related absence.

#256's optional `semantic_vectors` provider receives the freshly qualified,
source-bound selected domain from the native seam below, then computes exact
cosine for every required vector in that domain and hands the reader an internal
complete map, never a caller-supplied ranking or top-K. The persisted inventory
still covers all independently eligible active sources (§5.1); request scoring
does not broaden request authority to that inventory. Each map key is
`(tagged source key, canonical path, source_sha256, rendered_sha256)` and its value
is either a finite cosine score or explicit `empty-input`/`over-context` exclusion.
For ContextSource, renderer `context-source-v1` serializes a JSON object
with exactly `body` (the unmodified decoded UTF-8 context-prose source),
`path` (canonical bank-relative path), and `scope_chain` (ordered canonical
inherited scope strings). Encode with UTF-8, sorted keys, no insignificant
whitespace, no ASCII escaping and no trailing newline; prepend the profile's
document prefix bytes. Hash those exact rendered bytes. Context remains
orientation-only and gains no record authority. Renderer version and framing
serialization are profile-bound, and changes invalidate vectors.

#256 MUST add a source-bound internal qualification outcome before consulting
vectors, scoring, count limits or byte budgets. The current reader only retains
excluded counters; it does not implement a withheld/clarification result.
The new seam MUST first build the same complete active-superseder inventory as
native recall: exact `supersedes`/`corrects` ID/version references from records
passing authorized scope, applicability, active state, valid time and sufficient
trust, before replacement visibility, security, kind or query filters. It MUST
also inspect selected obsolete versions' canonical disclosure metadata even
when their lifecycle excludes current bodies; this is not historical-body recall.

the private cause `hidden-replacement`, mapped to `withheld` and exclusion
`withheld`. A safe visible replacement merely excluded by kind/query is not this
cause. Revocation, expiry, deletion, ordinary lifecycle inactivity, insufficient

Unknown applicability/disclosure needed to decide a selected source yields
`clarification-required`, not invented hidden-replacement evidence; an unreadable

effective context, authority/frontier and epoch; replacement identities and

generic outcome/exclusion, never hidden identity, path, body, hash or a new

For an exact obsolete-ID/path request, empty results MUST therefore remain
`withheld` (or the higher applicable status), exit 1, with noncomplete semantic
coverage, never `qualified` complete no-match. This cause applies within the
selected domain before ranking even when other safe primaries can be returned.
The native reader freshly applies its existing lifecycle, scope, conditions,
trust (`minimum_trust`), visibility, safety, supersession, hold/frontier and

all-query-terms text-overlap gate with membership in the selected domain: when

semantic coverage/status partial; a truly missing exact identity entry yields

## 9. Complete generation protocol

Private manifest schema: `agent-memory/semantic-generation-v1`:

- project/bank/checkout identity, generation UUID and authority/privacy epoch;
- exact canonical source/framing hashes and independently observed private
  frontier/hold token; actual Git context; policy/validator/producer identities;
- graph schema/query-template digests and exact instance/storage ownership pins;
- embedding profile/renderer/prefix/tokenization/assurance identities;
- per-source rendered hashes and vector keys/dimensions; required/filled/excluded
  counts with private eligibility reasons; graph/vector completeness separately;
- artifact digests, build journal/phase, capability qualification and timestamp.

Generation states are exactly `planned`, `building-graph`, `filling-vectors`,
`validating`, `ready`, `active`, `retiring`, `interrupted`, `discarded`,
`erasure-pending`, and `erased`. `pending` and `stale` describe namespace or
result status, never a generation state. State transitions are:

| From | To | Trigger |
| --- | --- | --- |
| `planned` | `building-graph` | Journal durable, pins captured and owned candidate allocated |
| `building-graph` | `filling-vectors` | Graph build complete |
| `filling-vectors` | `validating` | Required vector coverage filled |
| `validating` | `ready` | All artifacts, coverage, query plans and pins validate |
| `ready` | `active` | Publication CAS succeeds under the common lock |
| `active` | `retiring` | Replaced or explicitly retired; stale is a reader/namespace status, not a transition |
| `planned`, `building-graph`, `filling-vectors`, `validating`, `ready` | `interrupted` | Worker stops or slice ends before completion; journal records exact resume phase and checkpoint |
| `interrupted` | recorded prior state | Resume only the same candidate with all source, authority, frontier, engine, profile and epoch pins unchanged |
| `planned`, `building-graph`, `filling-vectors`, `validating`, `ready`, `interrupted` | `discarded` | Pins changed, validation fails, cancellation, or publication CAS loses |
| `discarded`, `retiring` | `erasure-pending` or `erased` | Dispose owned resources; enter pending if incomplete, erased only after verification |
| Any non-erased state | `erasure-pending` | Privacy fence requires disposal, regardless of reader activity |
| `erasure-pending` | `erased` | All required owned resources verified disposed |

A failure never advances by age. Before any candidate content persists, durably
journal its UUID, namespace, epoch, pins and planned owned resource identifiers;
record allocations before writing their contents. Snapshot eligible inputs and
authority/frontier at a safe boundary, then release the bank write lock before
graph/model work. Build isolated graph, copy/fill vectors and candidate-local
indexes, recording completed batches durably. Validate exact expected coverage
and all original pins; changed pins discard the candidate, never silently rebase
or publish omitted sources. A new build takes a new snapshot and journal.

Every embedding attempt MUST have a private, content-free journal entry before
transport admission, binding attempt/operation IDs, namespace, generation UUID,
bank-state key, privacy epoch, embedding-profile digest, approval-reference digest,
purpose (`document`, `query` or synthetic capability), and the ordered exact
source/rendered hashes for document inputs. Query attempts bind the request ID
and generation, not retained query text/vector; synthetic probes MUST NOT be
attributed to a canonical document. Entries MUST distinguish `prepared`,
`dispatched`, `completed`, `failed` and `outcome-unknown`; successful HTTP is not
proof of publication, erasure or provider deletion. Vector reuse/copy MUST be
recorded separately with source/target ownership and keys; it is not a provider
send. Each retry, if separately authorized, is another attempt, never an
overwritten record or presumed duplicate-free disclosure.
For managed-local/verified loopback default permission or §7's synthetic
setup-only permission, `approval-reference digest` is null: bind the applicable
policy version, destination classification and verification evidence in the
private attempt record instead. Do not fabricate an operator grant or hash a
fictitious approval reference. Remote project sends require the actual verified
approval-record digest. This journal detail adds no public result field.

Immediately before dispatch, the worker MUST recheck source eligibility,
approval/ceiling, stopped/inhibit state and all epoch/profile pins under the
common publication lock; it MUST register the transport attempt there before
releasing the lock. This transport admission is ordered with publication and
privacy fencing. It MUST NOT hold the bank lock across model/network work.
An attempt not admitted before a privacy fence MUST NOT dispatch under the old
epoch. The transport MUST support cancellation of admitted in-flight work;
after a fence its response MUST be discarded and MUST NOT fill or publish a
generation. Bytes already in flight cannot be recalled from a provider.

The pointer record includes active generation and privacy epoch. All publication,
epoch bumps and candidate fencing use the same publication lock. A builder
captures the pointer's old digest and epoch, fsyncs artifacts/manifest, then
under that lock rechecks all pins and compare-and-replaces only if both digest
and epoch still match. A CAS loser is discarded and disposed, never retried
over a newer pointer. Readers pin one manifest/instance, never mix generations,
and recheck the current pointer epoch, source, profile and frontier immediately
before output. A previous generation is usable only with exact complete bank-state
key equality and current policy/epoch (§4); otherwise report stale or
unavailable. Reader leases MUST NOT delay privacy fencing or disposal. An exact
completed retry returns its historical receipt, never republishes.

## 10. Automatic maintenance and resource controls

Explicit setup, `am graph start` and applicable disclosure approval precede
maintenance. Start grants a bounded started-runtime envelope with installation-wide
instance count and memory caps in private per-installation configuration, and at
most one active and one candidate per namespace. The owned launcher starts a
detached worker only within that explicit envelope. It may provision and dispose
owned per-generation instances, but MUST NOT restart a stopped runtime, download
software, change endpoint/model or silently disclose to a fallback provider.
At a cap or when stopped/unavailable, maintenance remains `pending`. Stop first
disables the envelope and fences publication, signals only a verified owned
worker, then waits at most a proposed 30 seconds; report pending/unknown if
termination is not verified, never kill an unknown process. Status reports queued
hints separately. `stop` is also the disable control: it cancels the started
maintenance envelope and fences publication without altering the bank; only
explicit `start` can re-enable it. No separate undocumented `disable` operation
or automatic restart exists.

Normal canonical writes enqueue only a content-free bank-state-change hint in
private installation-owned state outside the bank; hooks return without graph/model
work. Forget/consent operations instead synchronously perform the §11 privacy
fence immediately after canonical commit and before derived content can serve.
A detached AM-owned worker coalesces hints under the namespace builder lock,
observes complete eligibility at a safe boundary, and works without holding the
bank write lock. Work proceeds in resumable 30-second slices, including large
rebuilds; persist the exact candidate checkpoint, and resume only with unchanged
pins and epoch, otherwise discard. Never project/send secrets,
quarantined/deleted/unadmitted material or infer current-task applicability
from indexing eligibility.

One builder runs per namespace and one embedding batch is in flight per endpoint
profile across the installation. Private per-installation configuration binds
the endpoint-profile token ceiling and rolling window; per-project provider
approval binds its approved profile and ceilings as additional constraints and
cannot expand the installation ceiling. Reaching either leaves work `pending`
with `remote-budget-exhausted` until capacity returns.
Remote automatic work requires an explicit approved ceiling. Proposed limits of
eight inputs and 8192 aggregate tokens per reference batch remain measurement
and operator disposition, not established passes; stricter declared provider
limits apply. Limits never permit truncation or incomplete publication.

Missing or invalid installation instance/memory/provider ceilings MUST leave
automatic maintenance `pending`/`resource-limit`; missing disclosure authority
has §12's higher-precedence `approval-required`. There is no unlimited default.
Each batch MUST fit both scopes' approved input, aggregate-token, byte and
in-flight ceilings and the provider's declared limits; reserve the full known
cost before dispatch and retain unknown/failed sends against that reservation
until reconciled, never refund on an unknown outcome. Without trustworthy token
accounting, token-capped remote automatic work MUST NOT dispatch. The 30-second
slice is a scheduler checkpoint boundary, not permission to repeat an ambiguous
request: an in-flight operation MUST be resolved/cancelled and journalled before
resumption or a new batch. Eight inputs/8192 tokens are research candidates only,
not defaults, approvals or production resource ceilings.

## 11. Deletion, fencing and erasure authority

A monotonic private privacy epoch fences all readers/builders before prohibited
content can be served or republished. Global lock order is namespace builder
lock → bank scope/write lock → publication lock → installation endpoint-budget
lock. The endpoint-profile in-flight slot and both scopes' full cost reservation
are acquired atomically under that last lock during §9 transport admission,
after rechecking all pins under the publication lock. If either is unavailable,
release locks and remain pending; never wait for a slot while holding earlier
locks. Completion/reconciliation may take the endpoint-budget lock alone, but
MUST release it before acquiring publication/bank/builder locks. Never hold the
bank, publication or endpoint-budget lock over HTTP/model work; the namespace
builder lock may retain single-builder ownership across that work. The private
ownership/port lock is a
separate leaf; no holder may acquire any listed lock while holding it, nor nest
it with the endpoint-budget lock. No reader or builder may acquire a preceding
lock while holding a later lock. These are new #256/#257 coordination seams.
The canonical forget/consent operation durably sets
a private read/publication inhibit before its canonical commit. Still holding
the bank lock, it then synchronously takes the publication lock, CAS-bumps the
epoch in the active pointer and fences all prior-epoch journalled candidates.
Only after that durable fence may it clear the inhibit and release the locks.
A failure retains the inhibit and `erasure-pending`, fail closed; only the worker
performs physical disposal. Publication follows the same lock order.
The private inhibit binds its operation ID, pre-commit bank-state digest and
intended canonical commit. At the next explicitly started maintenance/recovery
boundary, the worker or exact forget retry reconciles it under that same lock
order: an unchanged, verified pre-commit state proves no canonical change and
allows clearing; a verified committed change completes the idempotent epoch
fence before clearing. Ambiguous or changed pins leave `erasure-pending`; elapsed
time, a process exit or an agent assertion never clears it.
Until verified reconciliation, semantic reads remain fenced and status reports
the retained inhibit; a stopped runtime does not silently start to clear it.
Enumerate every
affected journalled candidate as well as active and retired generations, including
unpublished and interrupted stores; no old-epoch candidate may publish after
the bump. Readers check the epoch immediately before output and cannot use leases
to delay fencing or physical disposal. Invalidate related vectors, caches,
inferred payloads, graph instances, pointers, snapshots, WAL and owned model logs.
Canonical deletion and derived erasure are separate receipt fields until all
owned persistent copies are verified erased.

### 11.1 Temporal send attribution and owned-copy erasure

The durable epoch bump is the privacy-fence linearization point. The receipt
MUST distinguish canonical commit, fence completion, each admitted transport
attempt, and verified local disposal. The fence MUST prevent new old-epoch
transport admissions immediately; it MUST cancel registered in-flight work
without waiting to fence publication. Unresolved local requests/buffers remain
in the erasure inventory and keep derived erasure pending; provider acceptance
or retention remains separately unknown where not observable. A pre-fence send
MUST NOT be labelled a post-delete resend merely because it appears in a
later observation, nor omitted from the overall disclosure history.

Each experiment observation MUST reference only its own generation/request send
attempt IDs and any explicitly reused vector keys. A whole-run ledger MAY be
retained separately but MUST NOT be copied into each generation's send counts.
A deletion control MUST enumerate all pre-fence owned copies (active, retired,
interrupted/unpublished candidates, copied vector rows, graph/WAL/snapshot and
content-bearing buffers/logs) and record their post-fence disposal independently
of post-fence send absence. New generations MUST omit prohibited rows, and
rebuild/restore MUST consult the current tombstone/epoch rather than old caches.
An old shared vector file retaining a prohibited row fails local erasure even
if no later request sends it. Production journals MUST contain hashes/opaque
identities, never the canary bodies, prompts, tokens or secret values.

These rules correct future accounting; the frozen case-76 failure, original
whole-run send oracle, raw rows and retained `erasure-pending` outcome in §13
MUST remain unchanged. New temporal evidence needs a separately reviewed freeze;
source review of this contract supplies no actual deletion/erasure verdict.

The baseline erasure strategy retires and removes each affected **whole owned
generation store/volume**, then rebuilds currently permitted content. Do not
pretend `DETACH DELETE` compacts WAL/snapshots. AM ownership receipts identify
exact volume/container IDs, directory/owner pins and build UUIDs; no recursive

### 12.1 Deterministic outcome and complete reason mapping

Evaluate only observed, applicable triggers for this operation and selected
domain. Status precedence is: `invalid-request`, `erasure-pending`, `refused`,
`approval-required`, `failed`, `incompatible`, `unavailable`, `stale`, `withheld`,
`clarification-required`, `pending`, `partial`, `qualified`. Choose the first
applicable status, then the first applicable row below having that status;
table order is the deterministic primary-reason tie-break. The two conditional
`over-context`/`runtime-stopped` rows apply only to their stated cases.
No reason is inferred merely from a null field, absent score, inactive source
or an operation phase not reached. All other true coverage evidence stays in
the existing assessment/exclusion/native fields, not a new reason array.

Unless a row specifies an exclusion, it adds none. For semantic execution,
`semantic_status` is the selected status before a permitted literal fallback.
Coverage is `complete` only with complete native recovery, freshly current
source/profile/epoch, a complete qualified-domain score map, verified identity
and processing assurance, and no exclusion other than `capped`. Otherwise it

assessment deficits in that order: unavailable, stale, partial, unverified,
complete. Source currency remains independently observed, never inferred from

MUST retain the observed per-source exclusions and independent fallback prohibition.

required before provider contact. Thus check order cannot hide missing approval
behind a long query or hidden replacement behind an endpoint outage. No
unreachable phase outcome is invented.

MUST NOT change the mode merely because fallback was requested. When semantic
execution ran, effective_mode remains semantic and other freshly qualified safe
primaries MUST be returned subject to the same mandatory-group and result

without hidden metadata. If no safe primaries exist, results remain empty with

return whole-request unavailable/graph-unavailable (or a higher applicable
