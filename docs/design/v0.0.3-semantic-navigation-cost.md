# Proposed primary workflow refinement after measured scale evidence

Existing #98; proposed by codex-root. Technical review required before implementation.
No changed semantic quality claim or standalone provider work.

At runtime/portable bytes identical to a31 (full source84f), blind recall of the
held-out retry question succeeded at10k/50k. At50k the actual helper calls were
12.34s discovery start,13.29s preliminary qualification,13.88s final traced
qualification; four model calls took16.33s. Whole fixture setup/end-to-end161.64s
must not be confused with those ready-bank operation times. All raw evidence is
retained. These are not numeric acceptance/isolated performance claims.

Two avoidable costs exist in the supported in-harness handoff: (1) start fully
parses/validates all records even though it exposes only untrusted root navigation
and an incomplete trace; (2) the first prototype reads bodies through a legacy
qualifier, then does another full qualification after the agent chooses its final
answer. A current observed tool result already has its evaluation time and exact
source labels; an immediate second read does not create continuing authorization.
Writes/consequential changes still revalidate under the actual lock.

Proposed changes:

1. Start is explicitly a **navigation-root and canonical-content fingerprint
   observation**, not complete-bank validity or current guidance. Resolve actual
   identity/scope/Git, refuse unknown locks/markers, stream complete physical and
   canonical hashes with existing finite caps/O_NOFOLLOW/ordinary-file guards,
   check physical aliases/deletion namespace and actual root metadata/routes/
   omission occupancy, then recheck hashes/topology/markers/scope/Git. Disclose only
   the safe bounded root and compact binding. No candidate bodies or claims are
   returned. Record exact hash-read metrics and validation scope; never report full
   bank validity. Later recall/comparison still performs its full unchanged checked
   observation and refuses malformed/unknown/invalidating sources before any usable
   guidance or admission. A broken unrelated record may allow root exploration;
   it cannot yield a successful qualified read or novelty/write proof.
2. Add `am discover node --repo --input TRACE --path INDEX`: read one actually
   connected native index with complete visited-parent hashes, safe bounded regular
   descriptors and actual identity/location/scope/Git/marker checks. Keep selection
   incomplete, add actual node hash, return bounded untrusted node+trace. It does
   not claim complete current inventory without the final global check. Final
   qualification must still compare the initial complete inventory digest. Changed
   unvisited content cannot license use/write merely because visited nodes match.
3. Add `am discover read --repo --input TRACE --request REQUEST --rationale TEXT`
   for recall/comparison intents. The invoking agent declares its plausible source
   selection by meaning from the actual map. Observe selected files' exact hashes
   with bounded ordinary descriptors and retain prior discovered sources. Create
   a completed *plausible-selection* trace using the actual agent rationale, then
   run the existing full current reader or broader comparison operation with that
   trace. Return the exact request/trace and actual qualified response/inspection.
   Do not disclose source bodies before that operation's policy/security gates.
   Every discovered source remains mandatory in comparison. Empty semantic choice
   stays empty in recall. Sharing intent must use the actual governed tri-side
   view; this local convenience must not claim landed-state qualification.
4. The current harness reads the qualified sources, reasons about their meanings,
   then answers from that checked observation or supplies comparison judgments.
   It may broaden navigation and qualify more sources when needed. It must not
   mechanically repeat the identical entire read after every answer decision.
   Changes to sources/context/authority, a write or consequential later use still
   require fresh checks; comparison preview/locked apply remains unchanged. No
   persistent cache, prevalidated body authority, database, daemon, model runner,
   new key or native bank schema is introduced.

The original manual trace inputs remain compatible. A completed trace is an
agent's coverage assertion, not semantic-completeness/factual-truth certification.
The initial snapshot is never accepted as a validated cache. Exact current sources,
all invalidation/visibility/lifecycle/scope/trust checks and write-time revalidation
remain the same. Expose the distinction in help/guides/results so a start/node
success cannot be mistaken for usable memory.

Qualify source/node/unknown marker changes, malformed/unsafe/hidden sources,
empty/untraced selectors, historical-ID correction, mandatory discovered match
coverage, parent-path substitution, raw oversized/FIFO/symlink nodes and actual
preview/locked-apply stale checks. Add a broken-record control showing start's
honest limited observation followed by refused qualification, never a create.
Repeat the fixed blinded workflows and report actual cost/context/IO separately;
do not retrofit a pass threshold. The existing literal performance target keeps
its original scope.

## Required approved recall-output amendment

For recall, the complete observed source trace remains internal. Return the
qualified reader results plus safe incomplete node/navigation state and a
content-free qualification digest. Do not echo newly derived excluded-source
hashes/labels or call a redacted state an exact replayable checked trace/request.
Successful comparison may return its checked request/trace because selected
hidden/unsafe sources already refuse the complete operation. The final full
qualification and locked write checks remain unchanged.
