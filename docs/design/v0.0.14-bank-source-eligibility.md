## Outcome and exclusions

Public validation must not call a bank usable when the complete observation
required by ordinary readers or mediated writers is unavailable. Native canonical
files remain at most 16,384 UTF-8 bytes including metadata; complete inventory
remains at most 65,536 canonical sources and 64 MiB. Existing lower router, record,
request, disclosure, private-operation and semantic requirements remain intact.
No larger caps, ignored sources, reinitialization, layout recovery, automatic
admission, cross-project sharing or new runtime service are introduced.

## Common eligibility boundary

1. Keep `sharing_limits` as the authoritative source for the existing canonical
   byte/count bounds. A small `bank_capacity` module contains only typed capacity
   failures, safe serialization and proposed-map capacity accounting; it imports
   the existing limits and `ContractError`, not filesystem, identity or CLI policy.
2. Retain `bank_observation` as the one complete filesystem observer. Its scan
   enforces physical inventory/type/alias budgets and bounded ordinary-file reads
   before layout/record validation. `observe` retains complete hashes, existing
   native layout validation, omitted-path occupancy checks and final recheck.
3. Replace `bank_contract.validate`'s separate unbounded filesystem reader with
   that observer. It must preserve file-only operation without requiring a Git
   checkout, registration, developer identity, remote access or a private audit.
   `bank_writes.bank_path` already supplies the canonical existing-bank locator
   without imposing those unrelated requirements. Pure format checking remains
   separable from filesystem stability, ownership and semantic admission.
4. Extend observation marker handling only to accept the exact caller-owned
   transaction marker already supported by `bank_contract.validate`. Ordinary
   callers still reject every present unknown marker without reading its body.
   Known marker reads are bounded by the already supplied expected byte length
   plus one, use ordinary no-follow descriptors and require exact equality.
   Transaction markers can contain complete base hash maps: do not replace this
   established allowance with the 4-KiB lock-record bound. Keep the existing
   exclusive-lock, owner and journal protocol; observation does not recover it.
5. Both initial and final observation retain the same owned-lock/transaction
   evidence. Source/topology, bank binding, markers or identity changes cannot
   become successful validation. The public filesystem result identifies complete
   canonical eligibility; proposed-map results identify only native format and
   source-capacity checks, not a stable on-disk observation or semantic truth.

## Intended canonical files

`bank_contract.validate_files` checks complete proposed-map byte/count limits
before returning success, including every complete UTF-8 context/record file.
Do this before a memoized successful result can be consumed. `render` validates
its actual intended files before returning them. Existing native schema and
router/index/record validators retain their lower bounds and responsibilities.

Multi-file writer proposals already pass through `validate_files`; migrate any
normal preview that bypasses it. In particular, single-file `bank_writes.preview`
and `apply` validate the complete intended bank, not merely a request schema or
isolated replacement. Reuse the current bounded observation's bytes/hash pins to
validate that intended map; apply repeats this check under its existing lock
before replacement. This prevents both oversized replacement sources and an
aggregate-excess replacement, without a second unbounded reader or new cache.
Unknown external edits retain existing stale-proposal and preservation behavior.

## Typed capacity failures

Use `BankCapacityError(ContractError)` for only these recognized dimensions:

| Cause | Measurement | Failure path |
| --- | --- | --- |
| `bank-source-byte-capacity` | Complete source UTF-8 bytes | That canonical bank-relative file |
| `bank-aggregate-byte-capacity` | Complete-bank observed/proposed byte count | The file crossing the bound, or `.` for the complete map |
| `bank-source-count-capacity` | Canonical source count | The observed excess source, or `.` for the complete map |

The safe public details contain the fixed `bank-eligibility` phase, code,
canonical relative path, actual limit, observed amount, unit, and explicit
`exact` versus `at-least` measurement. In-memory complete maps provide exact
counts. A stable descriptor may supply an exact oversized-file size without
reading that body; bounded evidence otherwise supplies only a truthful lower
bound. Partial inventory counts must not be presented as exact bank totals.

Descriptor/type checks and source stability must precede a capacity verdict for
that source. Revalidate its named file and opened parent bindings before using
an exact descriptor measurement, so a replaced link/file is not certified from a
stale descriptor. A changed, unsafe or unavailable source keeps its existing
non-capacity refusal. An oversized source need not be structurally or semantically
valid; the error must not claim it otherwise passed validation. No memory body
or arbitrary caught exception text is added to capacity diagnostics.

Repair text preserves canonical files, features, original index/HEAD and recovery
records; reports capture/ordinary recall pending; and states that this runtime
has no supported source-preserving layout-recovery command. It never proposes
truncation, deletion, selectors that skip evidence, larger normal caps, or
initialization over existing data. Repeating the same operation is not repair.

## Public operation propagation

Add the same explicit typed-capacity serialization at the public boundaries
that consume normal bank observation or intended-map validation: bank validation,
layout/state inspection, single/multi-file writes, discovery, retrieval,
comparison, admission, checkpoint, initialization, identity/scope binding,
assembly, governance/consolidation, and sharing/publication/refresh where those
paths observe a canonical bank. Existing schemas and operation-specific
mutation/assessment/pending facts remain authoritative. Do not add success,
empty-result, no-learning or novelty fallbacks.

Capacity is a known safe error, unlike arbitrary input exceptions. Preserve it
through intermediate catch/reclassification sites instead of losing it to a
generic source-change, identity, stale-review or empty-result response. Doctor
retains the same details in its failed check/error envelope while remaining
read-only. Keep all other failure classifications and sanitization unchanged;
no broad raw-exception disclosure or generic exception-chain guessing is needed.
A required-error-surface audit and source-bound public scenarios must verify this
migration, including scoped selectors and an unchanged small capture candidate.

## Acceptance and preservation

Keep consumer-visible deterministic regression cases in existing contract-test
conventions. Delete wording/incidental-implementation assertions rather than
re-pin them. Do not use mock forwarding or source-text assertions as acceptance.

The actual frozen candidate must exercise disposable public operations on macOS
and Linux within the existing per-test duration budget:

- Otherwise valid native contexts at exactly 16,384 and 16,385 UTF-8 bytes; full
  and unrelated-path inspection/recall, validation, discovery and a small capture
  request agree on eligibility while retaining different semantic guarantees.
- A larger synthetic source using the reported 79,054-byte size; its descriptor
  size is measured honestly and no original reported content is needed.
- Real aggregate/count excess plus deterministic focused boundary tests. Never
  infer full layout validity merely from a capacity result or a size-only check.
- Renderer and single/multi-file preview/apply refuse oversized intended sources
  and aggregate excess before canonical mutation.
- Within-bound unsupported root layout remains a layout failure. Symlinks,
  special files, changing named/parent bindings, unknown locks/transactions and
  stale source observations remain non-capacity negative controls.
- An ordinary owned multi-file transaction, its exact retry and interrupted
  recovery still validate their exact owned marker, including a marker larger
  than the lock-record bound. Unknown markers never gain this allowance.
- No canonical body appears in diagnostics; no selector bypass, empty successful
  recall, fabricated capture/admission, terminology inference or nonexistent
  recovery command is reported. Preserve exact bank/feature bytes and original
  index/HEAD on read-only diagnosis or pre-write refusal, plus recovery evidence.

Retain original failures and failed qualification attempts. After smoke proof,
update the existing offline/layout/recall/diagnostic contracts and user-facing
release notes to teach the complete per-file limit and truthful pending path.
Independent implementation acceptance must bind the exact candidate and proof.
