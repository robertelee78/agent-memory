# #244: exact governed output before independent coverage review

Status: implementation candidate for the existing [ADR-0010 recovery amendment](../adr/0010-memory-bank-file-contract.md#amendment-source-preserving-layout-recovery), not a new architecture approval or release claim. Required exact Opus5.5 review is blocked by recorded provider HTTP429; no substitute verdict. Source-specific runtime observations and their limits are recorded in the release qualification evidence.

## Why

An independent recovery-coverage review binds the complete intended canonical output. Maintenance previews formerly generated a fresh operation UUID and event timestamp after that review, changing record versions, event paths and router bytes. The reviewed hash could not match. Prospective full claims also need the actual future record version/hash; requiring those claims before generating output creates a circular workflow.

Read-only planning therefore precedes final output/coverage review. It does not waive source qualification or turn an unreviewed judgment into a write proof.

## Phase and authority boundary

1. Read current canonical matches and the complete applicable private frontier through ordinary comparison inspection. Form the existing closed semantic judgment. Every pending row is present, with `coverage:none` while planning; the session MUST NOT fabricate an approval for unseen future output.
2. Run `compact plan` or `govern plan` with that judgment and the real capture/authority/context. Fresh inspection plus pure `comparison.judge` checks current source identity, complete decisions and semantic routing. Existing target, lifecycle, provenance and qualification rules still apply. This stage emits only a detached private output plan, `proposal:null`, `verified:false`, and `coverage_review_required:true`.
3. A distinct reviewing session examines complete source context and the actual `output_plan.files`. It supplies the final full/partial/none mapping, including future record IDs, versions and exact hashes, then uses ordinary `compare review` to obtain the full independently bound comparison-v2 proof. Complete-union and prospective-capacity rules remain unchanged.
4. Run final `preview --plan` with the ordinary proof-bearing request. Reuse only the plan's operation UUID/time; rebuild from fresh actual source and authority, compare the entire base/output and planning identity, then run the unchanged authorizing transaction/coverage validators. Only this successful stage emits an apply-capable proposal.
5. Apply through the existing governed transaction. Under-lock and final source/frontier/policy checks remain authoritative. A unit resolves only after the actual matching canonical receipt and ledger linkage. Historical apply retry is distinct from trying to re-preview a stale plan.

Plans MUST NOT be accepted as proposals. No caller-controlled permission or ignore-validation flag exists. Contradiction, ambiguity, nonqualified targets and deferred operations cannot acquire a plan that authorizes a write.

## Public inputs

| Surface | Planning input | Final preview input |
| --- | --- | --- |
| `compact` | Exactly `comparison_request`, `comparison_judgment`, `capture`, `context` | Existing `comparison_request`, `comparison_proof`, `capture`, `context`, plus `--plan` |
| `govern` | Existing governance fields; nonnull `comparison` is exactly `{request,judgment}` | Existing governance fields; nonnull `comparison` is exactly `{request,proof}`, plus `--plan` |

The planning judgment uses the existing observation/decisions/pending_decisions/rationale structure, not an authorizing proof. The prototype proof-bearing plan request is not a compatibility alias. Normal unplanned preview remains valid where its existing contract can be satisfied.

For unheld governance, `comparison:null` remains meaningful where the operation requires no comparison. Held planning requires complete current frontier judgments. Deactivation/deletion may carry read-only comparison only for the nonempty pending frontier and exactly unchanged target metadata/body; capture/replacement remain forbidden. This does not permit new guidance through a revocation request.

## Detached plan schema and binding

`agent-memory/governed-output-plan-v1` is a closed private object:

- `schema`, `operation`, canonical `repo_root`, `project_id`;
- canonical `operation_id`, nonfuture `recorded_at`;
- `request_input_sha256`, complete `observed_hashes`, complete intended `files`.

The planning-only request fingerprint fixes candidate/source observation, semantic classifications/rationales, derived targets/disposition and other consumer fields. It excludes only the final coverage-review digest and each prospective `coverage_claim` fragment, allowing real mapping after the output is visible. It is NOT a comparison authorization digest.

The existing authoritative `recovery_frontier.proof_input`, independent review validation and `layout_resolution.claims_for` remain unchanged: final proof hashes bind every actual claim, source/frontier token and review; full output hashes and target identities/versions/content must match the actual proposal. Excluding late claims from a nonauthorizing planning fingerprint supplies no capacity credit or permission.

Final preview checks the same operation, root, project, UUID/time, original base hashes and every intended file byte. A changed request meaning, stale source, foreign identity or edited plan fails. A plan is detached, unauthenticated data; fresh actual qualification and final proof checks—not the file itself—authorize effects.

## Privacy, bounds and failure behavior

Plans always require checked `--private-output`. An explicitly requested private destination is honored even without pending units, for comparison and governed preview as well. Stdout contains only the private-artifact summary, not the planned files or private claims. Omitting the required destination or supplying an unsafe/existing-conflicting path refuses; there is no stdout fallback.

Existing request, private-artifact, ordinary bank/proposal, security and writer bounds remain unchanged. The plan reader uses the existing 512-MiB private-artifact allowance; producing a plan does not raise final apply limits. No canonical schema, provider, permission, model, daemon, network or omp setting changes.

Unsupported filesystem metadata remains pending rather than being stripped or exempted. Supported metadata is preserved through the current descriptor-bound recovery protocol. Platform qualification and exact independent review remain separate gates.

## Implementation seams

- `comparison.inspect`/pure `judge`: source-bound planning observations and classifications, not final coverage authorization.
- `consolidation`/`governance`: private planning construction; normal inspection/preview/apply continue full proof validation.
- `layout_resolution`: purpose-limited plan schema, context and exact rebuilt-output checks; unchanged final claim/receipt authority.
- `recovery_frontier.private_preview` and comparison CLI: checked private disclosure, including an explicitly requested destination without pending units.

Permanent consumer regressions retain the original update/consolidation/governance scenarios. Update maps a complete unit to the future planned version/hash and can resolve it only after actual apply; the other routes retain none-coverage controls. Plan tampering, foreign bases, unauthorized direct apply, missing private destination and ordinary-bank confidentiality are negative boundaries. These are behavior requirements, not source-text or fixed-clock/UUID tests.
