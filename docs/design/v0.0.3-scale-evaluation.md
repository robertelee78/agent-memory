# v0.0.3: growing-bank recall and daily-use qualification (#98, #99)

Status: proposed evaluation and repair boundary. This document does not approve
implementation, loosen existing safety requirements, choose performance tolerances
for the operator, or claim that a required workload passes.

The [measured sharing-capacity RCA](../research/2026-10-24-growing-bank-sharing-capacity.md)
shows a real blocking path: small structurally valid banks can be recalled by a
literal query while the complete semantic sharing operation refuses. Increasing
one constant would leave other limits and all-pairs work intact. #99 owns usable
sharing/recovery at the required workload; #98 separately owns retrieval quality
and cost curves. Neither a bigger bank nor a successful exact lookup closes both.

## Fixed evaluation before optimization

Use the actual published v0.0.1 commit as the baseline and an immutable candidate
as the comparison. Qualify each with its own installed public operations in
separate disposable homes; do not change version declarations, transplant current
implementation into the baseline, or call an internal function in place of the
public reader. Preserve identical canonical fixture bytes and logical ground
truth across versions, while keeping their local developer/binding state isolated.
Record every source/portable artifact hash, fixture hash, query/request, observed
Git context, selected record ID/version and exclusion reason. A failed operation
is unavailable, never a successful empty answer or a zero inventory.

The initial labeled suite will contain at least these distinct cases:

| Case | Expected qualified result |
| --- | --- |
| Exact record ID | The actual current applicable version |
| Exact path | The current safe applicable record at that path |
| Literal identifier and multiple query terms | The labeled relevant lesson, with bounded distractors |
| Natural-language paraphrase with shared terminology | The relevant lesson; measure missed recall |
| Paraphrase without shared terminology | Measure the actual workflow gap; do not give the reader an oracle expansion |
| Two equally relevant lessons | Both labeled lessons, retaining their separate provenance |
| Matching text under an inapplicable component | Excluded, without leaking its body |
| Unknown prerequisite or session condition | Excluded until actual evidence supplies that condition |
| Staged/working code differs from HEAD | HEAD observation does not certify working code applicability |
| Stronger correction with different wording | Obsolete version excluded even when its replacement misses the query |
| Hidden or unsafe qualified replacement | Old claim stays invalidated; unsafe replacement body withheld |
| Expired/revoked/superseded record | Excluded from current guidance |
| Similar but distinct conditions | Do not collapse into a universally applicable lesson |
| Duplicate candidates with distinct evidence | Retrieve matches for comparison; preserve evidence and provenance |
| Cleanly mergeable yellow/blue disagreement | Conflict remains together for the detecting developer |
| Mixed orientation and typed guidance | Orientation labeled separately; no invented trust |
| Unsafe/secret-bearing source | Withheld as a whole, with no disclosure in result diagnostics |
| No relevant current lesson | Explicit successful empty selection, if the bank itself is valid |

Labels must be reviewed against actual source metadata and approved project
intent before optimization. Lexical retrieval, agent-assisted query reformulation
and semantic judgment are different measured workflows. A fixture-aware scripted
oracle must not be called a harness's semantic understanding or counted as
independent evidence that a new paraphrase will work. Keep query wording and
labels fixed as realistic distractors are added; retain known misses.

Run sizes 1,000, 10,000 and 50,000 distinct durable lessons, not merely that many
files. Use valid hierarchical routes with bounded individual routers and realistic
record lengths, duplicates, corrections and conditional facts. Record actual
canonical/selected bytes and record-length distributions. Measure tokens only
with a named, versioned tokenizer; absent tokenizer measurements remain unavailable,
not a guessed conversion from bytes. Separate cold/warm observations and record
hardware/interpreter, complete-bank I/O, latency, recall and context size.

Before a performance pass, publish baseline curves and proposed numeric tolerances
for operator review. Unsafe, stale or incorrectly applicable guidance has a zero
allowance; missing a relevant safe lesson remains a quality defect rather than a
safety exception. Quantitative recall/latency/context/cost thresholds must be
agreed from the data. Do not invent them after seeing candidate outcomes.

## Required daily-use scenarios

The required representative case is 12 sessions/1,000 lessons; the required stress
case is 24 sessions/10,000 lessons. Vary session count and bank size independently.
48 sessions/50,000 lessons together remain exploratory, while 50,000 lessons still
belong in the retrieval curves. Model independent machines with independent clones,
two developer IDs and harness labels, all sharing one repository/project UUID.
Every programming session has its own worktree or branch. Same-physical-bank lock
tests are defensive controls and cannot substitute for the primary workflow.

Exercise concurrent compatible edits and same-file conflicts, cross-file semantic
contradictions, duplication/consolidation, offline publication and return, changed
main between preview/apply, process loss, receipt loss, pending review, and later
ordinary feature integration. At every stage compare canonical path bytes/modes,
record identities, conditions, evidence/history, feature code, index, HEAD and
branch. Read-back from a peer must qualify imported guidance against that peer's
actual code/scope; importing memory must not advance feature ancestry.

Measure publish/refresh convergence, useful recall after recovery, pending versus
fresh reporting, repeated failure/retry counts and operator effort. A refused safe
operation preserves data but is not a usable sharing pass at the required workload.
Use the available local macOS/Linux hosts and bounded owned-process cleanup. Keep
raw failures and source-specific receipts. No intensive hosted CI matrix is needed.

## Repair obligations from the measured capacity defect

The implementation design must address the whole pipeline: complete canonical
inventories and Git reads, semantic component/review construction, proof inputs,
publication/refresh plans, private recovery records and current peer recall.
Do not claim success by raising only the 256-file or 64-component bound.

A bounded paginated or incremental design is eligible only if it accounts for
all sources and relevant changed meanings. It must preserve cross-file conflicts,
source-version binding, route/applicability changes, corrections/invalidation,
provenance and uncertainty. Uninspected sources cannot become proof of absence.
A missing page, changed main, incomplete judgment or invalidated baseline must
leave the operation pending/refused rather than fresh. Scope/topic ranking alone
must not silently discard a plausible contradiction. Derived state must remain
rebuildable, project-bound and disposable; it cannot replace canonical Markdown.

An incremental design must explicitly distinguish reviewing incoming/local changes
against existing memory from a complete audit of previously unchanged memory.
Reusing a source-bound decision is different from assuming an unreviewed pair was
compatible. Initial adoption, lost baselines, route condition changes, deletions,
newer learning during recovery and independent machines with no local cache need
specific correctness paths before approval. A full-bank audit remains available
when internally conflicting evidence calls for a PM clarification round.

Any revised semantic coverage contract needs an independently reviewed technical
design and an ADR-0012 refinement before production code changes. The two open
stories retain their original requirements and delivery intent. This proposal
neither marks them Ready nor turns design research into execution acceptance.
