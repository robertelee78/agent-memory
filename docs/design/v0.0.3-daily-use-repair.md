# v0.0.3: usable sharing at the agreed daily-use workload (#99)

Status: proposed technical design; not implementation approval or a stress pass.
Existing work key: `robertelee78/agent-memory:ADR-0009:daily-use-reliability`.
The [capacity RCA](../research/2026-10-24-growing-bank-sharing-capacity.md) and
[agreed evaluation boundary](v0.0.3-scale-evaluation.md) remain authoritative
observations and qualification scope. No new workload or performance tolerance
is invented here.

## Repair the complete path

The current helper copies the whole local/landed corpus into one semantic review,
requires every possible pair, and refuses above 64 components/64 KiB. Its Git reader
also starts two processes per file. Other 1 MiB/4 MiB limits refuse larger snapshots
and plans. Safe refusal preserves files but does not satisfy the agreed usable
12-session/1,000-lesson and 24-session/10,000-lesson workflows.

ADR-0012 requires searching/reading plausible matches, examining cross-file
meaning, preserving conditions and asking the detecting developer about actual
conflicts. It explicitly does not promise perfect contradiction detection. Reuse
that product boundary and the existing admission comparison workflow rather than
certify compatibility of every unchanged pair in the repository on every turn.

## Versioned changed-learning review

Keep the current v1 proof reader for existing bounded callers. Introduce a
separately identified v2 sharing review and update the companion skill to select
it. Old helpers must refuse unknown proofs; native Markdown remains
`agent-memory/v1`, with no implicit data migration or required database.

Each review pins complete actual base/local/landed inventories, project identity,
Git observations and effective route framing. Detect changed learning by body,
meaningful typed metadata and inherited conditions, not file timestamps or a
router observation-time change alone. Changed read triggers/purposes/conditions
must include their affected payload in the review boundary. Preserve all original
source hashes/provenance even when a change is not a new semantic assertion.

The agent must search and read plausible existing matches for changed learning,
using multiple ordinary-text searches and explicit IDs/paths as in admission
comparison. Concurrent versions of one component, explicit correction/deletion
relations, changed framing and sources explicitly named by the agent are required
inputs. Cross-file matches must not depend on a Git textual conflict. The search
result is comparison-only, never current guidance or proof of semantic truth.

A v2 review records its actual changed set, search/read selectors, complete
selected-source set and source-bound classifications. The helper must bind that
selection to complete current inventories and reject stale/missing judgments.
It must not label unreviewed old pairs compatible or claim a complete global
consistency proof. The agent remains responsible for a defensible plausible-match
search, including paraphrases; a lexical miss is not an independent semantic
absence certificate. An uncertain selection or known unresolved match must keep
the affected update pending and surface the question rather than invent novelty.

Do not rank away selected sources to meet a context limit. Page the complete
selected set into bounded responses and require every selected interaction before
sealing its proof. Keep identifiers/hashes and decisions distinct from source
bodies; do not duplicate a complete bank in each response. A lost page/review
artifact is disposable: observe/review again, never lose canonical learning.

The same existing conflict classes, actual non-overlap checks, explicit dependency
holds and provenance-preserving consolidation rules apply. Preserve both claims
and attribution; ask the detecting developer and recommend contacting another
originating developer when needed. No automatic messages, recency winner or
blanket block on independent updates. Unknown/unsafe/hidden plausible evidence
must not be treated as absence. Terminal deletion and stronger qualified
invalidation still prevent resurrection.

## Complete bounded data movement

Inventory all bounds used by snapshot, semantic review, publication, refresh,
transactions, recovery and private inputs. Distinguish complete-data limits from
agent disclosure limits. Retain 16 KiB per canonical source; support a complete bank
up to 65,536 files/64 MiB, sufficient for the agreed workload and measured 50,000-lesson
fixture. These are explicit finite resource budgets, not a claim that arbitrary
payloads are safe or that capacity is retrieval quality.

Read actual Git trees/blobs through bounded batch Git operations, checking type,
size, exact byte count, path topology and complete inventory. Do not fetch into
feature history or silently skip a missing/oversized blob. Complete bank data and
large private plans belong in owned private artifacts with concise summaries;
page actual review context. Do not load every lesson into every agent turn.

Reuse the existing source-bound transactions, native replacements, private
journals/backups and memory-only Git publication/refresh. Keep source observations
fresh under existing locks; changed authority/source/scope requires reconciliation
before retry. Never import feature ancestry/code/index edits, force a ref, restore
a deleted lesson from an old branch or claim remote freshness while offline.
No shared mutable memory database, personal store, MCP, daemon or harness API is
introduced. Any later recall accelerator is separately derived and disposable.

## Qualification before acceptance

Use the existing World/independent-clone apparatus and real public commands.
Every programming session has its own worktree/branch, independent clones model
machines, two developer identities and harness labels share one repository UUID.
The required 12/1,000 and 24/10,000 cases must actually exchange useful memory and
recall it after recovery. Existing same-tree lock tests are defensive only.

Exercise compatible independent and same-file edits, cross-file yellow/blue
conflict, duplicates/conditions, prune/correction and older-branch nonresurrection,
offline return, stale authority between preview/apply, interruption/lost response,
lost private state and later ordinary feature integration. Compare exact canonical
paths/bytes/modes, identities, provenance, bank usability, source/index/branch/HEAD
and pending/fresh reports at each transition. Preserve raw failures; distinguish
fixture/apparatus failure from a product refusal or missing useful recall.

Use a fixed scripted fixture judge only to supply declared known fixture meanings
and test mechanical binding/convergence; do not call it an agent's semantic
understanding or a general contradiction detector. Independent review must check
selection completeness for those labeled scenarios and try a deliberately omitted
known cross-file match. Missing selected comparisons, stale pages and altered
framing must refuse. Unrelated memory must remain independently useful.

Measure elapsed work, complete-bank I/O, retries, recovery steps and useful peer
recall; publish data rather than invent a latency pass. #98 separately owns fixed
query quality/context/cost curves and operator-reviewed quantitative targets.
The 48/50,000 combined contention case remains exploratory. Run qualification on
local macOS/Linux, with fixture-only remotes/identities and bounded owned cleanup.
