## Repair the complete path

The current helper copies the whole local/landed corpus into one semantic review,
requires every possible pair, and refuses above 64 components/64 KiB. Its Git reader
also starts two processes per file. Other 1 MiB/4 MiB limits refuse larger snapshots
and plans. Safe refusal preserves files but does not satisfy the agreed usable
12-session/1,000-lesson and 24-session/10,000-lesson workflows.

ADR-0012 requires searching/reading plausible matches, examining cross-file
meaning, preserving conditions and asking the detecting developer about actual
conflicts. It explicitly does not promise perfect contradiction detection. Reuse
that product boundary and the existing admission comparison workflow rather than
certify compatibility of every unchanged pair in the repository on every turn.

## Versioned changed-learning review

Keep the current v1 proof reader for existing bounded callers. Introduce a
separately identified v2 sharing review and update the companion skill to select
it. Old helpers must refuse unknown proofs; native Markdown remains
`agent-memory/v1`, with no implicit data migration or required database.

Each review pins complete actual base/local/landed inventories, project identity,
Git observations and effective route framing. Detect changed learning by body,
meaningful typed metadata and inherited conditions, not file timestamps or a
router observation-time change alone. Changed read triggers/purposes/conditions
must include their affected payload in the review boundary. Preserve all original
source hashes/provenance even when a change is not a new semantic assertion.

The agent must search and read plausible existing matches for changed learning,
using multiple ordinary-text searches and explicit IDs/paths as in admission
comparison. Concurrent versions of one component, explicit correction/deletion
relations, changed framing and sources explicitly named by the agent are required
inputs. Cross-file matches must not depend on a Git textual conflict. The search
result is comparison-only, never current guidance or proof of semantic truth.

A v2 review records its actual changed set, search/read selectors, complete
selected-source set and source-bound classifications. The helper must bind that
selection to complete current inventories and reject stale/missing judgments.
It must not label unreviewed old pairs compatible or claim a complete global
consistency proof. The agent remains responsible for a defensible plausible-match
search, including paraphrases; a lexical miss is not an independent semantic
absence certificate. An uncertain selection or known unresolved match must keep
the affected update pending and surface the question rather than invent novelty.

Do not rank away selected sources to meet a context limit. Page the complete
selected set into bounded responses and require every selected interaction before
sealing its proof. Keep identifiers/hashes and decisions distinct from source
bodies; do not duplicate a complete bank in each response. A lost page/review
artifact is disposable: observe/review again, never lose canonical learning.

The same existing conflict classes, actual non-overlap checks, explicit dependency
holds and provenance-preserving consolidation rules apply. Preserve both claims
and attribution; ask the detecting developer and recommend contacting another
originating developer when needed. No automatic messages, recency winner or
blanket block on independent updates. Unknown/unsafe/hidden plausible evidence
must not be treated as absence. Terminal deletion and stronger qualified
invalidation still prevent resurrection.

## Complete bounded data movement

Inventory all bounds used by snapshot, semantic review, publication, refresh,
transactions, recovery and private inputs. Distinguish complete-data limits from
agent disclosure limits. Retain 16 KiB per canonical source; support a complete bank
up to 65,536 files/64 MiB, sufficient for the agreed workload and measured 50,000-lesson
fixture. These are explicit finite resource budgets, not a claim that arbitrary
payloads are safe or that capacity is retrieval quality.

Read actual Git trees/blobs through bounded batch Git operations, checking type,
size, exact byte count, path topology and complete inventory. Do not fetch into
feature history or silently skip a missing/oversized blob. Complete bank data and
large private plans belong in owned private artifacts with concise summaries;
page actual review context. Do not load every lesson into every agent turn.

Reuse the existing source-bound transactions, native replacements, private
journals/backups and memory-only Git publication/refresh. Keep source observations
fresh under existing locks; changed authority/source/scope requires reconciliation
before retry. Never import feature ancestry/code/index edits, force a ref, restore
a deleted lesson from an old branch or claim remote freshness while offline.
No shared mutable memory database, personal store, MCP, daemon or harness API is
introduced. Any later recall accelerator is separately derived and disposable.

## Minimal v2 wire contract

The existing `semantic` public command gains explicit `inspect-v2`, `page-v2`
and `review-v2` operations. Existing `inspect/review/check` v1 requests keep their
present interpretation and bounds. Publication, refresh and recovery dispatch on
an exact proof schema; an older installed reader must refuse v2. The common CLI
continues forwarding to the same portable helper. No service is introduced.

`inspect-v2` observes the sources and produces a private review manifest. A small
request contains the optional actual Git base and per-change search selectors;
absence of selectors means an initial discovery pass, not a publishable proof.
The manifest contains:

- schema, complete original observation/binding, three inventory digests and
  exact path/hash maps, and a digest of this complete manifest;
- stable component references `{key,path,component,target_path,sides,source_hashes}`,
  derived changed references, required selection entries and mandatory edges;
- one selection entry per changed component with its ordinary-text searches,
  explicit record-ID/path selectors, complete matched references and their digest;
- a sorted canonical required edge list, selected source/page manifests and
  `semantic_completeness_verified:false`.

Logical component identities retain path/component/target (and typed record
identity where present), separately from comparison endpoint identities. Each
comparison endpoint MUST include a digest of its meaningful body/metadata plus
complete effective inherited framing. Exact side source hashes remain separately
bound. Equal prose under different scopes, purposes, lifecycle or inherited
conditions therefore has distinct semantic-variant endpoints and a mandatory
concurrent-variant edge; it MUST NOT collapse into a self-edge and disappear.
Only truly identical semantic variants may share an endpoint across sides.
Comparison uses
complete comparison-only source bodies, metadata and effective framing, not the
current-guidance reader's visibility, lifecycle, query, trust or applicability
filters. Search semantics reuse the existing admission comparison behavior; the
old 64-match/64KiB total-result cap does not apply to the v2 selected inventory.
Metadata IDs, legacy capture owners and explicit lifecycle links remain matches.
A selector cannot delete a mechanically mandatory source. Broad matches produce
more pages; the skill must not narrow them merely to discard inconvenient claims.

For each changed component C, let M(C) be its complete selector match set plus
mandatory related references. The helper derives the exact edge union
`{sort(C,X): X in M(C), X != C}`, including relationships between two changed
components whenever selected or mandatory. It does not require all-pairs among
old selected matches, nor among unrelated changed components. Mandatory edges
include concurrent actual variants of the same body/framing component; exact
record ID/version, correction/supersession/tombstone/capture-owner links; and
explicit source/dependency/consolidation relationships. Existing container and
same-file merge code must find its concurrent edge in this derived set.

A selection entry must explicitly state that the agent completed a plausible-match
review, or mark that change uncertain. An empty match list is permitted only with
its actual nonempty searches and this explicit agent assertion; the result does
not certify semantic absence. Every changed source itself must be read even when
it has no edges. Empty delta can yield an empty review with source/freshness
qualification; it is not an audit of unchanged lessons. Explicitly named existing
sources can start a separately identified full-bank audit/clarification review;
it uses the same paging machinery and states its actual coverage, without
pretending that an incremental empty-delta proof performed that audit.

`page-v2` returns at most 64KiB of complete source/edge material per response.
The manifest fixes stable ordering, exact membership/count, per-page serialized
size/hash and complete source/edge digests before page disclosure. Oversized
individual source evidence is refused rather than truncated. The agent's judgment
contains the complete manifest binding, exact acknowledged page hash set, one
classification/reason for every required edge, dependencies, consolidations,
selection assertions, overall rationale and recorded time. `review-v2` reconstructs
actual sources and selection/page manifests, rejecting missing/duplicate/unknown
references, altered versions, mixed observations, stale/omitted pages or edges.

The classifications are exactly the existing classes. `disjoint-conditions`
requires actual known non-overlap for every scope variant; `lifecycle` requires
actual retained links; same-axis equivalent active typed records require an
explicit consolidation retaining all conditions/evidence/provenance. Contradiction
and uncertainty hold both actual components and dependent navigation/payloads.
The proof retains exact refresh/publish hashes, blocked components/paths and the
complete original judgment. Applying it reruns all source and classification
checks under the existing observed transaction boundary. No supplied edge list
or prior page can grant authority independently.

## Delta closure, baseline and dispute continuity

The helper derives changes from the actual three sides; the agent cannot submit
a smaller changed set. For every side it builds the complete effective ancestor
framing of each component: introductions, route purpose/read triggers, navigation,
scope, lifecycle and omissions. It compares canonical body/meaningful metadata
and this effective framing to the actual base. Changes include additions/removal,
ID/version/path movement, correction/supersession/tombstone/capture links and
changed ancestor framing. Descendant closure is transitive even when descendant
file bytes are identical. Timestamp-only router/index/record updates do not alone
create new meaning; their exact original hashes remain in the source binding.
Deletion witnesses and version links remain inputs even without a displayable
current body. A changed parent must not become a single harmless framing row
while silently omitting its children.

First use/fresh clone reconstructs a unique actual Git common base, as today.
Existing authority memory at that base is existing learning, not an automatically
certified consistent bank; new/local/landed differences still receive review.
An empty bank is allowed only when actual history proves first initialization.
An absent, ambiguous or rewritten base returns actionable pending reconciliation;
never choose an empty base or silently skip imported deltas. Explicit bases must
be actual authority ancestors and correspond to inspected source evidence.

Disposable page loss requires reconstructing the same manifest or observing and
reviewing again. A refresh with unresolved holds must not advance its reusable
baseline past those holds. Retain the prior safe base and source-bound blocked
components in the completed transaction evidence; cursor loss must consult that
evidence before reusing a newer base. A changed checkout or lost/corrupt transaction
readback cannot license old held guidance: reconstruct actual differences and
re-review, with freshness pending until completion. Independent updates may still
be imported/published through a proof that retains the held closure. Lost original
transaction journals/backups are not disposable page loss and use explicit recovery.

Already-known internally conflicting unchanged claims require explicit audit input
and continued held-state readback. If all local evidence of an unresolved audit is
lost, the helper cannot claim that no dispute existed; report unknown semantic
history and require a renewed audit before claiming it resolved. Remote observation
can be current while semantic work is pending. The skill must not translate either
fresh Git data or an empty incremental delta into a universal conflict-free claim.

## End-to-end resource and replay inventory

The raw complete bank budget is 65,536 files/64MiB, individual source 16KiB.
These are proposed resource budgets, not demonstrated universal capacity. The
measured fixed 50,000-lesson fixture must be checked against them; increase a
finite budget with explicit evidence if that fixture exceeds it. Git tree listing
has a separate 16MiB bound. Batch object transport is bounded by the complete raw
budget plus exact framing overhead, verifies returned object ID/type/length and
trailing delimiters, and validates every canonical bank mode as ordinary 100644.
No skipped blob, executable/symlink bank object or configured-root alias is allowed.
Linked worktrees retain their actual Git index/common-dir and configured bank root.

Private whole-operation JSON (semantic manifest/proof, publication/refresh proposal,
transaction journal/receipt and replay readback) has a separate finite 512MiB
encoded ceiling. It is checked on actual bytes before parsing/writing; raw-bank
capacity is never substituted for encoded capacity. Three sides, before/after,
hash maps, escaping and retained backups are counted separately. Where a combined
object exceeds this ceiling, return an explicit capacity diagnostic and retain
canonical/private recovery evidence; do not truncate or claim a workload pass.
Agent-facing input selectors stay 64KiB and each disclosure page stays 64KiB.
Existing publication 1MiB, refresh 4MiB, semantic 1MiB and cursor/receipt 64KiB
whole-operation readers must dispatch to the correct v2/large-inventory budget;
small replay selectors remain 64KiB. An upgraded proof must not be admitted by a
legacy v1 reader through an unmarked larger envelope.

Use existing private file/parent ownership, atomic replace, locks, journals and
backups for these artifacts. Verify exact size/digest/schema/source binding before
use and final complete source/scope/index/head/authority observations at apply.
A complete artifact is not sent as every agent response: public operations may
write an explicitly selected owner-only output file and return its digest/size
and concise outcome; page-v2 discloses only its fixed pages. No required persistent
index or custom artifact service is needed. A changed remote/local/scope requires
new reconciliation. Completed replay verifies original landing/readback, reports
whether it is still current and never reapplies it over newer learning. Preserve
original transaction evidence while reconstructing optional review pages.

## Finite workload schedule and negative matrix

Use schedule family `daily-use-v1`, with fixed authored relationships and exact
expected path/version/source outcomes before the implementation runs:

1. Seed the valid shared bank and feature revision in a fixture-only bare authority.
   Create N separate session worktrees over at least three independent clones,
   alternate two developer identities and Claude/Codex/OpenCode/custom labels.
   Every session stages its own unrelated feature edit; record index bytes/HEAD.
2. Every session captures one distinct compatible authored lesson on its own branch.
   Observe/review all N previews before publication, then publish in fixed ascending
   order; stale plans must reconcile and retry. Refresh every peer and recall the
   authored peer lessons with unchanged feature ancestry/index.
3. Repeat in reverse session order with a second lesson per session. One pair has
   actual same-file compatible edits; another has separate-file blue/yellow claims;
   another has duplicates with distinct evidence and two disjoint conditions.
   Only the disputed/dependent updates remain held; unrelated lessons converge.
4. Withhold one session offline while the others complete that round; return it,
   reconcile new authority and verify useful fresh peer recall. Lose one completed
   publish response and one refresh response, then read back instead of duplicate
   landing/reapplication. Interrupt an owned transaction at a declared failpoint,
   finish/recover, and verify all original bytes/provenance and staged code.
5. Correct/prune a designated lesson on a later authority, then attempt refresh and
   publication from an older branch. No obsolete resurrection is allowed. Lose a
   cursor/page state, reconstruct the actual review baseline and retain the dispute.
   Finally integrate ordinary feature branches and check memory does not revert.

Run the full schedule for required 12/1,000 and 24/10,000. Controlled independent
variations use 12/10,000 and 24/1,000 for the compatible publish/refresh rounds;
48/50,000 combined remains exploratory. Do not call N serial changes in one shared
worktree N concurrent sessions. Public command invocations may be scheduled in
bounded groups; all N independent pending writers must actually exist.

| Negative | Required result | Independent useful path |
| --- | --- | --- |
| Mandatory/selected edge or page omitted/duplicated | Refuse sealing/apply | New complete review can progress unrelated updates |
| Source/main changes after page | Refuse stale binding, reconcile | Current unrelated memory remains locally recallable |
| Route/condition edit, identical child bytes | Child enters derived changed closure | Unrelated route can converge |
| New clone/lost cursor | Reconstruct actual base and re-review | Compatible changes still exchange |
| Ambiguous/rewritten base | Actionable pending, no fresh claim | Preserve local recall and feature work |
| Later correction/tombstone versus old branch | Preserve terminal invalidation | New compatible lesson can land |
| Hidden/unsafe selected replacement | Hold affected work, no body leak/resurrection | Safe independent source can be used |
| Known held dispute/page loss | Re-review/retain hold; no cursor advancement past it | Unrelated reviewed changes converge |
| v2 proof supplied to actual old v1 consumer | Explicit refusal | Actual new helper can process the proof |
| Unselected semantic paraphrase deliberately missed | Independent label reports a selection-quality failure | Never claim helper detected an unknowable omitted meaning |

The last row is a negative of agent/fixture coverage, not an expected mechanical
refusal of a structurally complete selector proof. Reports must state this limit.
Final #99 acceptance references #98's exact fixed 1k/10k/50k query/byte/context/cost
artifact and approved numeric-target decision; ownership by #98 does not remove
#99's upper-bound quality obligation. Functional sharing convergence and measured
latency are separate claims; no unapproved latency threshold becomes a pass.
