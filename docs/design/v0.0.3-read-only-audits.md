# v0.0.3: supported read-only runtime audits (#171)

Product authority: ADR-0014's accepted safe-read-only-inspection outcome.
Independent technical approval is required before execution.

## Design

The packaged public entrypoints already set `sys.dont_write_bytecode = True`
before importing agent-memory modules. Preserve that behavior and document
public wrappers/helpers as the supported audit surface. Keep the existing
`python3 -I` public-helper examples compatible with older installed verifiers:
the helper's own early guard suppresses bytecode before any product import.
An explicit `-B -I` invocation is also supported by new verifiers and exercised
in source-helper audits, but MUST NOT replace the documented helper prefix while
older supported updaters only recognize `-I`. A custom Python inspection must set bytecode suppression
before importing product modules; `-B` is a complete invocation-level option,
whereas setting the variable after imports is too late. Do not document an
unqualified bare import as read-only inspection.

This is a runtime-artifact integrity contract, not a claim of zero writes
everywhere: canonical bank/config/code remain unchanged, while operations that
declare private audits may write those outside the package. `version`, `status`,
`doctor`, artifact inspection and portable-package validation perform no audit
write or setup. Do not relabel capture, initialization or projection output as
an inspection.

Add explicit focused installed public checks that bind all portable file bytes
and modes before and after repeated supported audits, in both copy/link layouts.
The environment must not pre-disable bytecode for these calls; the packaged
entrypoints must supply their own protection. Exercise the source-helper path
with `-B -I` as documented. Run from a directory outside the source package.
Check the exact artifact inventory, absence of new `__pycache__`/`.pyc`, and
receipt-owned identity rather than filtering cache files out of the comparison.

Unexpected executable cache contents remain drift. Preserve the existing
fail-closed artifact inventory and diagnostic failure. Test this with inert
synthetic `.pyc` bytes added to an isolated installed copy (never a real user
runtime); invoke a trusted outside helper and assert refusal plus byte-identical
preservation of the unexpected bytes, owned source, receipt and bank. Do not
import or execute the injected cache. No new automatic cache cleanup, recovery
permission, chmod, integrity exclusion, or migration is introduced.

The earlier RCA establishes a plausible cache mechanism, not the identity of
the process that wrote the observed caches. Documentation and release evidence
must preserve that uncertainty.

## Acceptance

1. Read every supported helper's early bytecode guard statically; keep this
   bounded source proof separate from actual public execution evidence.
2. Run repeated installed `am --version`, `am version --json`, `am status`
   and JSON status, and human/JSON doctor from isolated healthy copy/link installs
   on macOS/Linux. Public artifact/pack helpers with the documented source
   invocation must preserve the full inventory. The native source checkout's
   changing Git metadata is not a runtime-byte mutation.
3. Retain declared bank/config/receipt snapshots. Prove no bank initialization,
   identity selection, cache cleanup or write probe occurred.
4. Detect and preserve injected unexpected cache bytes through an outside-helper
   audit. Existing drift/update/uninstall rules remain unchanged and their
   applicable proof may be reused with its original source qualifications.
5. Bind the final local cases, source checks and inventory hashes to an immutable
   candidate; no hosted matrix or bytecode-based performance claim is needed.

## Upgrade compatibility correction

The first #171 candidate passed its audit-specific cohorts but changed documented
helper commands to `-B -I`. A later expanded #170 cohort executed the real frozen
pre-am updater and caught its old static verifier refusing those candidate docs
with `Undeclared shell command form`, before activation. This was a compatibility
defect in the #171 candidate, not a reason to weaken integrity checks or replace
the old-process fixture. Preserve the failed evidence and qualify the correction
against actual frozen pre-am and released v0.0.2 updater processes on both local
platforms, in addition to audit preservation and validator checks. Do not present
the earlier audit-only acceptance as release qualification of that broken path.
