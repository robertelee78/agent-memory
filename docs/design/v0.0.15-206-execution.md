## Why and source authority

Recall should remain useful on large same-repository Markdown banks without reducing semantic discovery, relevance, current-source checking or safety. The issue requires separately measured ordinary warm navigation/read and discovery-qualified recall inside actual refresh, source and quality conditions, cold rebuild and full native time excluding model thinking. Keep portable skill/CLI; no mandatory service, vector store, MCP, personal memory, or cross-repository sharing. Direct terminal semantic search and automatic turn-boundary hooks are separately scoped. The issue cites ADR-0005 at `8d2163bd3c6c5555aeaffc175bf2207917572dd8`; implementation/research baseline for this plan is **`33c95bbebef61e3ac6e58c5c59e0d411b6dc63e8`**, extracted from the available Git commit object to `/tmp/agent-memory-v15-readiness/206-source`; the working checkout is not used as this baseline. Implementation must rebind evidence if source changes.

## Operator-selected numerical target

**Operator decision:** after disclosure of the actual 50k no-import measurement, single-sample limitation and failed strict source-after check, the operator selected **at least 20% median improvement in complete 50k navigation and nested discovery-qualified recall during primed, inventory-unchanged 50k refresh**. Navigation improvement is regression restoration; measure a repair-only build separately. Conditions are (1) unchanged-inventory no-import with primed catalog, (2) unchanged-inventory no catalog, (3) import-invalidated with non-discovery recall or typed refusal, and (4) held conflict. Conditions 2–4 must have no more than 10% median nested-recall and whole-apply regression; all fixed quality, safety and preservation obligations remain unchanged. Full five-sample macOS/Linux qualification uses clean source inventories and matched frozen fixtures, retains all failures, and is an acceptance gate rather than a pre-target prerequisite. Current diagnostics do not certify acceptance or establish a production latency promise: the 50k nested recall was 22.128 s of 1338.607 s whole apply, so whole-apply gains cannot be assumed. The prior 480 s review timeout remains retained. <5 s 50k remains a later goal. This target selection is not approval of the full execution design or implementation.

## Correctness and acceptance contract

* Every selected record must preserve scope/project/identity, actual Git context, route and record applicability (including unknown required conditions), trust, visibility, validity at evaluation time, safety, provenance and current source hash; replacement/invalidation/conflict gates apply even for hidden/unsafe replacement. No missed relevant evidence, irrelevant additions, truncated safety data, widened semantic selection or changed fixed-case result to buy speed. `include_context` remains explicitly orientation-only; exact selectors do not bypass gates. Keep finite source/count/byte capacities and typed refusal; a failed/unavailable operation is never an empty success.
* Derived state is optional and nonauthoritative: missing, deleted, corrupt, stale, wrong-project/engine/version, permission-denied, truncated, over-capacity or ambiguous state falls back to a fresh complete canonical read or preserves the existing explicit failure. Catalog authenticity and binding, current bytes/topology/markers, Git/scope, audit, late recheck and time/applicability must still be checked, not replaced by mtime or a stored old judgment. Changed source/authority during observation must refuse or return pending as appropriate; never silently retry into an invented result. Cache loss cannot mutate bank or alter index/HEAD; interrupted writes and competing cache publishers/readers must not expose partial generations. Check concurrent readers, mutation between observation/check, rename/delete, correction/forget, cache eviction, process interruption, and refresh with owned locks/held paths. Retain original changes, staged feature index/HEAD and private audit behavior.
* Public operation tests cover direct discovery navigation/read and retrieval, assembly, and refresh prepare/apply with real discovery-qualified requests, before/after source edits and unsafe/stale/condition/hidden/conflict cases, on supported **macOS and Linux**, including existing CI Python 3.11 and 3.15 matrix (`.github/workflows/contracts.yml`); explicitly report runtime/platform gaps. Fix caller/test/docs contracts if a reviewed implementation changes them; no shims or graph prerequisite. Approved candidate must be reviewed independently and meet operator-agreed thresholds on both platforms plus fixed per-case quality and all controls; complete full relevant contract modules and appropriate release gate after implementation, then independent acceptance and published v0.0.15 delivery. This research plan itself makes no acceptance or release claim.
